# UI 架构重构技术设计

> **UI 层架构现状文档**。2026-09-12 起草为重构蓝图，P1-P4 已于 2026-09-13 全部收官（落地记录见 §6）；2026-09-14 精编为现状定案——重构前债务实证、对话记录等过程细节查 git 历史。
> 载体=**混合制**（4 屏 prefab 化 + Map 3D 弹层场景制、统一入栈）；术语保留 Screen；自研 UI Kit 对齐业界框架组件划分（TEngine UIModule / QFramework UIKit / GameFramework UIForm），不引入第三方全家桶（它们各自的 UI 模块长在自家资源/事件底座上，引入=换地基）。

## 1. 重构动因（历史，已解决）

> 2026-09-12 代码实证的四笔账，P1-P4 收官后均已消除或收编（现状见 §2-§4）：①Screen 全是 god-class（WishDrawController 1592 行/7 partial、SettingsScreen 811/8、BackpackScreen 755/6 等）；②纯命令式刷新无数据流约定（状态变更靠手动 RefreshXxx，漏调即静默不同步）；③弹窗双轨（PopupManager 与各屏手搓面板并存，z-order 靠场景加载顺序+Canvas sorting 分散维持）；④性能账（每次 GoBack 全走 UnloadUnusedAssets+GC.Collect、开关界面=完整 scene load/unload）。重构前完整盘点实证查 git 历史。

**底座保留项（重构前后不变）**：Wargame DI、EventBus（owner 登记）、InputLocks、AssetCache/Addressables、Unity Localization + TextCombiner、SaveManager、Mirror、AudioManager。

## 2. 架构总览

**业界框架 ↔ GIC 组件映射**：

| TEngine/UIKit/GameFramework 概念 | GIC 落地物 | 位置 |
|---|---|---|
| UIModule（UI 栈管理器） | **UIManager** | `GIC.UI`，Boot 常驻（挂 GameScene 子物体） |
| UIWindow/UIPanel/UIForm | **ScreenBase**（保留名，扩充生命周期） | `GIC.UI` |
| 分层 Layer（Hidden/Bg/Normal/Popup/Top…） | **UILayer**（Fullscreen/Popup/Toast/Top） | `GIC.UI` |
| Window 打开参数 payload | `UIManager.Open(ScreenId.X, args)` | — |
| 弹窗/Toast 栈 | UIManager 内置弹窗层（现 PopupManager 并入，留门面） | — |
| 资源加载 | 面板 prefab→Resources（与 Unit/Card.prefab 同路线）；3D 弹层→场景 | — |
| 事件/注入/输入锁 | EventBus / DI / InputLocks 原样 | — |

**分层结构**（P2 勘测勘定：全项目 UI 均为 ScreenSpaceOverlay——MainHall Canvas order=0、原 Settings order=100；故 UIRoot=**纯 GameObject 容器**，不设总 Canvas/UICamera）：

```
Boot（常驻）GameScene [DontDestroyOnLoad]
├─ UIRoot（编辑器手搭，docs/20 铁律）
│  ├─ Layer_Fullscreen / Layer_Popup / Layer_Toast / Layer_Top   ← 纯容器（无 Canvas）
└─ UIManager（组件：层级根引用 + 栈 + 生命周期调度）

面板 prefab 自带 Canvas（挂进容器后仍为 root canvas，Overlay 模式）；
sortingOrder 由 UIManager 按层级带强制：Fullscreen=100+栈深 / Popup=200+ / Toast=300+ / Top=400+
（层级权威落地——覆盖 prefab 内手调值，恒高于宿主根场景 Canvas 的 order=0）
粒子例外：需世界空间 ParticleSystem 的面板，其 Canvas 用 ScreenSpace-Camera + 面板自带 UICamera（P3 Wish 迁移时处理）

根场景体制不变：Splash / MainHall / Battle 仍是 Single 根场景（背景/战斗内容=场景级）
弹层两制同栈：纯 UI 弹层→PrefabHost（实例化 prefab 入层级根）；Map→SceneHost（Additive 场景，栈语义统一）
```

## 3. 核心抽象

### 3.1 ScreenId 注册表（对齐 SceneType 模式）

```csharp
public sealed class ScreenId
{
    public string Name { get; }
    public UILayer Layer { get; }          // Fullscreen / Popup / Toast / Top
    public ScreenHostKind Host { get; }    // Prefab | Scene | RootScene
    public string PrefabPath { get; }      // Prefab: "Prefabs/UIPanels/Xxx"（Resources 下）
    public SceneType Scene { get; }        // Scene/RootScene: 关联场景
}

public static class Screens   // 注册表（现状：4 屏已翻 PrefabHost，Map 场景制）
{
    // ── 根场景（context，不入栈） ──
    public static readonly ScreenId Splash   = ScreenId.Root("Splash",   SceneType.SplashScreen);
    public static readonly ScreenId MainHall = ScreenId.Root("MainHall", SceneType.MainHall);
    public static readonly ScreenId Battle   = ScreenId.Root("Battle",   SceneType.BattleScreen);

    // ── 弹层 ──
    public static readonly ScreenId Map      = ScreenId.Overlay("Map",      SceneType.MapScreen);          // 场景制（3D 内容，D1）
    public static readonly ScreenId Settings = ScreenId.Prefab("Settings", "Prefabs/UIPanels/SettingsScreen"); // P2 翻（2026-09-12）
    public static readonly ScreenId Backpack = ScreenId.Prefab("Backpack", "Prefabs/UIPanels/BackpackScreen"); // P3 翻（2026-09-13）
    public static readonly ScreenId Wish     = ScreenId.Prefab("Wish",     "Prefabs/UIPanels/WishScreen");     // P3 翻（2026-09-13）
    public static readonly ScreenId Coop     = ScreenId.Prefab("Coop",     "Prefabs/UIPanels/CoopScreen");     // P3 翻（2026-09-13）
}
```

调用面统一为 `UIManager.Open(Screens.Xxx, args)`；翻 Host 只改注册表一行+建 prefab+删场景，调用点零改动（本表实况以 `Assets/_Scripts/UI/ScreenId.cs` 为准）。

### 3.2 UILayer 分层与遮挡策略

| 层 | 语义 | 遮挡策略 |
|---|---|---|
| Fullscreen | 一级全屏界面（含 Map 场景制） | 新开时**下方 Fullscreen 收 OnPause**（仅钩子，不自动变暗/停用——重内容屏可在 OnPause 自行降载）；关闭后下方收 OnResume |
| Popup | 模态弹窗（确认框/输入框/管理面板） | 自带全屏阻断底图（prefab 内做），不触发下方 OnPause；栈式堆叠，ESC 先关最顶 |
| Toast | 轻提示（不阻断、自动消散、可堆叠） | 无阻断 |
| Top | 转场遮罩/强制提示（预留） | — |

### 3.3 生命周期（UIManager 调度，ScreenBase 虚方法）

| 阶段 | 虚方法 | 时机 | 配对/约定 |
|---|---|---|---|
| 初始化 | `OnInit()` | Prefab 实例化后一次性；场景制=Awake 后由 ScreenBase 自行调用等价逻辑 | 幂等守卫 |
| 打开 | `OnShow(object args)` | 每次入栈后 | 音乐 push（Safe 系列保留在此）；入场动画自管（Entering 锁不变） |
| 遮挡 | `OnPause()` | 被更高 Fullscreen 盖住 | 不动音乐；仅钩子 |
| 恢复 | `OnResume()` | 上方 Fullscreen 关闭 | 与 OnPause 配对 |
| 关闭 | `OnClose()` | UIManager 发起（ESC/关闭按钮/GoBack） | 防重入 isClosing + Closing 锁 + 退场动画 + 音乐 pop（ScreenBase 模板保留，仅收尾从 GameScene.GoBack 换成 UIManager） |

场景制 Screen（SceneHost）：OnPause/OnResume 同语义（场景保持加载，仅收钩子）；Show/Close 对应场景加载/卸载。

### 3.4 UIManager 职责与 API

| API | 语义 |
|---|---|
| `Open(ScreenId, args)` | 层级判定→Host 分发（Prefab 实例化/场景加载/根场景切换清栈）；UITransition 锁防抖；同屏重复 Open=幂等 no-op+Warn |
| `GoBack()` | **关闭栈顶 Fullscreen**（Popup/Toast 不入返回历史——弹窗不留面包屑） |
| `Close(unit)` / `CloseTop()` | 关指定/栈顶单元（供 ESC 收口与外部调用） |
| `ShowModal(message\|LocalizedString)` / `ShowToast(...)` | 弹窗层/Toast 层（吸收 PopupManager） |
| `Clear()` | 根场景切换（进 Battle/Splash）时清栈 |

ESC 链路**现状**：InputManager.CloseTopUI 不变——各 Screen 仍自注册 IClosable（栈序即遮挡序，Boot 注册的 UIManager 恒在栈底），从顶层向下关闭第一个注册的 IClosable。蓝图期设想的"P3 收口为 UIManager 单注册"未执行（面板化后自注册形态天然工作，无收口必要）。

### 3.5 三种 Host

| Host | Show | Close | 适配对象 |
|---|---|---|---|
| PrefabHost（**池化版**，2026-09-12 闪屏回归后升级，docs/14 §38） | 预热泵在 **Splash 就绪+30 帧**后逐屏实例化（2026-09-21 方案 B 重排，原为进大厅时机；每屏隔 30 帧摊成本；**渲染态预热**=alpha 0 激活两帧走完整渲染管线；根转场在途挂起、转场毕+60 帧再续——docs/17 §5b）；打开=池实例 SetActive(true)（首开 74ms/重开 11.6ms，池化前冷开 286ms 全屏闪烁） | 退场动画→SetActive(false) 入池（不 Destroy，实例复用） | Wish/Backpack/Settings/Coop（已全部 PrefabHost 化） |
| SceneHost | GameScene 场景原语（Load/Preload/Activate，SceneTransition 锁） | 退场动画→卸载场景+恢复激活上级 | MapScreen（3D 内容弹层） |
| RootHost | 清栈+Single 加载根场景 | 无（根场景间无 GoBack 语义，如 Battle→MainHall 直 Open） | Splash/MainHall/Battle |

GameScene 瘦身为**纯场景原语**（Load/Preload/Activate/Unload/SetActive/过渡锁），历史栈、GoBack、OnGoBackEvent 发送全部移交 UIManager（事件类本体在 Data/Event 不动，MainHall 的 GoBackHandler 监听不变）。

**性能决策**：场景制关闭保留 `UnloadUnusedAssets`（Map 瓦片内存重），**去掉每 GoBack 的 `GC.Collect`**（主线程卡顿尖峰，托管内存交运行时 GC）；面板制关闭=入池，零额外清理。

**池化生命周期推论（P3 迁移屏必守，docs/14 §38 规范）**：面板不销毁 → **Start 只跑一次**——每开一次的动作（音乐 push/入场动画/选中态/值刷新）必须落 OnShow，一次性 wiring（监听器/集合/本地化文案）落 OnInit；`isClosing` 由 ScreenBase.RaiseShow 统一复位（入池残留复位，否则重开面板永远关不掉）；可关闭注册改为每开一次自动注册+OnDisable 注销。

### 3.6 注册制与栈语义（实施勘定）

**模型勘定：root 场景 = context，不是栈单元**。栈只收**弹层**（Fullscreen overlay）；根场景切换（Splash→MainHall、Coop→Battle、Battle→MainHall）**保留 `SceneType.Load()` 直载**（6 个调用点零改动），栈内残留弹层随 Single 加载触发 `ScreenBase.OnDisable/OnDestroy` 自清。MainHall/Battle/Splash 在注册表中标记 RootScene，`ScreenBase.OnEnable` 注册时自动跳过。

**注册制**：场景制 Screen 由 ScreenBase 的 `OnEnable/OnDisable` 钩子自动入栈/出栈（无需各屏手写）；场景名未注册时**匿名入栈 + Warn**（保零回归，P4 清查）。P3 面板化后注册点不变（prefab 实例化同样触发 OnEnable）。

**返回语义两分（防递归，实测 CoopScreen.Close→OnLeaveRoomClick→GoBack 链）**：
- `UIManager.GoBack()` —— 返回**意图**（未来 pet 聊天/UX 返回键入口）：调栈顶的 `Close()`，各屏可按领域语义响应（Coop 房主状态 = 离房回发现页，不弹层）
- `UIManager.PopToPrevious(unit)` —— **弹出原语**（原 GameScene.GoBack 职责）：移栈项+卸载场景+恢复上级激活+资源清理+发 OnGoBackEvent。CloseScreen 模板收尾、PetGameBridge 兜底两处直连本原语，不再经 Close 二跳（Coop 关闭 2026-09-13 起改走 CloseScreen 模板带退场动画，不再直连；"Coop 房客离房"为屏内状态切换不弹层，本就不经本原语）

- `PopupManager` 维持专科管理器形态，**折叠进 UIManager 已被 P4 拍板"故意不做"**（toast/modal 专科管理与导航栈职责分离清晰、久经考验，折叠纯化妆性收益+回归风险不成比——见 §6 P4 与 §7 决策语境）。
- `GameScene.Instance.GoBack()` 3 个调用点（ScreenBase 模板 / CoopScreen.RoomFlow / PetGameBridge）改连 `UIManager.PopToPrevious`。
- ScreenBase 的 `RegisterClosableSelf/PushMusicSafe` 等对子类 API 不变（迁移期零回归）。
- UIRoot 层级容器（编辑器手搭，docs/20 铁律）已随 P2 在 Boot 场景落地（四层级纯容器）。

## 4. 导航语义汇总

| 操作 | 语义 |
|---|---|
| Open | 见 §3.4；Fullscreen 新开→下方 OnPause；根场景 Open→Clear+Single Load |

## 5. 界面拆分路线（已废弃，D13 推翻）

> 原蓝图规划将五屏 god-class 拆成 View+Controller 体系（BackpackScreen→View+三 Controller、SettingsScreen→View+6 TabController、WishDrawController→六职责类等，映射明细查 git 历史）；**2026-09-13 D13 拍板推翻**：界面模式维持现状（Screen+按职责 partial+自然控制器，如 WishFlowController/DeckSwitchPanel），MVP 仅按屏演进——partial 分文件已达成职责组织目标，拆 Presenter 类的可单测收益当前无消费方、回归风险全担。演进触发器见 §7 D13。
> 保留的有效纪律：状态变更只经 Controller 公共方法→内部调 View.RefreshX，EventBus 事件→Controller 订阅→走同一条刷新路径；不引入数据绑定框架（漏刷防治完整决策见 §7 D14）。

| D10 | 返回意图与弹出原语分离 | GoBack() 走 Close() 会被 CoopScreen.Close→OnLeaveRoomClick→GoBack 递归；模板/离房/兜底三处直连 PopToPrevious 原语 |
| D11 | 注册制+未注册匿名入栈 | ScreenBase OnEnable/OnDisable 自动入出栈；未注册场景匿名入栈+Warn 保零回归（P4 清查） |

| D13 | **界面模式维持现状**（Screen+按职责 partial+自然控制器如 WishFlowController/DeckSwitchPanel），MVP 仅按屏演进 | 2026-09-13 拍板会（MVP/架构选型讨论）：商业游戏业界主流=UIManager+Panel+每屏 MonoBehaviour，TEngine/UIKit 均无 MVVM；partial 分文件已达成职责组织目标，拆 Presenter 类的收益（可单测）当前无消费方、回归风险全担；**演进触发器=某屏逻辑复杂到需要断言测试**（候选：B6 战斗 HUD 的回合/资源/技能三区联动），按屏做，不全局换制 |
| D14 | **MVVM/绑定框架永不引入**；数据驱动界面的漏刷防治走"数据版本号事件"中间态 | 游戏 UI 双谱系：祈愿=演出驱动（时序编排绑不上）、背包=数据驱动（真痛点=漏刷）；MVVM 与项目"UI 属性编辑器直调"工作流直接冲突（绑定=布局状态由 ViewModel 决定）；漏刷解法谱系 ①手动 Refresh→②事件通知→③绑定，现状=②健康态（SaveManager.Modify 单点收敛+开屏重读+EventBus）；**数据版本号事件**（卡牌域数据变更发版本事件，相关界面统一订阅重刷，漏刷面从 M×N 收敛到 M）在 B7 联机数据推送落地前实施——届时数据源爆炸才是绑定真正值钱的时刻，而版本事件能以 ①的成本拿走③的主要收益 |
