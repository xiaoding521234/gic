# GG 系统

> 2026-09-13 立项（用户需求原话："类似于QQ，是本游戏专用的，与游戏内版派蒙类似，只内置于游戏内"）。
> **本期只做设计，实现放后面**（用户拍板"GG放后面再做"）——本文档是唯一交付物，代码零改动。
> 依托：UIManager 面板化（docs/23）、指令系统（docs/25）、AI 派蒙会话层（docs/19 §6.5）、Mirror 联机与 NetworkEventBus（既有联机设施——输入/手势两文档不覆盖网络层，网络架构见 docs/17 §2）。

## 1. 定位

- **GG = 本游戏专用的内置 IM**（类 QQ），命名对齐 QQ 的"短叠字"风格。
- **只内置于游戏内**：不是桌宠/独立应用——桌宠进程不含 GG；打开后**从屏幕左边滑入**（QQ 侧栏式）。
- 承担三件事：**社交（房间/小队聊天）**、**AI 对话（派蒙大任务）**、**系统消息（邮箱）**，外加**控制台**（开发者向指令入口，指令系统前置条件已就绪）。

## 2. 信息架构（模块清单）

| 模块 | 定位 | 依托/要点 |
|------|------|-----------|
| 房间聊天 | 当前联机房间全员的公共频道 | Mirror 聊天消息同步（NetworkEventBus 广播——既有联机设施，见 docs/17 §2）；内容=文字+内置表情 |
| 小队聊天 | 当前小队（对局分组）频道 | 同上，按队伍 id 过滤分发 |
| 派蒙聊天 | 与 AI 派蒙的完整对话界面 | **与桌宠共享上下文**（§3）；GG 内更适合大任务 |
| 邮箱 | 系统邮件：版本公告/补偿/抽卡结果汇总等 | 本地数据即可起步，联机后可做离线消息；复用本地化文案表 |
| 控制台 | 指令系统（docs/25）的正式界面 | 输入框即指令行（同聊天框 "/" 模式语义：补全/Tab/回执直出）；help 即目录 |

模块间切换=GG 顶部的会话列表（QQ 导航栏式，聊天会话+邮箱+控制台平铺）。

## 3. 派蒙聊天（与桌宠共享上下文）

- **同一会话层**：GG 的派蒙会话与桌宠/游戏内派蒙聊天共用 `PaimonChatSession`（人设/长期记忆/工具表/run_command 全同）——"既可以直接与派蒙宠物对话，也可以在 GG 里对话，二者共享上下文"。
- **会话实例策略**：同一时刻只允许一个活跃请求（session.IsBusy 互斥）；GG 打开期间桌宠聊天的滑窗/记忆引用同一份（进程内单例语义，与反应通道共用同一 session 实例的口径一致）。
- **GG 的差异化价值=历史可翻阅**（"能往上翻聊天历史，像 QQ 一样"→ 适合大任务）。与现行对话 UI 的关键差异：
  - 现行桌宠/游戏内聊天=**纯内存滑窗 12 轮**（docs/19 §6.5），气泡只保留最近内容；
  - GG 需要**会话历史落盘**（会话文件按会话 id 存 `{persistentDataPath}/gg/`），打开时可回放滚动；发送给 LLM 的滑窗语义不变（仍是最近 N 轮），**落盘只是展示层的历史账本**——不改变 token 预算模型。
- 大任务形态：GG 里派蒙的消息可以更长/更结构化（GG 气泡宽度预算大于桌宠小窗）；派蒙口吻、工具调用、知识库检索全部照旧。

## 4. 消息类型

- **纯文字 + 内置表情**。表情=项目内置表情包（静态图 + **gif 动图**），发送方从表情面板选择——**不允许自定义发送文件**（个人 Demo + 安全体面：无文件上传面，天然免传输安全审计）。
- **表情资产=待备项**（项目当前无聊天表情库——Assets 全库扫描无 emote 资产）。候选来源二选一（实现前找用户拍板）：
  1. gi-extract 从本地原神提取官方聊天表情（gic-gi-extract skill 流水线，与图标素材同管线）；
  2. AI 生成一套（原神风格、统一规格，UI 图标风格铁律=单一简单物体+单色细线不适用于表情——表情是内容素材不是 UI 图标）。
- 表情消息=表情 id 引用（非文件路径）；渲染=Sprite/gif 播放组件，不入 TextCombiner。

## 5. UI 接入

- **形态**：全屏高度、从**屏幕左边滑入**的侧栏面板（QQ 窄栏≈420-520px 设计宽），半开时右缘拖拽可调宽度（二期）。
- **接入纪律**：走 UIManager 统一栈（Screens 注册 + 池化面板 + IClosable，docs/23 P4 面板制纪律；新增 Screen 全流程=gic-new-screen skill）；与桌宠/游戏内派蒙聊天的关系=**并存**（GG 是会话账本+大任务界面，桌宠是陪伴体，互不替代）。
- 入口：主界面左侧边缘的常驻把手（hover 拖出）；联机房间内自动提示新消息（红点）。

## 6. 联机语义（房间/小队聊天）

- 依托 Mirror：聊天消息=NetworkEventBus 广播事件（含 sender 昵称/uid/频道 id/内容/表情 id 列表）；客户端本地渲染。
- 频道生命周期：房间聊天=进入房间产生会话、离开归档；小队聊天=对局开始按队伍 id 产生；离线不可达（无服务器中转，LAN Demo 边界——邮箱同理起步只做本地）。
- **实现前置**：联机对局（B/C 批次战斗联机）落地后才有真实房间/小队语境；GG 实现排序放其后。

## 7. 控制台（指令系统的 GG 集成）

- 输入框=指令行：语法/补全/回执与设置页指令行、聊天框 "/" 模式完全同源（docs/25 §8——`session.RunCommandDirect` 同一执行路由，联机指令只走本地）。
- 回执以系统消息样式混排在控制台频道内（滚动可回看，开发者格式原文——文案基调铁律）。
