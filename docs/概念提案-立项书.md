## 一句话描述

> 带着从祈愿中解锁的角色卡牌进入战场，在同时回合制的博弈中用攻速、势力机制和科技树构筑击败对手，摧毁协议核心掠夺资源，循环成长。

## 目标受众

- **原神玩家**：IP 吸引，降低门槛
- **战棋/策略玩家**：策略深度留存

## 核心卖点

1. **同时回合博弈** — 双方同时选行动、按攻速排序执行，无等待、有心理博弈
2. **势力混搭构筑** — 自由组合不同国家势力的独特机制，每局体验不同
3. **局内科技树成长** — 建筑即科技节点，局内牌库不断扩张，RTS 式铺基地体验

### 架构预留（Demo 不实现，但接口+TODO 先留好）

以下功能在 Demo 阶段不实现逻辑，但**架构必须从第一天就预留**，避免后续大量重构：

| 功能 | 预留方式 | 后续接入时只需 |
|------|----------|---------------|
| 6人模式 | TurnSystem 支持 `List<Player>` 而非写死2人；PlayerManager 无硬编码上限 | 扩展 UI + 淘汰逻辑 |
| 稻妻/纳塔/须弥/枫丹/至冬/坎瑞亚 | FactionMechanism 基类+注册表（似 SkillFactory 反射注册），Demo 只注册蒙德/璃月/挪德 | 新增子类+注册 |
| 衍生玩法（炼金/水车/矩力/机械科技） | Building 子类体系预留 `ISubsystem` 接口，Demo 的 Building 不实现 | 新增子类 |
| 战场动态摧毁 | Tile 持有 `Destroy()` 接口 + `OnTileDestroyed` 事件，Demo 不调用 | 接入技能触发 |
| 多级科技树 | Building 已有 `UnlockCard()` 接口，科技树用 `TechTreeNode` 链表结构，Demo 只填2级 | 扩展数据 |
| 全角色技能 | SkillFactory 反射注册已就绪，Demo 只写2个 `[SkillAttribute]` 子类 | 新增子类 |
| 全命座效果 | Constellation 用 `IConstellationEffect` 接口+列表，Demo 只填固定效果 | 新增效果类 |
| 全状态同步 | EventBus 已有本地/网络双通道，Demo 只同步行动选择事件 | 新增事件类型 |

> **原则**：不实现的功能不等于不设计。每个"暂不做"的模块在代码中必须有：接口定义、注册位、TODO 注述标记缺失逻辑。后续填充时只加代码不改架构。

## Demo 核心循环

```
局前选8种卡 → 进入1v1对局（Mirror连接） →
  同时选1行动 → 攻速排序执行 →
  出战角色(摩拉) / 出战建筑(摩拉) / 战技(体力) / 使用物品 /
  建筑购买卡牌扩张牌库 / 蒙德延奏 / 璃月契约 / 挪德升命二选一 /
  开启敌方核心宝箱 / 摧毁虚空扩展地形 →
  造成伤害爆原石 / 摧毁核心掠夺手牌 →
  一方协议核心被摧毁 → 结算
```

## Demo 验证目标

| 问题 | 验证方式 | 成功标准 |
|------|----------|---------|
| 同时回合制好玩吗？ | 1v1 联机对局 | 至少3局不想中途退出 |
| 势力混搭有策略深度吗？ | 蒙德+璃月 vs 纯蒙德/纯璃月 vs 含挪德双祝福 | 混搭阵容胜率不低于40% |
| 建筑科技树有成长感吗？ | 2级科技树对局 | 玩家主动使用建筑购买卡牌 |
| 已有系统接入战斗了吗？ | 卡牌/物品/属性/地形/Mirror全参与 | 1局无bug完整对局 |
| 核心宝箱+动态战场有意义吗？ | 宝箱开启+地形扩展参与对局 | 玩家主动争夺宝箱、利用地形变化 |
| 架构预留是否到位？ | 检查所有"不做"模块有无接口+TODO | 后续加功能不改架构 |

## 成功标准

- 能完成一局无 bug 的 1v1 Mirror 联机对局
- 规则无歧义，不需要"主持人裁决"
- 已有系统（卡牌/物品/属性/地形/Mirror）全部参与战斗流程
- 所有"不做"模块在代码中有接口定义+TODO，后续填充不改架构
- 体验上证明核心玩法有趣，值得继续投入

### 不做（逻辑不做，架构预留）

- 6人混战 / 分组模式 → 架构预留：TurnSystem 支持 N 人
- 稻妻/纳塔/须弥/枫丹/至冬/坎瑞亚势力 → 架构预留：FactionMechanism 注册表
- 衍生玩法（炼金/水车/矩力/机械科技） → 架构预留：ISubsystem 接口
