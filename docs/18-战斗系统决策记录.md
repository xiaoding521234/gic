## 一、联机权威模型（决策 3）

### 选项对比

| 维度 | A. Host 权威（结果同步） | B. 双端确定性（输入同步） |
|------|------------------------|-------------------------|
| 同步内容 | 客户端只上交**行动选择**；Host 收齐→排序→执行→广播**结果命令流** | 只同步行动选择，各端并行跑同一套逻辑 |
| 带宽 | 中（每回合一次结果流） | 极小（每回合一次选择） |
| 确定性要求 | **无**——浮点、协程动画、遍历顺序随便写 | 苛刻——C# 浮点跨平台不一致、容器遍历序、动画时序都要锁死 |
| 与现有架构契合 | ✅ 完全复用 Mirror + NetworkEventBus + OnlyHost + Immediate 模式（联机大厅已验证） | ❌ ActionQueue 协程串行 + 表现层动画耦合深，改造成本高 |
| 防作弊 | 天然免疫（客户端无逻辑权限） | 客户端可自改逻辑 |
| 单机模式 | Host=本地，零额外代码 | 同一套逻辑直接跑 |
| 断线重连 | 需补：结果流快照/追放（切片可先不做） | 天然支持（重放输入即可） |

### 推荐：A（Host 权威）

**核心理由**：
1. 已定架构是「ActionQueue 协程串行 + DamagePipeline 同步 + 战斗逻辑不走 EventBus」——协程动画天然不确定，B 方案等于推翻这个架构重写确定性逻辑层，成本不可比
2. 联机大厅层已验证的事件通道（请求类 OnlyHost + Immediate=true）可直接复用于行动选择上交
3. 个人 Demo 无电竞级公平性需求，带宽不敏感

**要点展开（拍板后进技术设计）**：
- 行动选择上交：新增 `SubmitActionRequestEvent`（OnlyHost + Immediate），携带 playerID + 行动数据
- Host 收齐全部玩家选择 → 攻速排序（含先决先执行 tiebreaker，docs/04 §4.1）→ 逐个经 ActionQueue 执行
- 每个行动执行产出**结果命令**（ResultCommand：位移/伤害/死亡/特效触发/属性变化），Host 广播，客户端 BattleView 按命令流播放动画——**逻辑与表现彻底分离**，与祈愿系统 PlanShot→PlaySteps 同构
- 战斗事件不走 EventBusHub（铁律），走专用 BattleCommandChannel（NetworkEventBus 上的独立MessageType 或 Mirror SyncList/自定义序列化，技术设计时定）
- AI 行动阶段（1-2星角色）：Host 生成选择，同一队列执行

### 已拍板（2026-08-16）

- [x] **采用 Host 权威 + 结果命令流（TurnScript）**。命令流复用祈愿 PlanShot→PlaySteps 模式：Host 逻辑执行产出有序步骤列表，客户端与 Host View 均为纯播放器；步骤粒度=一次原子视觉事件（位移/命中/扣血/死亡/上Buff/特效）
- [x] **回合推进屏障同步**：Turn N 动画播完（或超时快进）才开 Turn N+1 选择阶段，慢机不卡死全场
- [x] **迷雾后置但协议预留可见性作用域字段**：命令流设计含 recipient 可见性过滤位（切片期恒全可见），防将来加迷雾时重设计通道
- [x] **断线重连切片不做**，仅协议占位
- [x] **先决先执行 tiebreaker = Host 收到提交的顺序**（客户端时间戳不可信）

## 二、单位视觉表现（决策 4）

### 选项对比

| 维度 | A. 3D 模型单位 | B. 2D 立牌棋子（全 2D 战场） | C. 3D 战场 + 2D 贴片单位 |
|------|---------------|------------------------------|--------------------------|
| 工作量 | **巨大**：每角色 rigged 模型+动画状态机+技能特效，6 角色≈6 套 | **小**：头像/立绘资源已在（Avatars/Cards 图集） | 中：地形 3D 化+光照，单位仍 2D |
| 与现有资源契合 | ❌ 项目 0 个角色 3D 模型管线 | ✅ SpriteAtlas 6 个、卡牌视图策略、立绘体系全复用 | 部分 |
| 战棋信息传达 | 好 | **足够**（格子+立牌+状态图标是战棋成熟范式，Into the Breach 级别验证过） | 好 |
| 相机/渲染 | 复杂（动画 LOD、遮挡） | 正交相机+SpriteRenderer，MainHall 已有同款管线 | URP 已有，需处理 billboard 朝向 |
| 战斗打击感上限 | 高 | 中（靠震屏/闪白/粒子补） | 中高 |
| 后续扩展 3D | 原生 | 需重做（但 Demo 定位下大概率不会） | 半原生 |

### 推荐：B（全 2D 立牌棋子）

**核心理由**：
1. 概念提案定位是**概念验证 Demo**——视觉管线选工作量最小、复用最大的一条
2. 现有美术资产全是 2D（头像图集、卡面、立绘、元素图标）；MainHall 的 SpriteRenderer 背景管线可直接复制到战场
3. 战棋核心体验在「同时博弈+攻速排序+势力构筑」，不在单位建模精度；打击感用震屏/受击闪白/粒子/音效补齐（ScreenEdgeGlow、CardGlow 等 shader 已有积累）
4. 单位棋子 = 头像（Avatars）+ 阵营色底座 + 稀有度边框 + 状态图标区，与卡牌 UI 语言统一，学习成本零

**要点展开（拍板后进技术设计）**：
- 相机：正交，固定俯视微俯角（类似 30-45° 视觉），支持缩放（MapZoomAndDrag 可参考）
- 战场：SpriteRenderer 平铺 Tile 网格 + 网格线/高亮（Shader 或九宫格 Sprite）
- 单位：立牌（Sprite + 底座），选中/悬停高亮复用 CardGlow 体系
- 朝向：单位立牌不做 3D 朝向，用左右翻转表达阵营朝向
- 表现层动画：位移（推力移动的匀速/击退抛物线）、受击闪白、死亡变灰（尸体）——全部 Tween，不引入动画状态机

### 待拍板

- [x] 全 2D 立牌方案确认
- [x] **棋子底图切片期用现有头像**（Avatars 图集，零成本）；Q 版立牌视觉升级后置
- [x] **斜俯视棋盘**：相机约 50-60° 俯角正交，棋盘平铺 3D 平面（SpriteRenderer 地块），立牌竖立面向相机，桌游纵深感；支持缩放；单位朝向用左右翻转表达阵营

## 三、垂直切片范围（决策 5）

### 推荐范围

| 模块 | 切片范围 | 不进切片（后置） |
|------|----------|------------------|
| 对局人数 | **1v1**（双开控制调试模式 + LAN 联机；架构按 6 人预留 playerID） | 3-6 人、分组淘汰、Hotseat 隐私幕帘（可选后置） |
| 角色 | **6 个已有文档角色**：安柏/凯亚/丽莎/琴/芭芭拉/诺艾尔（全蒙德，正好验证延奏） | 其余国家角色 |
| AI 单位 | **2 个 1-2 星**（如丘丘人×2 变体）验证 AI 行动阶段+尸体系统 | 完整 AI 行为树 |
| 势力机制 | **蒙德延奏 only** | 璃月契约、挪德双祝福等 |
| 战场 | **20×20**，地形 3 种（平原/水/障碍）验证通行性标签 | 50×50、全 7 地形、动态战场（虚空切换）、宝箱 |
| 迷雾 | **后置**到核心循环跑通之后（visionRange 字段已在，渲染层最后补） | — |
| 命座 | 最小验证：**1 个角色 2 个命座效果**（建议安柏，文档最全） | 全势力命座 |
| 建筑 | **1 个产摩拉建筑**（验证出战建筑+摩拉产出闭环；科技树面板不做，购买入口用简化按钮） | 科技树、多建筑 |
| 物品 | 食物×2（使用）+ 武器×1（装备槽）验证 IUsable 流程 | 圣遗物等其余子类型 |
| 经济 | 局内摩拉（初始200+每回合5）+ 体力（初始60+每回合5，与摩拉统一发放时机）+ 核心掠夺手牌 | 原石结算、局外循环 |
| 胜负 | 摧毁协议核心 → 掠夺 → 结算画面 | 消散演出、观战 |
| 控制 | 硬控晕眩×1（丽莎？）验证韧性公式；**冻结反应作为第二控制验证** | 心控/压制、全部软控 |
| UI | 战斗 HUD：手牌区/体力/摩拉/回合数/行动选择面板/攻速队列显示 | 战报、回放 |

### 拍板后的落地顺序（与既有 B 批次合并）

```
B1 ActionQueue + DamagePipeline（Host 权威，见决策一）
B2 Buff 最小可用（含尸体状态、燃烧 DoT 一例）
B3 管理器职责边界（含 Framework/Battle 4 文件与 WishManager 层级归位——上一批遗留）
B4 示例技能：安柏战技/爆发 + 凯亚；元素反应做融化+冻结两例（伤害乘区 + 控制链路）
B5 战场与单位表现层（决策二）：斜俯视 Tile 网格 + 立牌 + 位移动画
B6 回合流程串联：选择阶段（含 20 秒时限/先决先执行）→ AI 阶段 → 结束阶段
B7 联机闭环：双开控制调试模式（单人公开操控双方，不经网络层）→ LAN（行动上交 + TurnScript 广播）
B8 切片收口：建筑/物品/命座最小集 + 迷雾 + 结算
```

### 已拍板（2026-08-16）

- [x] 1v1 + 6 角色全蒙德（安柏/凯亚/丽莎/琴/芭芭拉/诺艾尔，正好验证延奏）
- [x] 迷雾后置到 B8 尾部（TurnScript 协议预留可见性作用域字段，见决策一）
- [x] **B7 顺序改为「双开控制调试模式 → LAN」**，Hotseat（隐私幕帘 UI）降为可选后置
- [x] 建筑砍到 1 个产摩拉建筑、科技面板不做（购买入口用简化按钮）
- [x] **元素反应做融化 + 冻结两例**：融化验证伤害乘区，冻结验证控制链路（联动韧性/尸体系统）
