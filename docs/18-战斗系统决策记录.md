## 一、联机权威模型（决策 3）

### 选项对比

| 维度 | A. Host 权威（结果同步） | B. 双端确定性（输入同步） |
|------|------------------------|-------------------------|
| 同步内容 | 客户端只上交**行动选择**；Host 收齐→排序→执行→广播**结果命令流** | 只同步行动选择，各端并行跑同一套逻辑 |
| 带宽 | 中（每回合一次结果流） | 极小（每回合一次选择） |
| 确定性要求 | **无**——浮点、协程动画、遍历顺序随便写 | 苛刻——C# 浮点跨平台不一致、容器遍历序、动画时序都要锁死 |
| 与现有架构契合 | ✅ 完全复用 Mirror + NetworkEventBus + OnlyHost + Immediate 模式（联机大厅已验证） | ❌ ActionQueue 协程串行 + 表现层动画耦合深，改造成本高 |
| 防作弊 | 天然免疫（客户端无逻辑权限） | 客户端可自改逻辑 |
| 单机模式 | Host=本地，零额外代码 | 同一套逻辑直接跑 |
| 断线重连 | 需补：结果流快照/追放（切片可先不做） | 天然支持（重放输入即可） |

### 推荐：A（Host 权威）

**核心理由**：
1. 已定架构是「ActionQueue 协程串行 + DamagePipeline 同步 + 战斗逻辑不走 EventBus」——协程动画天然不确定，B 方案等于推翻这个架构重写确定性逻辑层，成本不可比
2. 联机大厅层已验证的事件通道（请求类 OnlyHost + Immediate=true）可直接复用于行动选择上交
3. 个人 Demo 无电竞级公平性需求，带宽不敏感

**要点展开（拍板后进技术设计）**：
- 行动选择上交：新增 `SubmitActionRequestEvent`（OnlyHost + Immediate），携带 playerID + 行动数据
- Host 生成低级单位选择（低级单位决策阶段）→ 收齐全部玩家选择（选择阶段，含 AI 玩家操控其高级单位）→ 全部行动统一按攻速排序+延迟执行（执行阶段）。排序与延迟规则见 docs/04 §4.1（2026-09-16 修订：原五阶段中的玩家/AI 两个执行阶段合并、"AI 单位"更名"低级单位"，见决策五）
- 每个行动执行产出**结果命令**（ResultCommand：位移/伤害/死亡/特效触发/属性变化），Host 广播，客户端 BattleView 按命令流播放动画——**逻辑与表现彻底分离**，与祈愿系统 PlanShot→PlaySteps 同构
- 战斗事件不走 EventBusHub（铁律），走专用 BattleCommandChannel（NetworkEventBus 上的独立MessageType 或 Mirror SyncList/自定义序列化，技术设计时定）
- 低级单位（1-2星角色/造物）：低级单位决策阶段决策（Host 生成选择，先于玩家选择），统一执行阶段与其他单位一并按攻速结算

### 已拍板（2026-08-16）

- [x] **采用 Host 权威 + 结果命令流**。命令流复用祈愿 PlanShot→PlaySteps 模式：Host 逻辑执行产出有序步骤列表；步骤粒度=一次原子视觉事件（位移/命中/扣血/死亡/上Buff/特效）。**2026-09-12 修订**：粒度从回合级一整块降为**片级命令块流**（分步流式演算），客户端与 Host View 从"纯播放器"改为"播放器 + 执行期交互端"——详见决策四
- [x] **回合推进屏障同步**：Turn N 动画播完（或超时快进）才开 Turn N+1 选择阶段，慢机不卡死全场
- [x] **迷雾后置但协议预留可见性作用域字段**：命令流设计含 recipient 可见性过滤位（切片期恒全可见），防将来加迷雾时重设计通道
- [x] **断线重连切片不做**，仅协议占位
- [x] **先决先执行 tiebreaker 废除**（2026-09-08 回合流程重排，取代 2026-08-16 的"先决先执行 tiebreaker = Host 收到提交的顺序"）：攻速相同 = **同时开始执行**，不再按提交顺序排序；同时开始执行的多个行动，其内部结算序在技术设计时确定（表现上无先后）
- [x] **回合流程重排 + 攻速延迟执行模型**（2026-09-08 拍板，规则本体 docs/04 §4.1）：AI 行动阶段（AI 决策）→ 玩家行动阶段（玩家选择）→ 玩家执行阶段 → AI 执行阶段 → 回合结束。执行阶段按攻速从高到低排序，**每相差 10 点攻速延后 1 秒开始执行**（延迟秒数 = 攻速差 ÷ 10）；行动及其衍生事件提早完成时，后续行动跳过剩余等待立即执行（避免空等待）**【追记 2026-09-30 落地：报障「凯亚（40 攻速）行动完后芭芭拉（10 攻速）空等 3 秒」——片头延迟此前客户端无条件死等，现攻速片片头等待（BattlePlayer.WaitSliceDelaySkippingDeadAir）逐帧探测在途有意义行动计数（_meaningfulActionInFlight：投射物飞行/箭雨单箭下落〔含散布延迟，fire-and-forget=唯一跨片在途源〕/移动行走），==0 立即进片、>0 等到在途结算即止（剩余空等不再补满——空等只承担攻速节奏提示）；已结算装饰尾巴（伤害数字飘字/插箭滞留淡出/闪色恢复）不计数不阻跳过；部署/回合结束/即时块固定短拍不参与跳过】**
- [x] **执行阶段合并 + 低级单位命名**（2026-09-16 拍板，取代上述五阶段结构、攻速延迟规则本身不变）：玩家执行阶段与 AI 执行阶段合并为**统一执行阶段**——全部单位（高级+低级）的行动统一按攻速排序，攻速时间窗跨单位归属一致生效；"AI 单位（1-2星）"概念更名为**低级单位**：无论属于真人玩家还是 AI 玩家都自主行动（如 MOBA 小兵），3~5 星为高级单位由所属玩家操控。详见决策五

## 二、单位视觉表现（决策 4）

### 选项对比

| 维度 | A. 3D 模型单位 | B. 2D 立牌棋子（全 2D 战场） | C. 3D 战场 + 2D 贴片单位 |
|------|---------------|------------------------------|--------------------------|
| 工作量 | **巨大**：每角色 rigged 模型+动画状态机+技能特效，6 角色≈6 套 | **小**：头像/立绘资源已在（Avatars/Cards 图集） | 中：地形 3D 化+光照，单位仍 2D |
| 与现有资源契合 | ❌ 项目 0 个角色 3D 模型管线 | ✅ SpriteAtlas 6 个、卡牌视图策略、立绘体系全复用 | 部分 |
| 战棋信息传达 | 好 | **足够**（格子+立牌+状态图标是战棋成熟范式，Into the Breach 级别验证过） | 好 |
| 相机/渲染 | 复杂（动画 LOD、遮挡） | 正交相机+SpriteRenderer，MainHall 已有同款管线 | URP 已有，需处理 billboard 朝向 |
| 战斗打击感上限 | 高 | 中（靠震屏/闪白/粒子补） | 中高 |
| 后续扩展 3D | 原生 | 需重做（但 Demo 定位下大概率不会） | 半原生 |

### 推荐：B（全 2D 立牌棋子）

**核心理由**：
1. 概念提案定位是**概念验证 Demo**——视觉管线选工作量最小、复用最大的一条
2. 现有美术资产全是 2D（头像图集、卡面、立绘、元素图标）；MainHall 的 SpriteRenderer 背景管线可直接复制到战场
3. 战棋核心体验在「同时博弈+攻速排序+势力构筑」，不在单位建模精度；打击感用震屏/受击闪白/粒子/音效补齐（ScreenEdgeGlow、CardGlow 等 shader 已有积累）
4. 单位棋子 = 头像（Avatars）+ 阵营色底座 + 稀有度边框 + 状态图标区，与卡牌 UI 语言统一，学习成本零

**要点展开（拍板后进技术设计）**：
- 相机：正交，固定俯视微俯角（类似 30-45° 视觉），支持缩放（MapZoomAndDrag 可参考）
- 战场：SpriteRenderer 平铺 Tile 网格 + 网格线/高亮（Shader 或九宫格 Sprite）
- 单位：立牌（Sprite + 底座），选中/悬停高亮复用 CardGlow 体系
- 朝向：单位立牌不做 3D 朝向，用左右翻转表达阵营朝向
- 表现层动画：位移（推力移动的匀速/击退抛物线）、受击闪白、死亡变灰（尸体）——全部 Tween，不引入动画状态机

## 四、执行阶段模型与片内结算（2026-09-12 拍板）

> 起因：稻妻连携"2 秒内随时点击"、璃月"谈判时停 3 秒投票"证明执行阶段是**即时演算+实时交互**的——玩家在执行阶段实时在线，旧"整回合预计算+播放"模型作废。参考王者荣耀/原神的服务器权威结构，tick 粒度换成战棋的"攻速片"。

- [x] **执行阶段 = 分步流式演算**：Host 结算一片 → 立即广播该片命令块 → 等全体播放确认或超时快进 → 结算下一片；命令流从回合级一整块改为**片级命令块流**
- [x] **Host 永不跑在客户端前面**（片级 ack 门控）：即时输入永远作用于当前演算点之后，无回滚问题
- [x] **即时行动协议**：连携等执行期交互随时上交（SubmitInstantAction），Host 在片边界 poll 输入队列、立即插入结算；蒙德切片只预留协议位不实现
- [x] **两类交互点**：软窗（连携 2 秒——演算照走不暂停，阶段切换前扫 WaitConditions 等窗结束）、硬停（契约谈判——Pause→收投票→Resume）；"提前完成不空等"的压缩仅限纯演算片间等待，**交互窗时间不可压缩**
- [x] **同攻速片内 = 快照结算（真同时）**：片内全部行动读取片前快照、独立结算、效应统一应用——同片互杀 = 同归于尽；"死亡中断"仅跨片发生（"开始执行前被击杀才落空"）；结算顺序退化为命令枚举序（unitID 升序）不影响结果——取代 2026-08-16"内部结算序待定"
- [x] **移动 = 同片内同步逐步结算**（与快照结算并存：瞬发效应读片初状态，移动动态展开）：每步只判定将要进入的下一格、当前所在格不判定（同格共存单位不阻挡彼此离开）；完全进入下一格前位置判定仍在上一步的格；对穿互换 = 互相穿过（规则本体 docs/05 §5.3）；瞬发×移动交互暂定按片初位置结算（docs/11 跟踪）→ **该悬案已销（2026-09-17）**：投射物类命中 = 接触立牌圆柱之时、读**命中时刻的连续插值位置**（含移动中途，见决策二"格=交互粒度，非判定粒度"条）；零表现时间的纯瞬发效应仍按片初快照结算（同片并发基石不变）

## 五、回合结构与规则修订（2026-09-16 拍板）

> 起因：2026-09-16 战斗系统设计文档全量交叉分析（04/05/06/07/11/18/22 + units）发现三项跨文档矛盾与规则缺位，当日拍板修订。

- [x] **执行阶段合并**：玩家执行阶段与 AI 执行阶段合并为**统一执行阶段**——全部单位（玩家操控的高级单位 + 自主行动的低级单位）的行动统一按攻速排序。修复"攻速时间窗在玩家/AI 边界失效"（原五阶段分离下 1-2 星单位结构性永远后手，与"每 10 攻速=1 秒先手机会"核心卖点冲突）；规则本体 docs/04 §4.1
- [x] **"AI 单位"更名"低级单位"（1~2星角色与造物）**：无论属于真人玩家还是 AI 玩家都自主行动（表现类似 MOBA 里的小兵）；3~5 星为**高级单位**，由所属玩家（真人或 AI 玩家）操控。同时明确 **AI 玩家**（AI 补位玩家）操控其高级单位走玩家选择通道，与低级单位自主决策是两套逻辑
- [x] **尸体被动改为例外制**：**绝大部分被动失效，倒下仍生效的例外在技能中额外说明**（例：凯亚的寒冰之棱——持有者倒下仍然生效，docs/units/蒙德/凯亚.md；纳塔夜魂元能流逝为势力级例外，声明在 docs/07-势力机制/纳塔.md）。原 docs/05 §5.4"被动技能失效"通则与纳塔保留的矛盾就此消除
- [x] **同格争格合并候选一删除**（"枚举序前 N 个入格其余停在格前"）：直接违反 docs/active/22 §1 枚举序铁律（枚举序仅决定命令排列与写-写冲突合并依据，**不影响结算结果**）；保留候选"全部争格失败停在格前"为唯一候选，B4 移动系统落地时拍板（docs/11 移动与体积节）
- [x] **时序模型与 Buff 计时**：整个回合 = 执行阶段**即时演算** + 选择阶段**软暂停**（表现层照播、不产生任何影响战局的结算）；回合制 Buff 只在每次回合结束时计数减一（上 buff 的**当回合**结束即减），现实秒计时只走执行阶段时轴；**执行中段被控时，已上交未执行的行动作废**（与死亡中断同构：开始执行前被控才落空）。规则本体 docs/04 §4.4 + docs/05 §5.5
- [x] **行动配额显式化**：选择阶段可用的全部动作——移动/战技/爆发/延奏/契约/交互、打出手牌（部署角色/建筑、装备物品）——**均各占每回合 1 个行动**（原 05 §5.0-5.2 已隐含，本次显式化；docs/05 §5.0 + docs/07-势力机制/00-总述）
- [x] **"玩家行动阶段"更名为"选择阶段"（2026-09-17）**：阶段名只描述本阶段实际内容——玩家在此只做选择、不做执行，消除"行动阶段里行动却还没执行"的语义歧义；"行动"一词专指**动作单位**（每回合 1 个行动）。历史拍板条目中的旧阶段名按当时原名保留；代码 `BattlePhase`（Selecting/Resolving）本与新名一致，零改动。规则本体 docs/04 §4.1 命名说明
- [x] **乘区运算 = 同乘区内加法并入**：反应/技能提供的增伤、易伤数值**加法并入**所属乘区项后再统一计算，不做独立乘法（一个乘区内的叠加量）；示例：防御 100（基础易伤 0.5）+ 1 级融化（+50%）→ 易伤 = 1.0（docs/05 §5.6 乘区运算规则）
- [x] **体力系统维持现状**：初始 60 + 每回合 5、移动/战技/爆发各耗 10 的结构不变（曾指出"前 12 回合无约束力 + 残局战斗频率减半与终局节奏反向"，知情评估后维持）
- [x] **格子距离 = 切比雪夫度量**：两格距离 = max(|横坐标差|, |纵坐标差|)（对角与正交同距，八方向等价）；"半径 N" = 切比雪夫距离 ≤ N 的全部格子（**正方形区域**：半径 1 = 9 格、半径 3 = 49 格）。对比候选：曼哈顿（与十字技能方向体系同构、菱形范围）、欧氏（浮点运算 + 需格心定义）——知情选择切比雪夫；规则本体 docs/03 §3.3，docs/05 §5.3 / docs/06 §6.4 补引用。附带影响：扩散/导电/寒冰之棱等存量半径数值需按正方形区域复核（B4 技能数值阶段）；结晶"最近单位"等距平局规则待拍板（docs/11 技能与判定）
