## 1. 定位

AI派蒙 = **常驻桌宠 + 对话式游戏助手**：

- **表现层**：派蒙 3D 模型桌面常驻置顶悬浮，游戏失焦/最小化时仍在
- **生命周期**：**拉起不绑命**——启动游戏自动唤出（Mutex 单例防重）；游戏退出/崩溃后派蒙独立存活；关闭方式=三连击她
- **交互层**：拖拽（刚体直跟+四肢摆动+挣扎）、待机动作轮换、视线跟随、屏幕边缘坐
- **功能层**：LLM 对话指令入口（§6.5）

非目标：战斗/联机中表现策略不考虑；不做逐小窗口交互（只认屏幕边缘）；移动端不做独立进程（仅游戏内悬浮挂件）。

## 3. 窗口与渲染

### 3.1 窗口体制【实证+目检】

**固定画布**（VPet/eSheep 源码逐行核验后重写）：

- **窗口**：750×825 逻辑像素 ×DPI×缩放上限固定尺寸；DWM 逐像素 alpha 透明（前提关 `useFlipModelSwapchain`）
- **核心原则**：一切动画期间**相机/模型根/窗口完全静止**——动画只在固定画布内演，窗口位置绝无"播动画的副作用"。窗口唯一移动源：①启动停靠/pet.json 恢复 ②拖拽物理绝对定位 ③松手防丢拉回+防隐形守卫
- **缩放**：滚轮只改模型 localScale（固定窗口防 resize 闪烁）；pet.json 独立存档
- **帧节奏=DWM 帧对齐**：分层窗口 blt present 不阻塞→vSyncCount 实际无效；`DwmFlush` 每帧阻塞到下一次桌面合成=唯一有效节拍器，165Hz 实测 99% 帧 6.06ms/163fps。开时强制 vsync=0+不限帧
- **性能矩阵**【实测】：画布像素对稳态帧时间几乎无感（2.40MP→6.40MP 仅+4%）；真实成本=CPU 单核，全屏逼近满载。当前 3.28MP 落在免费区间

> 演化史（vsync0+限帧30 → vsync2 → vsync1 → 自适应分频 → DwmFlush；窗口体制三轮重构：相机双跟随 → 根绝对补偿 → 固定画布终案）详见 git 历史。业界机制参考：VPet=固定 500×500 画布+走路才移窗；eSheep=窗位即宠位+离场逐帧裁窗。

### 3.2 渲染风格 v8【目检，2026-08-26 定妆】

**纯官方贴图 × 原神式基色暗化描边**：

| 项目 | 内容 |
|------|------|
| 光照 | 全关（`_ShadowStrength=0`/`_RimStrength=0`/SDF 关）；官方贴图自带烘焙渐变即"原神味"；ramp 调子在小窗读作脏色/发绿=负资产。参数全留接线，Inspector 可调回 |
| 描边宽度 | 身体 0.2 / 头发 0.18 / 披风 0.15（脸恒 0——脸轮廓由头发承担）+ 距离/缩放补偿 |
| 描边色 | **基色暗化**【原神逆向实证】：`_OutlineColorMode=1` 时描边=该处主贴图像素×`_OutlineTint(0.5,0.45,0.4)` 逐通道（白衣→冷灰、肤色→暖棕、深发→深发色）；mode=0 回退固定色 |
| 未接 | 原神 ilm/Lightmap A 通道逐区域描边宽度（本项目网格无 UV1 lightmap，每材质统一宽度）；ILM 其余通道/边缘光/发影 |
| 贴图铁律 | Diffuse UV 与光照 UV（UV1）是两套空间，Lightmap/ILM 类贴图不能按像素直接叠加到 Diffuse |

### 3.3 桌面阴影【目检】

剪影→高斯模糊（17-tap×2 轮）→偏移合成 Quad 三步管线。影子壳共享骨骼姿势逐帧同步、专属层独立相机渲 RT、合成 Pass `Blend SrcAlpha OneMinusSrcAlpha, One Zero`（alpha 直写防平方）。内部 shader 必须序列化 Material 引用（Shader.Find 构建期被裁）。参数 Inspector 中文可调。

## 4. 行为层

- **待机循环** + 事件动作（`PetBehaviorController`）：光标停留 1.2s（包围盒扩 90px，冷却 45s）→ Greet；久待机随机小动作（Nod/ShakeHead/Sneer/Clap/Show_1-4，间隔 25-55s）
- **出场/退场**：进程启动播 Appear；三连击=播 Disappear 后 Quit；仪式期间视线+眨眼静默
- **视线跟随**（`PetLookAtController`）：颈(35%)→頭→眼球分层叠加，每帧基线重建（防复利累积自转）【实证】。进入静默=权重混合淡出（输出 `Slerp(动画姿态, 平滑值, w)`，停写时输出恒等于动画姿态=结构性无跳变）
- **动作切换**（GoW4 惯性化）：硬切新 clip + PetInertializer 后处理（五次多项式 C2 衰减，速度承接任意切点无缝）。幅度自适应：偏移<10° 全额拉引+0.6s 慢混；≥60° 拉引×0.3+0.3s 快切
- **统一入口**（`PetAnimSwapper.Play/PlayOnce`）+ 启动全 clip 预热
- **命中网格=一次性补烘**：周期性重烘全删（重 cook 15-22ms 尖峰=切换停顿主凶）；只在交互结束 2s 后补烘一次；cookingOptions=UseFastMidphase

## 5. 进程架构

- 同 exe 双形态：`gic.exe`（主游戏）+ `gic.exe --pet-mode`（桌宠）；`PetMode` 静态开关，编辑器恒 false
- Boot 的 GameScene.Awake 与 Mirror 网络组件 Awake 均有 PetMode 守卫
- 主进程拉起桌宠（PetProcessLauncher，`UNITY_STANDALONE_WIN` 守卫）；Mutex 单例
- **双进程约束**：共享 ScreenManager 注册表——主进程必须显式 SetResolution，桌宠永不碰主存档（独立 pet.json）、永不触发存档写盘
- 构建走 `Tools/桌宠/构建 Windows 桌宠测试包`（构建判据与竞态守卫见 gic-pet skill——**只信 Editor.log RESULT 行**）
- 编辑器联调：`Tools/桌宠/Play 时自动拉起派蒙`（编辑器 Play 自动拉起上次构建产物）

## 6. 功能详情

### 6.1 拖拽与拎起【目检】

**现状**：拖拽=**身体刚体 1:1 直跟光标**（骨盆目标=抓取时骨盆位+光标位移，零摆动零滞后）+**四肢跟拍摆动**+**轻微挣扎**+**松手即停**（骨盆冻结原地、四肢弹簧 ~0.5s 归零）+**放下反应**（按时长分档）。窗口按"骨盆客户区投影钉物理目标位"定位。

**四肢摆动**（`PetDragPhysicsController`）：4 条欠阻尼二阶角弹簧（左右臂/左右腿），目标角∝光标速度低通值（τ=50ms）——水平分量=惯性滞后（往右拖四肢向左甩）+竖直分量=外展（下拖张开/上提收拢，张开上限 10°、收拢再×0.35 防穿模）；臂腿增益/频率微差防同步机械感。应用层=LateUpdate 以**世界 Z 轴**旋转叠加到 `L/R UpperArm`+`L/R Thigh`。参数全在 Inspector 中文可调。

**挣扎**：全身轻微摆动=侧摆±2.5°（绕骨盆钟摆）+扭动±4°（绕竖直轴肩部拧）+四肢反相扑腾±6°（左右肢镜像开合）；两频叠加（次级占比 0.53）防机械摆锤感；包络渐入 0.4s/收尾线性衰减/相位全程连续（收尾中被再抓无跳变）。参数 Inspector 中文可调（单项 0=关闭）。

**拎起动画**（`Ani_NPC_Kanban_Paimon_Drag01.anim`）：躯干 4 骨 C 型塌陷（Spine25°/Spine1 50°/Neck45°/Head55° 链式前屈=含胸低头脸朝观众）+四肢 12 骨贴身垂落共 16 条常量曲线；披风/头发/发饰/手指保留 Standby 微动。姿势基准=拎起转身角 45°（3/4 偏左）×横躺角 0（Inspector 可调，收尾平滑归零）。表情=Confuse。

**放下反应**（物理收尾 0.5s 归位结束后分档播单次，播完自然回待机）：

| 拖拽时长 | 反应 | 动作 | 表情 |
|----------|------|------|------|
| <3s | 无反应 | 直接回待机 | — |
| ≥3s | 害羞 | Shy01AS | 害羞 |
| ≥7.5s | 生气 | Anger | 生气（阈值砍半，用户拍板） |

阈值/动作名 Inspector 中文可调（清空动作名=跳过该档）。

> 标定教训与方向符号规则（世界 Z 轴负角=四肢向右甩，与直觉相反；`Transform.rotation` 即世界旋转误做父系共轭是"左右手反向摆"根因）详见 git 历史。

### 6.2 边缘坐【目检】

**机制**（`PetEdgeSitController`，挂 PetWindow 物体）：拖拽松手（无放下反应档）时磁吸探测附近"横框"——**窗口顶边**（DWM 可见帧 `DWMWA_EXTENDED_FRAME_BOUNDS`，非 GetWindowRect——后者含不可见阴影边 ~7px）+**窗口底边**（坐下沿=身体在窗前、腿垂窗下）+**任务栏顶**（工作区底）→ 磁吸贴合播直坐姿 SitUpright。全体横框最近者胜。掉落跨越检测仍只落顶边（物理下落只能落在上方表面）。

| 参数 | 值 | 说明 |
|------|-----|------|
| 磁吸窗 | 上 120px / 下 60px / 水平 160px | 物理像素，场景序列化值可调 |
| 判定基准 | 骨盆（`Bip001 Pelvis` 投影） | 非包围盒底脚线（脚线判定整条腿沉入窗下） |
| 坐定贴正 | 1.2s 逐帧钉骨盆 | 站→坐姿势过渡平滑"坐进去" |
| 窗口跟随 | 垂直恒贴顶边，水平按锚定比例 | eSheep FollowWindow 同款 |
| 窗口失效 | 重力掉落 2800px/s² | 途中更低窗口顶边可接住，任务栏顶兜底 |
| 坐定中 | 纯坐 | 打招呼/随机小动作全压制；情绪映射无匹配=默认脸 |
| 缩放露馅 | 切回站立→缩放稳定 0.3s 后重坐 | 模型绕脚底长高→屁股浮离窗沿的修正 |
| 枚举过滤 | eSheep 标准 + 现代补充 | 可见+标题非空+非自身+最小化/cloaked/最小尺寸 240×160；0.15s 重枚举节流 |

**坐姿动画 SitUpright**（合成）：Standby 直立上身（抬头+中性脸+idle 微动）+SitLoop 腿（前伸下垂）与手势（上臂世界取向 Δ 补偿，补偿链=根⊗骨盆⊗脊⊗脊1⊗锁骨——漏锁骨差 7°）+骨盆高度不变（0.214）。SitLoop 原版是"生病坐姿"（含胸驼背），弃用。

**合成数学**：换某骨父链后保该骨世界取向 = `q' = newChain⁻¹ ⊗ oldChain ⊗ q`，链必须逐骨完整（非交换，省略中间骨必留残差）。

### 6.4 游戏画面内版派蒙【2026-08-28 落地，复测通过】

**定位**：派蒙渲染在主游戏进程内（游戏画面悬浮），替代桌面版进程——目标安卓（Win32 不适用）与想省内存/单进程的 Windows 玩家。桌面版与游戏内版二选一，设置"派蒙"栏目切换（存档字段 petForm），热切换+启动分发均即时生效。

**渲染架构**（全屏 RT 画布）：

| 项目 | 内容 |
|------|------|
| RT 画布 | RT=屏幕尺寸×rt倍率（默认 1，1:1 像素），RawImage 铺满全屏；模型根在 RT 相机视野内移动（相机恒静置于 (0,10000,0) 附近）。与桌面版窗口体制同构：桌面=固定 750×825 窗+模型窗内演+窗口移动；游戏内=固定"窗"=整屏+模型移动 |
| 正交相机 | 透视投影下模型偏离光轴即斜视畸变【实证】；正交视线处处平行，屏内任何位置恒正对，世界/屏幕像素比恒定（拖拽/缩放标尺不随位置漂移）。可见世界高按原透视 FOV 45.27@模型距离折算 |
| 缩放 | 基准 localScale×(825/1080) 折算（保持屏幕显示尺寸=桌面版 750×825 逻辑窗口）；上限动态钳 `Min(缩放最大, 0.95×视野高/模型高)`（对齐桌面版"工作区 95%"语义） |
| 交互 | legacy Input 全轮询（对齐桌面版 Win32 轮询语义）；命中=光标→RT 视口→射线 vs 烘焙蒙皮碰撞体；事件挡板=全屏透明 Image，命中派蒙时开 raycastTarget 吃掉主游戏点击、未命中穿透（桌面版 WS_EX_TRANSPARENT 穿透切换的同构） |

#### 6.5.2 密钥管理

**链路**：设置「派蒙→对话 API Key」输入 → `PetApiKeyCrypto` AES-128-CBC 加密 → 主存档 `petApiKeyCipher` + `PetPrefs.WriteChatCipher` 磁盘读改写 → 客户端每请求 `PetPrefs.ReadChatCipher` 直读磁盘（绕进程缓存：改 key 即生效+跨进程新鲜），兜底供应商环境变量。Save() 落盘前设置类字段一律取磁盘现值——防桌面进程陈旧缓存抹 key（详见 docs/14 §16）。

**开发 key**（`#if UNITY_EDITOR` 内，构建产物不含此字面量）：SaveManager.CreateNewSave 预填加密 key 到 petApiKeyCipher + 同步 WriteChatCipher 落 pet.json。构建产物两条代码路径均不存在，导出后玩家存档初始化恒为空 key。编辑器与构建共享 persistentDataPath+同机设备指纹=密文互通。

**商业边界**（2026-08-28 拍板）：LLM 费用玩家自付——设置里提供 API Key 输入条目（玩家自己的 key），开发者不出钱不内嵌自己的 key；存档中 key 必须加密存储。**DevKey 本地文件制（2026-09-07）**：key 存项目根 `devkey.txt`（.gitignore 排除，勿提交），`PetApiKeyCrypto.DevKey` 查找链 devkey.txt → `GIC_DEVKEY` 环境变量 → 空（构建产物恒空 key 不变）；git 历史中的旧 key 已于首次推送前用 filter-branch 清洗——key 从未泄出，无需供应商吊销。

### 6.6 三连击切换形态

**机制**（用户拍板"双击改连点3下；游戏存在时切换形态，不存在时才关闭——保证游戏运行时恒有且只有1个派蒙"）：

- **桌面版三连击**（0.4s 窗计次 3）→ fire-and-forget 发 `pet_go_ingame` 指令（PetIntentIpc.RequestFireAndForget，不卡退场）+ 本地 Disappear 退出
- **游戏内版三连击**（同构 0.4s 窗计次 3）→ `PetInGameHost.GestureSwitchTo(FormDesktop)`（主进程内直调无需 IPC；存档 petForm=0 + HotSwitchForm）
- 两条路径行为一致：存档更新 + HotSwitchForm（幂等；内部写 quit_request、**等旧形态退出后才创建新实例**=交接期不并存）
- 游戏未运行→请求 3s 陈旧丢弃无副作用=纯关闭

**点击手势下沉共用层**（用户质问"两种形态应当同步，难道这些逻辑没有复用？"后重构）：

- 连击计次/窗口（0.4s 常量）/聊天收起判定收拢 `PetHostBase`（`CountClickChain`/`ResetClickChain`/`ShouldCloseChatOnClick`）
- 两宿主只保留输入源（Win32 轮询 vs Unity Input）与触发动作（IPC+退出 vs 直调切换）差异
- **单击立即开对话**（两形态一致）：第 1 击即开输入条 + chatInputActive 态点模型且连击计数≥2 不收起（第 2 击静默计数）+ 第 3 击先 CloseChat 再切换；收起路径保留（点外部/超窗点模型）、拖拽打断仍清计数

**设置界面刷新**：`OnPetFormChangedEvent`（Local UI 事件，HotSwitchForm 内广播）——SettingsScreen 派蒙栏下拉订阅刷新（SetValueWithoutNotify 不回环），否则外部切换后下拉显示旧值且点同项不触发 onValueChanged。
