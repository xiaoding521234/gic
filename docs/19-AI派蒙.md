# AI派蒙（桌宠）

> 2026-08-21 立项。设计草稿 + 分阶段实现——本文记录需求、方案与实现进度；§7 待拍板项已于 2026-08-21 回合收敛；**透明置顶窗口 spike 已于 2026-08-21 验证通过并合入主干（见 §5.8）**。

## 1. 定位

AI派蒙 = **常驻桌宠 + 对话式游戏助手**：

- **表现层**：派蒙 3D 模型作为桌面宠物常驻屏幕——只要游戏进程开启就存在，且**不止在游戏窗口内**：游戏失焦/最小化时仍以置顶悬浮形式出现在桌面（桌宠模式）。**桌面置顶悬浮一期直接做**（2026-08-21 拍板，不走"先仅游戏内"妥协路线）
- **生命周期（2026-08-21 二次拍板，取代早前"同生共死"）**：**拉起但不绑命**——启动游戏自动唤出派蒙（桌面已有则跳过）；游戏退出/崩溃后派蒙**独立存活**，继续留在桌面；重开游戏不重复拉起（Mutex 单例）；派蒙的关闭方式=双击她（后续可换右键菜单）。她专为本项目打造，但不必陪葬
- **交互层**：鼠标拖拽（抓斗篷拎起）、待机动作、视线跟随鼠标、屏幕边缘探头（见 §3.5）
- **功能层（预留）**：对话指令入口——"设置游戏内时间 / 打开背包 / 帮我抽卡"等自然语言操作游戏。**接 LLM 实现已拍板，一期不做**（2026-08-21）

非目标：战斗/联机中的表现策略**暂不考虑**（2026-08-21 拍板，届时再说）；**不**细致到与每个小窗口交互（只认屏幕边缘，不做 DesktopMate 式"坐在某窗口标题栏上"）；不承诺移动端桌面形态（见 §6）。

- **v9 工程化（已提交 9c97222）**：配置 SO `PetRetargetConfig`（`Assets/Art/PaimonPet/RetargetConfig.asset`，映射规则表/CLIPS/阈值数据化，加动画只改配置）；AnimationUtility 类型化解析（坑：Transform 曲线 propertyName 是内部名 `m_LocalPosition.x`）；数学核心 `PetRetargetMath` + 自检菜单 `Tools/桌宠/方案B: 数学自检`（109 断言）
- **一致性审计（2026-08-22）**：Standby 与 GI 源逐帧逐骨对比 19 主链骨摆动幅度差 0.02–0.14°（浮点级）、峰值时刻全同；60fps/时长 2.667s 同源。审计方法论：GI 侧曲线 FK 合成 + 符号感知四元数插值（GI 源曲线关键帧存在 q≡-q 符号跳变，分量插值会假翻转——管线只在 key 时刻取值不受影响，但**审计/采样类工具必须符号感知**）
- **演化坑史（全实测）**：v1 GI 绝对旋转→逐骨捻碎（Max 骨轴滚转任意）；v2 纯增量→MMD 站立绑定 vs GI 悬空 f0 基准差=腿直棍；v3 目骨平移虹膜不驱动（对齐残差 8mm 把左眼虹膜推出眼眶）；v5 位置+方向双硬对齐→过约束骨长压短皮肤绷紧+腰前翘；v7 只驱动 28 代表骨→辅助骨保持绑定（裙摆/腰腹皮肤不动=僵硬主病灶）→全骨驱动；v7.2 躯干按 Biped 骨段对齐=肚子前翘 25.7°（结构角）→指向头骨；v8 捻骨世界 Slerp→MMD 手臂链绑定相邻骨反相对齐（179.9°）被捋直=每臂三处塌缩→捻骨并入跟随公式保 180° 结构
- **腿部病灶排查定案（2026-08-23，工具 `Tools/桌宠/腿部方向审计` = PaimonLegAudit.cs）**：用户报"左膝前弯"。审计方法：用管线同款对齐 R 直接对比输出 clip FK 膝段方向 vs R⁻¹·GI 源方向（纯向量夹角，无参考系歧义——此前多轮排查被"模型自身前后左右重建"反复误导，教训：**任何姿态审计必须用已知映射矩阵，禁止从骨骼位置重建局部坐标系**）。结论：①11/13 条输出数学完美（误差 0-9°，含此前误判的 C07=0.0°）——重定向管线本体无恙；②**C05_01 剔除**：源曲线路径全为哈希数字，管线按设计忽略 → 此前输出实为静态 Standby（从未真正重定向），已从 CLIPS 移除并删产物；③**Standby R@1.34s / C06 R@0.83s 两处"单帧误差"为审计伪影**：GI 源 Bip001 R Thigh 存在真实 q≡-q 符号跳变（@0.27/0.82/1.35s），审计 AnimationMode 跨跳变分量插值出假翻转，与误差时刻精确吻合；管线本体不受影响（key 时刻取值 + v11 双保险）；④**v11 加固**：BuildTrack 旋转曲线符号连续化——堵死 frameTimes 并集时刻跨跳变插值的污染路径（docs 此前"管线只在 key 时刻取值不受影响"论断不严谨）。用户看到的"膝前弯"最可能是 C05_01 静态错位（恒 77.9°）或裙摆 D 链视觉（待目检复验）

### 2.6 表情层（2026-08-22 完成，语义级复刻）

- **数据现状（实测）**：旧批次 `Ani_NPC_Kanban_Paimon_*`（含 Standby/Greet/Anger）**不含表情曲线**；Cs 系列（`Ani_Cs_*`，C01-C59 共 52 条）带 49 条 blendShape 曲线（path=Face, classID=137）。
- **表情与动作是两套系统（2026-08-22 晚定论）**：状态机动画（旧批次）零表情曲线=游戏运行时表情由另一层驱动（程序化眨眼/表情系统，行业通行 Animator body/face 分层做法，米哈游未公开细节）；Cs 过场动画自带表情=预烘焙演出数据。AssetMap 中派蒙无独立 Blink/Face 资产（其他个别生物如柴犬有 `Ani_..._Blink_AS` 族）。重导多少遍旧批次也导不出表情——源数据本就没有，非导出丢失（时间戳实证：两族同一次导出会话产出）
- **哈希映射无解**：Cs 曲线属性名=哈希数字（`blendShape.3985037423` 等，GI mesh 打包时 morph 名被哈希化），GI mesh 不可导出（反优化判死）→ 哈希→语义映射无本地解
- **眨眼数据陷阱（v2 修正，用户目检纠正）**：Cs 系列高频短脉冲曲线（0.05-0.08s，间隔中位 0.03-0.08s=每秒12~30次）是**说话嘴部/眼球微颤**，不是眨眼——真人眨眼间隔 2-10s。v1 误把脉冲时长当眨眼特征注入了 2.68s×4 眨（用户反馈"频率过高，原神没这么频繁"）。v2 修正：每循环 1 眨（t=1.3s，每 2.68s 一眨≈真人自然频率下限）
- **方案（v4 定案，行业通行三层架构）**：**表情全部运行时驱动，零烘焙进 clip**
  - **身体层** = Animation clip（方案 B 管线产物，morph 无曲线）
  - **情绪层** = `Assets/_Scripts/Pet/PetEmotionController.cs`（指令式：SetEmotion(情绪名)，情绪表 Inspector 中文可配 情绪名/Morph名/强度/过渡秒/延迟秒/保持秒/复位秒；保持秒<0=持续到下指令，>0=到时自动复位）；`PetAnimSwapper.Play` 按动作名映射下发（映射表 Inspector 可配，当前 Anger→怒り 100% 过渡 0.25s；无映射动作下发空名清回默认脸）
  - **微动作层** = `PetBlinkController`（随机 timer 2.5~5.5s 眨眼，时长 0.13s，Inspector 中文可调）
  - **morph 独占约定**：组件管理的 morph 不得出现在任何 clip 曲线中（Animation 只覆盖 clip 中存在的曲线，clip 无曲线则组件权重生效）——`PaimonFacePipeline.cs` 已改为纯清理工具（菜单 `Tools/桌宠/表情曲线清理(迁移运行时架构)`，清残留 blendShape 曲线，幂等）

## 3. 表现与交互设计

### 3.1 常驻显示

- 生命周期：启动游戏 → 自动唤出派蒙（已存在则跳过）；游戏退出/崩溃 → **派蒙独立存活**（2026-08-21 拍板不绑命）；双击派蒙 → 派蒙退出
- 显示层级：优先于游戏窗口与其他应用；游戏后台时仍置顶悬浮于桌面
- 位置：默认屏幕角落；拖拽松手后记忆停留位置（写入**独立配置文件**——同 exe 双进程不得碰主存档，见 §5.8 约束）

### 3.2 拖拽交互（抓斗篷 · 仓鼠式拎起）

核心手感：**鼠标抓住的是背上的斗篷，不是派蒙本体**——像抓仓鼠后颈皮一样把派蒙整个拎起：

- 按住派蒙（命中斗篷区域）→ 斗篷被"捏住"，派蒙身体悬垂
- 移动鼠标 → 抓点跟随鼠标，身体因重力自然垂坠、随移动惯性摆动（钟摆效应，拖快了会被甩起来）
- 松手 → 下落回停靠位置，轻微弹跳/晃动后恢复待机

物理要求（"真实物理效果"）：

| 状态 | 要求 |
|------|------|
| 拎起 | 身体绕抓点下垂摆动（单摆），有角速度惯性与阻尼 |
| 拖动 | 弹簧-阻尼跟随（滞后+回弹，非刚性瞬移）；头/四肢相对躯干次级滞后摆动 |
| 斗篷 | 被捏住处固定，其余部分布料式摆动 |
| 松手 | 自由落体 + 落地弹跳衰减 |

- 候选实现：Verlet 链/弹簧骨骼（把派蒙当作挂在抓点下的多节弹簧链）或 Unity SpringBone；斗篷用 Cloth 或骨骼链。**不做全刚体 Ragdoll**（易穿模难稳定，弹簧链手感更好）
- 手感参数（摆幅/阻尼/回弹强度）落地时暴露为 Inspector 中文命名字段，用户自调

### 3.3 待机动作

- 动作集（初版候选，待模型入库后确认）：悬浮呼吸/原地扑腾、左右张望、打哈欠、发呆眨眼、长时间无操作→打瞌睡
- 触发：随机轮换 + 事件触发（无操作计时、拖拽结束、指令执行）
- 依赖模型动画与 BlendShape，具体清单待定

### 3.4 视线跟随（头看鼠标）

- 头部实时朝向鼠标屏幕位置，平滑阻尼（转头不瞬移）
- 角度限制：超过肩颈合理范围即停止/带动身体，避免"拧脖子"
- 模型支持的话，眼球骨骼/BlendShape 瞳孔小范围跟随

### 3.5 屏幕边缘探头（扒边框）

派蒙被拖到/停靠在**屏幕边缘**时的特殊状态（2026-08-21 新增拍板）：

- **进入**：拖拽松手时停靠点距屏幕边缘小于阈值（或直接被甩出屏幕），派蒙滑到边缘外，转为"扒边"——**身体在屏幕外，只露出头和扒住屏幕边框的双手**，朝屏幕内探头张望
- **表现**：手扒边框 + 探头（可配张望/眨眼/偶尔缩回去只露半张脸等小动作变体）；探头姿态下视线跟随鼠标仍生效
- **退出**：再次抓住拖回屏幕内，恢复正常悬浮；长时间无操作可自行爬回或原地打瞌睡（变体，落地时定）
- **实现要点**：
  - 边缘检测：虚拟桌面坐标系下判断宠物锚点是否越出屏幕工作区边界（多显示器：只认主屏/宠物所在屏的边缘，跨屏拖拽待定）
  - 动画：优先用原神提取的扒边/探头类动作参数还原；无现成动作则手 K（手部定位于边框 + 身体 offset 到屏幕外）
  - 与拖拽物理衔接：松手时的惯性决定"滑出"还是"停在场内"，越界后钳制到扒边姿态吸附点
- **边界**：只认**屏幕边缘**，不做逐窗口边框交互（拍板：暂不需要细致到每个小窗口）

### 4.3 Agent/LLM 框架调研（2026-08，一期不实现仅选型参考）

本项目需求画像：**单角色对话 + 工具调用（Intent→Action）+ Unity C# + 中文**——不是多智能体编排场景，重量级 Agent 框架（LangGraph/CrewAI/AutoGen 等，且均为 Python/TS 生态）对本需求偏重，接入它们意味着为 Unity 游戏外挂一个 Python sidecar 服务。候选分层：

| 方案 | 类型 | 优点 | 缺点 | 适用 |
|------|------|------|------|------|
| **云 LLM API + 自研薄 Intent 层**（豆包/DeepSeek/GLM，OpenAI 兼容 + Function Calling） | 云 API | 零依赖、成本可控、中文强、function calling 原生 | 需联网/密钥管理 | **推荐主选**：C# HttpClient 直连，Intent 层就是 doc 已设计的 Intent→Action |
| **LLMUnity**（github.com/undreamai/LLMUnity） | 本地推理（llama.cpp 内嵌 Unity） | 完全离线、开源、Unity 原生组件（LLM/LLMAgent），支持 RAG；官网案例里就有"Anime Desktop AI Companion"桌宠 | 无原生 function calling（需手写 JSON 输出解析）；本地模型能力弱于云端；移动端仅 1-2B 小模型 | 离线/隐私敏感时的备选；也适合先做对话体验 demo |
| **Ollama/LM Studio + HTTP** | 本地推理（本地服务） | 模型可换、支持 tool calling 的新模型（Qwen 等）、与 Unity 解耦 | 本机常驻服务进程；用户机器需自装 | 开发期本地调试方便 |
| **Agora Conversational AI Engine / Inworld / Convai** | 商业 NPC 平台 | 语音全链路（ASR→LLM→TTS）开箱即用、游戏状态注入 | 按量计费、绑定平台、中文与定制受限 | 将来做"语音对话"阶段再评估，文字指令阶段不需要 |
| **通用 Agent 框架**（LangGraph/CrewAI/Vercel AI SDK/OpenAI Agents SDK 等 2026 主流） | 编排框架 | 多智能体/持久化/MCP 生态成熟 | Python/TS 生态，需 sidecar 进程；本需求用不上多智能体 | 暂不采用；若未来派蒙要多步任务规划（"帮我清日常"）再评估 |

选型结论（草稿建议，一期落地前复核）：
- **文字指令期**：云 API function calling + 自研 Intent 层（架构即 §4.2，无需引入框架）；LLMUnity 作为离线降级备选
- **语音期（远期）**：TTS 已有项目内通道（AudioManager.PlayVoice，可 voice_clone 派蒙音色）；ASR/对话编排届时评估 Agora 类平台 vs 自建
- 关注 **MCP（Model Context Protocol）** 作为工具接入标准的演进——若 C# 生态出现成熟 MCP SDK，Intent 层工具注册可对齐该标准，避免自研格式锁死

**关于"接团结提供的 GLM"（2026-08-21 查证）**：不可行——Tuanjie AI/Codely 的 GLM-5.2 Max 是**编辑器侧**开发工具模型（公测免费额度），AI Graph 也是编辑器侧 AIGC 资产工作流，均不提供游戏运行时 API。要接 GLM，直接用**智谱 BigModel 开放平台**（bigmodel.cn，同款 GLM 模型，OpenAI 兼容 + function calling，按量计费，自备 API Key），或经阿里云百炼等聚合平台调用。

## 5. 技术要点与风险（PC 桌宠形态）

1. **透明置顶窗口**：Unity 无原生支持——需 Win32 API（无边框 + WS_EX_LAYERED + 置顶 + 色键透明），相机纯色背景——**✅ 2026-08-21 spike 验证通过，已实现，详见 §5.8**
2. **双进程架构（已实现，生命周期二次拍板为"拉起不绑命"）**：同 exe 加 `--pet-mode` 参数启动轻量宠物进程（透明置顶窗口 + 派蒙渲染 + 拖拽/探头逻辑），主游戏进程照常全屏。主进程 GameScene.Awake 拉起子进程前先 OpenMutex 探测（Local\GIC_PaimonPet_SingleInstance，已有派蒙则跳过）；**不绑 Job Object、不持句柄**——游戏退出/崩溃派蒙照常存活；派蒙进程启动时 CreateMutex 声明单例（重复实例首帧前 Quit）。将来 IPC（named pipe/socket）仍按预留设计——指令（§4）经 IPC 下发主进程执行，游戏在跑则执行、不在跑则派蒙单机卖萌
3. **输入穿透**：悬浮窗非模型区域鼠标事件穿透到下层（按像素 alpha 命中动态切换穿透，Win32 WS_EX_TRANSPARENT 动态开关）；模型区域接收点击/拖拽
4. **模型导入**：MMD/原神提取 → Unity 的材质/骨骼/物理/动作重定向重建（§2）
5. **性能**：宠物进程常驻渲染单个角色需限帧（如 30fps）、待机降频、单光源简单 Toon；不能影响主游戏帧率与功耗
6. **多显示器**：边缘检测与停靠位置记忆需明确单屏/多屏策略（§3.5）
7. **战斗/联机兼容**：暂不考虑（拍板）；将来需要时再做隐藏/缩小策略

### 5.9 派蒙原神风格卡渲（2026-08-22 一期完成）

- **Shader** `Assets/Shaders/PaimonToon.shader`（内置管线 CGPROGRAM 风格，URP 下无光照 pass 正常渲染，项目既有风格）：完全自包含**不读场景灯**——虚拟光方向=材质属性 `_LightDir`，无灯场景保持贴图原生亮度（用户拍板"不需要光照"）；Pass1 本体 + Pass2 视图空间法线外扩描边（Cull Front 壳，距离补偿）
- **关键原料结论（实测）**：模之屋 MMD 贴图（脸/头发/衣服）与官方 Diffuse **UV 布局完全一致**（纹理相关性 1.000，即官方贴图放大重绘版）→ 官方 ShadowRamp/Face_Lightmap 可直接用于 MMD 模型；披风2/表情是改模者自绘布局（相关性 0.1，不接入）
- **ramp 行选择有官方依据**：Body_Lightmap R 通道=材质 ID（皮肤 texel R=1.0、白布 R=0）× 官方公式 `rampV=ilm.r*0.5+0.25` → 皮肤 v=0.75（暖光紫影带）、衣服 v=0.25（薰衣草影带）；头发固定行 v=0.425
- **面部=原神 SDF 阴影**：Face_Lightmap R 通道（R=G=A 同图，已设线性导入 sRGB=off）即 SDF 面部阴影图——左暗右亮渐变+鼻梁轮廓带；`_FACESHADOW` keyword 启用，光从右→镜像采样（**实测 corr(uv.x,世界X)=-0.983：SDF 高UV亮侧=模型左脸**，镜像条件 L.x≥0）；亮/暗色与皮肤同 ramp 行 → 面部与身体色调连续
- **材质参数**（8 个 .mat 在 `Assets/Art/PaimonPet/Materials/`，全部 Inspector 中文可调）：脸=SDF+皮肤行+描边0.7、皮肤=0.75行、衣服=0.25行、头发=Hair ramp 0.425+描边1.2、披风=0.925行双面、眼白/眼睛/表情=全亮不描边；Ramp 贴图已关 mipmap 防跨行混合
- **测试场景** PaimonRetargetTest：无灯（MainLight 已删）、地面 RetargetGroundUnlit.mat（URP/Unlit 绿色）——渲染与灯光彻底解耦
- **2026-08-22 二次拍板：桌宠完全无光照（当前生效状态）**——用户目检反馈"看起来仍有光照、被照成绿色"。像素采样实证根因：白发×ramp 中段被染灰压暗（(167,158,150)）+部分 ramp 段黄绿脏色调+SDF/ramp 明暗渐变的"光照感"。**全部 8 材质阴影强度=0、脸部 SDF 关闭**——输出=纯贴图颜色（复采样头发回中性灰）。ramp/SDF/虚拟光参数全部保留在材质上，将来想开随时 Inspector 调回；重开时注意头发 ramp 行 0.425 亮端偏黄绿 (0.92,0.93,0.82) 应换行
