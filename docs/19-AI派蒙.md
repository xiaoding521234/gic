## 1. 定位

AI派蒙 = **常驻桌宠 + 对话式游戏助手**：

- **表现层**：派蒙 3D 模型作为桌面宠物常驻屏幕——只要游戏进程开启就存在，且**不止在游戏窗口内**：游戏失焦/最小化时仍以置顶悬浮形式出现在桌面（桌宠模式）。**桌面置顶悬浮一期直接做**（2026-08-21 拍板，不走"先仅游戏内"妥协路线）
- **生命周期（2026-08-21 二次拍板，取代早前"同生共死"）**：**拉起但不绑命**——启动游戏自动唤出派蒙（桌面已有则跳过）；游戏退出/崩溃后派蒙**独立存活**，继续留在桌面；重开游戏不重复拉起（Mutex 单例）；派蒙的关闭方式=双击她（后续可换右键菜单）。她专为本项目打造，但不必陪葬
- **交互层**：鼠标拖拽（抓斗篷拎起）、待机动作、视线跟随鼠标、屏幕边缘探头（见 §3.5）
- **功能层（预留）**：对话指令入口——"设置游戏内时间 / 打开背包 / 帮我抽卡"等自然语言操作游戏。**接 LLM 实现已拍板，一期不做**（2026-08-21）

非目标：战斗/联机中的表现策略**暂不考虑**（2026-08-21 拍板，届时再说）；**不**细致到与每个小窗口交互（只认屏幕边缘，不做 DesktopMate 式"坐在某窗口标题栏上"）；不承诺移动端桌面形态（见 §6）。

## 3. 表现与交互设计

### 3.1 常驻显示

- 生命周期：启动游戏 → 自动唤出派蒙（已存在则跳过）；游戏退出/崩溃 → **派蒙独立存活**（2026-08-21 拍板不绑命）；双击派蒙 → 播退场动画后派蒙退出（2026-08-24 起，见 §3.3 出场/退场）
- 显示层级：优先于游戏窗口与其他应用；游戏后台时仍置顶悬浮于桌面
- 位置：默认屏幕角落；拖拽松手后记忆停留位置（**已实现 2026-08-24**：写入独立配置文件 `pet.json`——同 exe 双进程不得碰主存档，见 §5.8 约束；缩放倍率同文件持久化，防抖 1s 落盘+退出兜底）

### 3.2 拖拽交互（抓斗篷 · 仓鼠式拎起）

核心手感：**鼠标抓住的是背上的斗篷，不是派蒙本体**——像抓仓鼠后颈皮一样把派蒙整个拎起：

- 按住派蒙（命中斗篷区域）→ 斗篷被"捏住"，派蒙身体悬垂
- 移动鼠标 → 抓点跟随鼠标，身体因重力自然垂坠、随移动惯性摆动（钟摆效应，拖快了会被甩起来）
- 松手 → 下落回停靠位置，轻微弹跳/晃动后恢复待机

物理要求（"真实物理效果"）：

| 状态 | 要求 |
|------|------|
| 拎起 | 身体绕抓点下垂摆动（单摆），有角速度惯性与阻尼 |
| 拖动 | 弹簧-阻尼跟随（滞后+回弹，非刚性瞬移）；头/四肢相对躯干次级滞后摆动 |
| 斗篷 | 被捏住处固定，其余部分布料式摆动 |
| 松手 | 自由落体 + 落地弹跳衰减 |

- 候选实现：Verlet 链/弹簧骨骼（把派蒙当作挂在抓点下的多节弹簧链）或 Unity SpringBone；斗篷用 Cloth 或骨骼链。**不做全刚体 Ragdoll**（易穿模难稳定，弹簧链手感更好）
- 手感参数（摆幅/阻尼/回弹强度）落地时暴露为 Inspector 中文命名字段，用户自调

- 依赖模型动画与 BlendShape，具体清单待定

**实现（2026-08-24 首期，`PetBehaviorController`）**：光标在派蒙旁停留（模型包围盒投影屏幕矩形扩 90px 内停留 1.2s，冷却 45s）→ 播 Greet 一次回待机；久待机（光标不在旁）→ 随机小动作轮换（Nod01/ShakeHead01/Sneer01/Clap01/**Show_1~Show_4**，间隔 25-55s，列表/参数 Inspector 中文可调）。播放统一走 PetAnimSwapper.PlayOnce（新增：wrapMode Once + 情绪/手指挂钩同 Play），行为层只管"何时播什么"；拖拽中不触发。动作列表同步：菜单 `Tools/桌宠/同步 PaimonPet 动作列表`（PetSceneSyncTool，重跑重定向管线后跑一次——管线删旧建新 clip 会换 GUID，场景引用靠它对齐）。

**出场/退场（2026-08-24 傍晚）**：出场=进程启动后首帧（PetAnimSwapper 预热完成的同帧、渲染前）播 `Appear` 一次回待机（`PetBehaviorController.出场动画名`，Inspector 可换）；退场=双击退出改为先播 `Disappear`、播完才真正 `Application.Quit()`（`请求退场(Action)` API，窗口控制器注入退出回调；无 clip/无行为层时兜底立即退出；退场中屏蔽重复双击/新拖拽/一切行为触发）。编辑器 Play 下 Quit 无效——退场动画播完自然回待机，可反复目检。**出场/退场期间视线跟随与眨眼一并静默**（`置仪式静默`：头链完全交给动画曲线——`PetLookAtController.Set视线静默` 恢复时首帧重置平滑基准防瞬移归位）；普通单次小动作只静默眨眼不静默视线（待机微动+视线叠加是常态）。

### 3.4 视线跟随（头看鼠标）

- 头部实时朝向鼠标屏幕位置，平滑阻尼（转头不瞬移）
- 角度限制：超过肩颈合理范围即停止/带动身体，避免"拧脖子"
- 模型支持的话，眼球骨骼/BlendShape 瞳孔小范围跟随

**实现（2026-08-23，`PetLookAtController`，PaimonPet 场景）**：首(分担35%)→頭→目.L/目.R 分层叠加，世界空间增量法（LateUpdate 在 clip 姿势上叠加"光标相对屏幕中心偏移×最大角"的旋转增量，动画微动完整保留）；光标走 `PetWindowController.TryGetCursorUnityScreenPos`（Win32 全局轮询，无焦点/屏外可追踪）；指数阻尼平滑（头 8 / 眼 14）。"带动身体"未做（先只钳制停止）。

**眼球修复（2026-08-23 晚，v5 定案）**：曾"只剩眼白 + 鼠标不动眼球自转"。根因有二：①clip 中目.L/目.R 本体无曲线（曲线在 目戻/_dummy/_shadow 子骨上），动画每帧不覆写眼球骨骼，v3/v4 在上帧残留旋转上继续叠加增量 → **复利式累积自转**到极限位只剩眼白；②颈分担 35% 后头又叠加满份（头世界旋转已含父骨增量）→ 总偏转 1.35× 过冲，眼球余量被迫反向补偿。修复：**每帧用启动时本地基线重建中性姿态**（父骨当前旋转 × 本地基线快照）再叠加余量，不再累积；余量基准从首帧快照改为本帧动画姿态（待机摇晃不再漏进眼球反向补偿）；头分担改 `1-颈分担`（颈+头恰 1×）；眼球最大角 8°→15°（小幅不可见）。眼球余量 = inv(头链本帧实际叠加增量) × 目标增量，头未转满时眼球快速补足、头收敛后余量归零眼球随动画回中。

### 3.5 屏幕边缘探头（扒边框）

派蒙被拖到/停靠在**屏幕边缘**时的特殊状态（2026-08-21 新增拍板）：

- **进入**：拖拽松手时停靠点距屏幕边缘小于阈值（或直接被甩出屏幕），派蒙滑到边缘外，转为"扒边"——**身体在屏幕外，只露出头和扒住屏幕边框的双手**，朝屏幕内探头张望
- **表现**：手扒边框 + 探头（可配张望/眨眼/偶尔缩回去只露半张脸等小动作变体）；探头姿态下视线跟随鼠标仍生效
- **退出**：再次抓住拖回屏幕内，恢复正常悬浮；长时间无操作可自行爬回或原地打瞌睡（变体，落地时定）
- **实现要点**：
  - 边缘检测：虚拟桌面坐标系下判断宠物锚点是否越出屏幕工作区边界（多显示器：只认主屏/宠物所在屏的边缘，跨屏拖拽待定）
  - 动画：优先用原神提取的扒边/探头类动作参数还原；无现成动作则手 K（手部定位于边框 + 身体 offset 到屏幕外）
  - 与拖拽物理衔接：松手时的惯性决定"滑出"还是"停在场内"，越界后钳制到扒边姿态吸附点
- **边界**：只认**屏幕边缘**，不做逐窗口边框交互（拍板：暂不需要细致到每个小窗口）

### 4.3 Agent/LLM 框架调研（2026-08，一期不实现仅选型参考）

本项目需求画像：**单角色对话 + 工具调用（Intent→Action）+ Unity C# + 中文**——不是多智能体编排场景，重量级 Agent 框架（LangGraph/CrewAI/AutoGen 等，且均为 Python/TS 生态）对本需求偏重，接入它们意味着为 Unity 游戏外挂一个 Python sidecar 服务。候选分层：

| 方案 | 类型 | 优点 | 缺点 | 适用 |
|------|------|------|------|------|
| **云 LLM API + 自研薄 Intent 层**（豆包/DeepSeek/GLM，OpenAI 兼容 + Function Calling） | 云 API | 零依赖、成本可控、中文强、function calling 原生 | 需联网/密钥管理 | **推荐主选**：C# HttpClient 直连，Intent 层就是 doc 已设计的 Intent→Action |
| **LLMUnity**（github.com/undreamai/LLMUnity） | 本地推理（llama.cpp 内嵌 Unity） | 完全离线、开源、Unity 原生组件（LLM/LLMAgent），支持 RAG；官网案例里就有"Anime Desktop AI Companion"桌宠 | 无原生 function calling（需手写 JSON 输出解析）；本地模型能力弱于云端；移动端仅 1-2B 小模型 | 离线/隐私敏感时的备选；也适合先做对话体验 demo |
| **Ollama/LM Studio + HTTP** | 本地推理（本地服务） | 模型可换、支持 tool calling 的新模型（Qwen 等）、与 Unity 解耦 | 本机常驻服务进程；用户机器需自装 | 开发期本地调试方便 |
| **Agora Conversational AI Engine / Inworld / Convai** | 商业 NPC 平台 | 语音全链路（ASR→LLM→TTS）开箱即用、游戏状态注入 | 按量计费、绑定平台、中文与定制受限 | 将来做"语音对话"阶段再评估，文字指令阶段不需要 |
| **通用 Agent 框架**（LangGraph/CrewAI/Vercel AI SDK/OpenAI Agents SDK 等 2026 主流） | 编排框架 | 多智能体/持久化/MCP 生态成熟 | Python/TS 生态，需 sidecar 进程；本需求用不上多智能体 | 暂不采用；若未来派蒙要多步任务规划（"帮我清日常"）再评估 |

选型结论（草稿建议，一期落地前复核）：
- **文字指令期**：云 API function calling + 自研 Intent 层（架构即 §4.2，无需引入框架）；LLMUnity 作为离线降级备选
- **语音期（远期）**：TTS 已有项目内通道（AudioManager.PlayVoice，可 voice_clone 派蒙音色）；ASR/对话编排届时评估 Agora 类平台 vs 自建
- 关注 **MCP（Model Context Protocol）** 作为工具接入标准的演进——若 C# 生态出现成熟 MCP SDK，Intent 层工具注册可对齐该标准，避免自研格式锁死

**关于"接团结提供的 GLM"（2026-08-21 查证）**：不可行——Tuanjie AI/Codely 的 GLM-5.2 Max 是**编辑器侧**开发工具模型（公测免费额度），AI Graph 也是编辑器侧 AIGC 资产工作流，均不提供游戏运行时 API。要接 GLM，直接用**智谱 BigModel 开放平台**（bigmodel.cn，同款 GLM 模型，OpenAI 兼容 + function calling，按量计费，自备 API Key），或经阿里云百炼等聚合平台调用。

## 5. 技术要点与风险（PC 桌宠形态）

1. **透明置顶窗口**：Unity 无原生支持——需 Win32 API（无边框 + WS_EX_LAYERED + 置顶 + 色键透明），相机纯色背景——**✅ 2026-08-21 spike 验证通过，已实现，详见 §5.8**
2. **双进程架构（已实现，生命周期二次拍板为"拉起不绑命"）**：同 exe 加 `--pet-mode` 参数启动轻量宠物进程（透明置顶窗口 + 派蒙渲染 + 拖拽/探头逻辑），主游戏进程照常全屏。主进程 GameScene.Awake 拉起子进程前先 OpenMutex 探测（Local\GIC_PaimonPet_SingleInstance，已有派蒙则跳过）；**不绑 Job Object、不持句柄**——游戏退出/崩溃派蒙照常存活；派蒙进程启动时 CreateMutex 声明单例（重复实例首帧前 Quit）。将来 IPC（named pipe/socket）仍按预留设计——指令（§4）经 IPC 下发主进程执行，游戏在跑则执行、不在跑则派蒙单机卖萌
3. **输入穿透**：悬浮窗非模型区域鼠标事件穿透到下层（按像素 alpha 命中动态切换穿透，Win32 WS_EX_TRANSPARENT 动态开关）；模型区域接收点击/拖拽
4. **模型导入**：MMD/原神提取 → Unity 的材质/骨骼/物理/动作重定向重建（§2）
5. **性能**：宠物进程常驻渲染单个角色需限帧（如 30fps）、待机降频、单光源简单 Toon；不能影响主游戏帧率与功耗
6. **多显示器**：边缘检测与停靠位置记忆需明确单屏/多屏策略（§3.5）
7. **战斗/联机兼容**：暂不考虑（拍板）；将来需要时再做隐藏/缩小策略

**关键坑（全实测，详见 docs/14）**：
- **DWM 生效前提**：必须关闭 Player Settings 的 `useFlipModelSwapchain`（flip model swapchain 不透传逐像素 alpha，开启时 DWM 窗口整体全透明连模型一起看不见）
- **DPI 缩放**：exe 清单 PerMonitorV2（客户区物理像素=渲染像素）；窗口客户区物理尺寸=逻辑尺寸(550×825@96dpi，2026-08-24 由 480×720 扩出阴影边距，见 §5.10)×GetDpiForWindow/96×当前缩放；命中/视线换算改 GetClientRect+ClientToScreen（消 GetWindowRect 隐形边框误差）
- **缩放对齐主流桌宠（2026-08-24 三期：固定窗口=闪烁根治）**：**窗口客户区尺寸恒=基准(550×825 逻辑×DPI)×有效缩放上限，运行期不随缩放变化**——平滑过渡期间逐帧 SetWindowPos 改窗口尺寸会令 swapchain/DWM 高频重建合成（派蒙肉眼高频闪烁，实测），固定窗口后缩放只改 Paimon 根 localScale；相机/窗口恒定→**脚底客户区位置天然锚定**（绕脚底原地长高，对齐 DesktopMate/VPet 脚底语义）；oversized 窗口区域全透明+命中外穿透，无视觉/交互代价；**平滑过渡**=滚轮只改目标倍率，显示倍率每帧指数趋近（`缩放平滑速度`=12，0=瞬达）；**持久化**=`{persistentDataPath}/pet.json`（缩放+窗口客户区原点物理像素；防抖 1s 落盘+OnDestroy/退出兜底；启动恢复位置优先于右下角停靠，钳制到虚拟屏幕矩形——拔显示器后拉回可找范围；编辑器恒跳过，主进程永不读写该文件）；有效缩放上限=min(缩放最大, 工作区 95%)。**大小基准变化（2026-08-24）**：旧"窗口随缩放"版派蒙屏幕尺寸∝s²（模型+窗口同倍），固定窗口版∝s（仅模型）——同 s 值新版渲染偏大，存量 pet.json 缩放偏大属预期，滚轮重调一次即可
- **构建竞态**：`Tools/桌宠/构建 Windows 桌宠测试包` 经 `delayCall` 排到时若脚本编译/导入尚未落地，`BuildPlayer` 报 `Error building Player because scripts are compiling`（`RESULT FAIL errors=0 size=0` 假失败）。修复=`PetSpikeBuildTool.BuildInternal` 起手 + `AssetDatabase.Refresh` 后各加一道 `isCompiling||isUpdating` 守卫。**建成判据**：Editor.log `[PetSpikeBuild] RESULT OK errors=0 size=778059931`，exe/dll 属 payload 时间戳不更新、别以 exe 时间为准。**更深一坑（2026-08-24 实证）**：守卫齐全+编辑器程序集已新，BuildPlayer 仍可能复用旧 PlayerDataCache 产出旧代码的"RESULT OK 假成功"——判据升级=除 RESULT OK 外验证构建 DLL 含新代码字面量（UTF16 文本搜索）；补救=对改动 .cs 显式 `ImportAsset(ForceUpdate)` 后重编译再构建（详见 gic-pet skill）
- **命中关键坑**：`BakeMesh(mesh, useScale=true)` 输出在 SMR 局部/骨骼空间（顶点模长 <1），命中节点必须与 SMR 同 transform 且不能带额外缩放；DWM 透明分支必须挂 `WS_EX_LAYERED`（曾漏挂致穿透/双击全失效）；命中坐标须按 `Screen.width/窗口物理宽` 换算 DPI

### 5.9 派蒙原神风格卡渲（2026-08-22 一期完成）

### 5.10 桌宠阴影（2026-08-24 二期重做：高斯投影 = 2026 主流桌宠做法）

- **需求定案**：用户要的不是脚下地面阴影，而是 **DWM 窗口阴影式屏幕投影**——派蒙轮廓投到桌面上、跟随她的姿势（像网页/Windows 窗口在屏幕上的投影）。首版"脚下椭圆 Quad"已废弃；次版"PaimonToon 加 Pass3"因 **URP 只执行第一个 Pass**（多 Pass 描边/投影 Pass 全失效）而完全不渲染，已回滚；一期定案的"双物体法线外扩硬壳"（PaimonDropShadow.shader + .mat）**只有硬边实心影、无真正柔边（法线衰减是棋盘噪点），不符合主流观感，二期废弃已删**
- **二期方案 = 剪影 → 高斯模糊 → 偏移合成**（CSS `filter: drop-shadow` / DWM 窗口阴影 / VPet DropShadowEffect 同款管线，2026 主流桌宠标准做法）：
  1. `_DropShadow` 影子壳沿用一期结构（复制本体 Paimon_mesh 的 SMR，**共享同一套 219 骨骼 + 根骨 + 网格** → 姿势逐帧同步），8 槽全换 `PaimonShadowSilhouette.mat`（`GIC/PaimonShadowSilhouette`：纯黑 alpha=1 剪影、无属性），整体进专属层 `PaimonShadow`(slot 8)；主相机 cullingMask 剔除该层（当前 -257）
  2. `PaimonDropShadowController`（GIC.Pet，挂 Paimon 根，Inspector 全中文）运行时自建全套管线：`_ShadowCam`（主相机子物体、逐帧同姿同投影、只渲 PaimonShadow 层、`enabled=false` 由 LateUpdate 手动 `Render()` 保时序）→ 剪影 RT（高 512、宽随 aspect 换算、16bit 深度）→ `Hidden/GIC/PaimonShadowBlur` 双向 17-tap 高斯 Blit ×2 轮（每轮半径=总半径×0.66，两轮方差相加 σ≈0.42×总半径）→ `_ShadowComposite` 全屏 Quad（主相机近裁面前逐帧贴合视锥，`Hidden/GIC/PaimonShadowComposite`，Queue=Background+10 最先画，本体 Opaque 后画自然盖住重叠区；UV 平移=屏幕像素偏移，界外 alpha 清零防 Clamp 寻址 streak）
  3. 零灯光、零阴影贴图、零后处理——与 §5.9"桌宠完全无光照"定案兼容；半透明像素经 DWM 逐像素 alpha 直接合成到桌面
- **参数**（控制器 Inspector 中文，逐帧应用即调即见）：阴影颜色（Alpha=浓度，默认 0.6）、阴影偏移像素（x 右正/y 上正，默认 (0,-24) 下垂=光源在上方）、模糊半径像素（默认 14，RT texel）、阴影贴图高度（默认 512）、启用开关。防线：Awake 强制影子壳进层 + 主相机剔除，场景接线漂移也能工作
- **太不明显二次修复（2026-08-24 晚，双根因）**：
  1. **合成 Pass 的 Blend 把 alpha 平方了**——`Blend SrcAlpha OneMinusSrcAlpha` 单写法对 alpha 通道同样生效，缓冲区 A_out=A_src×A_src（dst 起始为 0），浓度 0.45 实际写入 swapchain 只剩 0.2，DWM 合成后影子淡掉一半以上。修复=`Blend SrcAlpha OneMinusSrcAlpha, One Zero`（alpha 直写；黑影在 DWM 直通/预乘两种解释下视觉一致）
  2. **窗口=模型包围盒没有影子落脚空间**——偏移 (0,-16) 把影子推出窗口底边被裁，脚下阴影全无，只剩两侧模糊光晕。修复=窗口留边距：窗口逻辑 480×720→550×825（×1.1458，2:3 比例不变）+ 主相机 FOV 40→45.27（同倍率放大视野）——**派蒙屏幕像素尺寸/构图完全不变**（窗口与视野同倍率扩大），四周留出 ~55-70 逻辑像素边距供影子落脚；启动参数（PetProcessLauncher/PetEditorAutoLauncher `-screen-width/-height`）同步 550×825。副作用：停靠右下角时派蒙脚下离屏幕底边略高（≈边距×缩放）
  3. 参数加强：浓度 0.45→0.6、偏移 (0,-16)→(0,-24)、模糊 12→14（配合边距加大）
  4. **影子呈"多个格子"= 模糊欠采样平台条带（三次修复，2026-08-24）**——旧 9-tap 高斯 tap 间距=radius/4（≈3.5 texel），硬边剪影卷积出平台状阶梯：相邻 tap 之间 alpha 恒定、tap 位置瞬间跳变（最大一档 23%），轮廓呈多层格子/贝壳纹。修复=Blur shader 重写 **17-tap**（间距 radius/8，权重 exp(-k²/32) 归一化、形状与半径无关→任意半径采样密度恒定）+ 控制器 **H+V 跑两轮**（每轮半径=总半径×0.66，两轮方差相加=旧单轮 σ≈0.42×总半径——模糊量/观感不变，第二轮把第一轮残余台阶再抹平）。已排除的非根因：8-bit alpha 量化（154 级/44px 足够平滑）、RT 双线性放大、Composite 采样
- **踩坑（2026-08-24 构建实测）**：内部 shader（Blur/Composite）**不能用 `Shader.Find("Hidden/...")` 运行时装**——构建期无场景/资产引用会被当未引用裁剪致 null（Awake `ArgumentNullException: shader`，编辑器能跑但打包版没影子）。正解=序列化 `Material` 引用（`PaimonShadowBlur.mat`/`PaimonShadowComposite.mat`，构建期必收录），运行时 `new Material(模板)` 克隆后改参
- **已知取舍**：眨眼/情绪 morph 权重存在各 SMR 组件上**不共享**——影子壳不眨眼不皱眉（morph 差异仅眼部几个像素，12px 高斯下不可见）；骨骼/蒙皮共享，姿势同步不受影响
- **遗留增强**：阴影方向/浓度当前为静态参数；将来可在 PetWindowController 按停靠屏幕边缘动态调偏移（如贴右边缘时影子偏左，对齐 DWM 光源语义）；拖拽物理落地后可接"拎起时影子变淡缩小"的距离反馈
