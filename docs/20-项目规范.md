> 本文档随 git 提交（人类协作者与 AI 均可读）；记忆（CODELY.md）只记事实与决策背景，规则本体以本文为准。
> 分类去向：操作工作流→skill、技术陷阱→docs/14、设计决策→各设计文档、**通用规则→本文**（四类不重复）。

## 1. 编码规范

### 1.1 命名

- **命名空间固定为模块根**（GIC.Framework / GIC.Data / GIC.UI / GIC.Battle / GIC.Tool / GIC.Pet / GIC.Editor），目录仅做物理分组，不逐级嵌套 namespace
- **标识符统一用英文**（2026-08-29 用户拍板"统一用英文，除非不得不用中文"）：类名/方法/属性/字段/事件/参数/局部变量全部英文；Unity 生命周期方法（Awake/Update/OnDestroy）与 override 天然英文
- **Inspector 显示中文**：序列化字段统一英文名 + `[InspectorName("中文名")]`（Inspector 面板显示中文，代码标识符保持英文）+ [Header] 中文分组 + [Tooltip] 中文说明（可读性，2026-08-10/29 拍板）
- 线上协议 DTO 的序列化成员（JSON 键，如 role/content/tool_calls）保持英文——序列化按字段名
- 外部库强约束的签名（如 TMP_InputField 的 override）按库要求
- **角色属性命名参考 HP 不加 Max 前缀**：baseEnergy 既是基础值也是上限（当前值运行时管理），与 baseHP 同构
- **目录名一律英文**（防编码问题，2026-08-10）
- 字段改名必挂 `[FormerlySerializedAs("旧名")]`（场景/Prefab 引用存活），验证链=编译→FindProperty 断言→保存→重开二次断言（详见 docs/14 §程序化 UI/序列化相关条目）；**CoopScreen.unity 仍存 5 处旧序列化键——必留勿删（删则丢数据，2026-09-02 实证）**
- **统一前缀 `_` 私有字段**（英文 camelCase，如 _history、_waitingFirstChunk）
- 存量中文标识符已全部迁移至英文（2026-08-29 完成，编译零错误）；序列化字段=英文名+[InspectorName("中文名")]（FormerlySerializedAs 迁移完成后已删除）；唯一保留中文= PetPrefs pet.json DTO 字段（JsonUtility 键，存档可丢）+ Data 层枚举成员（领域词汇表待后续评估）

### 1.2 架构

- **不用 asmdef**（2026-08-01 拍板）：单一程序集 + 命名空间隔离。勿主动推进拆分（曾尝试，循环依赖硬拆成本大于收益）
- 依赖方向：UI→Framework/Data，Battle→Framework/Data，Editor→全部；禁止反向
- **战斗逻辑不走 EventBus**（回合制严格串行；EventBusHub/LocalEventBus 仅 UI/网络层）
- **战斗系统 StS 风格**：ActionQueue（协程串行）+ DamagePipeline（同步，Phase hooks），详见 docs/18
- 祈愿三层架构：PlanShot() 预计算业务 → PlayStepsCoroutine() 纯动画播放零业务调用（表现层不调 WishManager）
- 联机分层：PlayerManager=纯数据层 / RoomManager=流程层（单向依赖 Room→Player）；网络 Handler 常驻订阅不退订（CanHandle 守卫）；**RoomManager.Cleanup 仅作应用关闭钩子，勿在断线时调用**（曾致同会话重连名册失联）

### 1.3 Unity 序列化铁律（血泪教训汇总，细节+实证见 docs/14）

- **场景值恒优先于代码默认值**：改 Inspector 暴露字段的代码默认值，必须同步写场景/Prefab 序列化值（SerializedObject.FindProperty 写入），否则构建后行为不变
- **场景 YAML 中文键序列化为 \uXXXX 转义**：文本检索中文键名必零命中——搜转义形式或按 fileID
- **UI 属性（字体大小/颜色/布局）在编辑器改 Prefab/场景，不在代码运行时设置**（`tmp.fontSize = X` 类禁止，2026-08-10 拍板；例外=程序化构建的 UI 无 prefab 可改，构建时设值是唯一路径）
- git 回滚已打开场景后必须 OpenScene 强制重载（磁盘还原 ≠ 编辑器内存态还原）
- **跨场景预设含场景级 override 子物体的面板必须 Object.Instantiate(场景实例) 深拷贝**；静态预设实例保存为未激活时，运行时使用前必须显式 SetActive(true)（P10 三次返工教训）

### 1.4 资产与资源

- 判定资产引用禁止文本 GUID 检索（Tuanjie 加密资产 meta 是密文），用 unity_asset get_info / AssetDatabase 查真实 GUID
- 小 UI 贴图入 Sprite Atlas（6 个，Assets/SpriteAtlases/），大贴图不入
- BGM 用 Streaming loadType；Release 包抑制 Debug.Log（GICLog.Info 编译期删除）
- Pet 运行时代码**故意**用 Debug.Log 而非 GICLog.Info（桌宠是 Development 构建，Player.log 诊断方法论依赖；详见 docs/19）

### 1.5 编辑器安全红线（曾卡死主线程 330s）

execute_csharp_script / 桥脚本禁止：
- LoadAssetAtPath 整 prefab 后递归遍历层级
- Play 模式下跑重反射诊断
- GetWindow 泛型参数传 null
- PrefabUtility.Set/GetPropertyModifications 往返清理（静默丢引用 mod——用 SerializedObject.FindProperty().objectReferenceValue=xxx + ApplyModifiedPropertiesWithoutUndo()）

### 1.6 存档与数据入口

- 卡牌库存一律走 PlayerSaveData.AddOwnedUnit/AddOwnedItem（自动重建缓存）；货币/物品走 GetItemCount/AddItemCount/TryConsumeItem——不直接 ownedUnits.Add
- 场景跳转仅三条路径：LoadSceneWithConfig（Single）/ PreloadScene+Activate（Additive）/ GoBack；弹窗走 PopupManager.ShowToast/ShowModalPopup，不走 GameScene
- 桌宠数据走独立 pet.json（双进程铁律：桌宠进程永不读写主存档）
- LLM 密钥：玩家自输 key，AES 加密存档（明文永不落盘、不进日志/异常栈，2026-08-28 商业边界拍板）

### 1.7 文件位置与目录归属（新文件放哪的唯一决策表，2026-09-01 建）

完整目录结构与模块职责见 docs/17 §2；本节只回答"新文件放哪"。判定按顺序走：

1. **先判运行时还是编辑器**：含 `using UnityEditor` / 仅编辑器使用 → `_Scripts/Editor/`（通用工具→`Editor/Tool/`、URP 相关→`Editor/URPTools/`、临时验证脚本→`Editor/DevTest/`，**DevTest 不入包**）
2. **再判归属层**（运行时，见 docs/17 §2 表）：
   - 纯数据/配置类（无游戏行为逻辑）→ `Data/{域}/`
   - 被多模块复用的框架服务（DI/事件/资源/音频/存档/输入/网络/池/渲染）→ `Framework/{域}/`
   - 界面/弹窗/界面专属组件 → `UI/`（每屏建子目录 `UI/Screen/{屏名}/`，跨屏共用→`UI/Common/`）
   - 战棋局内专属 → `Battle/{Unit|Card|Skill|Tile|Buff}/`
   - 跨模块通用 UI 组件/扩展方法 → `Tool/Component/`
   - 桌宠专属 → `Pet/`（依赖只出不进，见 §1.2）
3. **拿不准时跟随同域惯例**：先看最近的同类文件在哪个目录；新增顶层模块/顶层目录=结构变化，需用户拍板后才建
4. **文件纪律**：MonoBehaviour/ScriptableObject 的文件名=类名（Unity 反序列化硬要求）；一文件一类（partial 拆分大文件除外）；namespace 固定模块根（§1.1），不因新建目录改 namespace
5. **非脚本资产归属**：场景→`Scenes/`；Config SO→`Resources/Configs/`；小 UI 图→`SpriteAtlases/`；大贴图/立绘→`Art/`（Addressables 地址约定见 docs/17 §5）；角色语音→`Resources/Audios/Voices/{UnitName}/`；shader→参照既有同域 shader 位置

## 2. UI 与本地化规范

- **UI 文本一律 TextCombiner 组件**，禁止 `tmp.text = GetLocalizedString()` 直赋（语言切换不刷新）。例外：TMP_InputField 的 placeholder（InputField 覆写 text，同步解析直赋——InputPopupDialog 同款）；LLM 动态回复内容（非本地化范畴）
- 程序化 UI 挂 TextCombiner 时 **TMP 必须与 Combiner 同物体**（Awake 只 GetComponent 同物体，不查子级）
- 本地化表 .asset **禁止手编 YAML**（Id 撞号→整表解析失败→五语言全空壳，2026-08-28 事故）；一律走 gic-localization skill 的 API 路径（AddKey(key, id) 带参）
- **UIText Id 统一分段编号**（1000通用/2000联机/3000稀有度/4000区域/5000颜色/6000地图/7000元素/8000移动/9000设置/10000祈愿）；新键=域内最大序号+1；存量大数键不动
- DontDestroyOnLoad 实例上的 Camera 必须 tag=Untagged（Camera.main 抢占事故，运行时加 CompareTag 安全带）
- 程序化新建 RectTransform 必须显式设 anchor（默认中心锚）；项目约定=左下锚 + anchoredPosition 绝对坐标
- **技能图标=裸图案 + 底图分离**（2026-09-10 拍板）：技能图标 PNG 一律透明底裸图案（游戏提取/Upscayl 256 流程见 gic-gi-extract skill），深色圆形底板由 Skill.prefab 的 Badge 子级统一渲染（badge.png，#253343）——**勿再把底板烘焙进图标文件**；UnitConfig 技能 icon 字段只接裸图案 sprite
- **技能图标元素染色 + 颜色配置化**（2026-09-10 拍板）：SkillIconView 按 unitData.selfElement 运行时乘色（白线稿→元素色，不改原图）；**元素颜色数值只存配置文件** `Configs/ElementFactionConfig.asset`（原 ElementColor.cs 已退役删除）；静态访问走 `ElementFactionConfig.Instance.GetElementColor()`（StarVisualConfig 同款单例模式，ConfigManager 注入+Resources 兜底）；ElementFactionIconConfig 已更名 ElementFactionConfig（预留后续元素/势力类配置扩容）
- **武器通用战技图标**（2026-09-10 拍板）：各武器类型角色的通用战技图标固定为 `Assets/Resources/UI/Skills/` 六张——`claymore_skill`(双手剑)=Skill_A_04 / `sword_skill`(单手剑)=Skill_A_01 / `polearm_skill`(长枪)=Skill_A_03 / `gauntlet_skill`(臂铠)=Skill_A_00 / `catalyst_skill`(法器)=Skill_A_Catalyst_MD / `bow`(弓)=Skill_A_02（安柏专用已改接 amber_double_shot，bow 回归纯通用）；Gun 暂无对应图标（原神无此武器，需求出现时再定）
- **通用移动类图标**（2026-09-10 拍板）：`teleport.png`=通用瞬移移动（源 Skill_S_Chasca_03）、`walk.png`=通用行走、`fly.png`=通用飞行（2026-09-10 换源=UI_Talent_S_Liuyun_07 闲云固有天赋 Crane Form 全队滑翔速度+15%，用户 AI 处理移除右下角提升双箭头，1024 透明底高质量降回 256 落地，【目检】用户验证通过）；**项目技能为原创设计，图标按图案语义自由选用、不强求与原神技能一一对应**（用户拍板），全量素材库备查=webrefs all_skills_256/all_talents_256/all_monsterskills_256
- **通用图标补充**（2026-09-10）：`amphibious.png`=通用两栖移动（源 Skill_S_Yelan_01，walk 式共享模式）、`constellation.png`=通用命座（用户 AI 生成版换源落地，中心闪光提亮修正）、`detail.png`=通用详情（亮度→alpha 管线处理；"详情"技能本身未建——未来接线时直接用 Assets/Resources/UI/Skills/detail.png 勿再处理）
- **图标素材一律取官方**（2026-09-09 拍板）：任何技能/角色图标需求先走本地游戏提取（gic-gi-extract skill；Fandom/网络图库抓取链已弃用）；AI 生成仅限官方无对应的项目自创技能且需用户点头
- **UI 素材分辨率基准**（2026-09-03 普查，186 PNG）：按钮/弹窗素材 500~512px 一档，勿超标也勿低于显示尺寸；Canvas 参考分辨率 2560×1440（仅 PaimonPet 960×540）；纹理内存大头=Art/Wish 470MB（8 张 4096px）/Art/PositionBack 172MB/UI/Cards 107MB——内存优化议题优先看这三处，不是弹窗族

## 3. 文档规范（2026-08-26 拍板）

- 文档只记**"现在是什么 + 为什么"**（现状定案/参数/资产位置/决策记录）；过程流水与已废弃路线排查细节移交 git 历史
- 新条目改对应小节，**不往顶部堆叠**（迁移式文档几轮后必成不可信流水账）
- **可信度分级标注**：【实证】=有实测/源码核验 /【目检】=用户确认过 / 未标注=当前实现记录
- 被推翻的旧结论不删原文，原地加"❌已推翻 + 正确结论"（防后人翻 git 旧版再信）
- 通用规则写总设计文档（本文或各系统总文档），角色文档只记该角色具体数据
- 文档间不重复：工作流→skill、陷阱→docs/14、决策→设计文档、通用规则→本文

## 4. 术语表（写文档/讨论严格区分）

| 术语 | 含义 | 反义/易混 |
|------|------|-----------|
| **战场** | 局内网格战棋地图（docs/03） | 勿与"大地图"混用 |
| **大地图** | 局外导航地图（MapScreen，docs/13） | |
| **消散** | 玩家战败时该玩家所有单位真正删除不可恢复 | 勿用于 Buff 过期 |
| **放逐** | 转移到另一维度，仍可被特定技能召回 | |
| **消失** | Buff/造物过期 | 勿用"消散" |
| **元能** | 元素能量简称（属性名 Energy） | |
| **战技/爆发/移速/火伤/体力** | 元素战技/元素爆发/移动速度/火元素伤害/原粹树脂 的既定简写 | 全称简写转换见 gic-localization skill |
| **技能参数百分比** | 非 Fixed 基准的值是百分比（"伤害 40 BasedOnAttack"=40%×攻击力） | 勿当固定值 |

## 5. 角色文档规范（docs/units/{势力}/）

- 采用默认值的字段只写 `auto`（UnitConfig.asset 对应填 -64 哨兵），只有非默认值才写显式数字；默认值参考 UnitConfig.GetEffective*() 方法
- 角色数据源头是文档：AI 读取 docs/units/{势力}/{角色名}.md 后同步 enum+asset+本地化（流程见 gic-new-unit skill）；角色文档按势力分目录存放（蒙德/璃月/稻妻…，目录名与 docs/07-势力机制/ 命名一致），转正前草稿放 docs/units/草稿.md
- 角色语音：Assets/Resources/Audios/Voices/{UnitName}/ 按文件名前缀，工具自动加载（不独立 ScriptableObject）
