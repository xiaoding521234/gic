# 16 - 代码优化计划

> 2026-08-14 制定。目标：**不改游戏行为**的前提下系统性清理技术债，让后续开发（尤其战斗系统）不用反复返工。
> 执行方式：分批次，**每次对话只做一个批次**；每批次以「编译零错误 + 用户自测通过 + git commit」收尾，再进入下一批。

## 原则

1. **不改行为**：纯结构优化。不新增功能、不改数值、不改 UI 表现（明示的 bug 修复除外）。
2. **每批独立验收**：`start_compilation_pipeline` 后 console 零错误零警告（新增），用户手动测试涉及的界面流程。
3. **不使用 asmdef**（2026-08-01 决定）：保持单一程序集 + 命名空间隔离。
4. **战斗核心不在本计划**：ActionQueue+DamagePipeline、Buff 体系、技能结算属新功能开发，落地时另行设计；本计划只做不依赖战斗核心的部分。
5. **遵循既有模式**：DI 用 [Component]/[Autowired]、UI 本地化用 TextCombiner、客户端→Host 请求事件 Immediate=true 等（见项目记忆与 skills）。

横切问题：
- **Debug.Log 172 处**，Release 仅靠 GameScene 全局 `filterLogType` 抑制——字符串插值在 IL2CPP 下仍会执行，存在真实性能损耗。
- **三种单例取法并存**：`Singleton<Wargame>`（唯一使用者）、`Wargame.Instance`（80 处）、`GameScene.Instance` / `EventBusHub.Instance`（MonoBehaviour 静态）。
- **`IS_DELETION_TEST_MODE = true`**（SaveManager）——删档开关默认开启，上线忘改即清空玩家存档，高危。
- 亮点（无需动）：DI 容器、Wish 三层分离（FlowController/Manager/表现层）、PlayerManager 的 Cleanup 退订范例、SkillFactory 反射注册。

## 执行约定

1. 每批次开始：重读本计划对应条目与相关项目记忆/skill；结束：在本文档勾选完成状态
2. 过程：读码 → 小步修改 → `start_compilation_pipeline` → `unity_console get` 清零
3. 收尾：用户自测涉及流程 → 确认后 git commit（沿用 `refactor:`/`fix:` 前缀中文描述风格）
4. 发现本计划未覆盖的新问题：小则顺手修并在 commit 说明，大则记入本文档「新增发现」节，不扩当前批次范围
