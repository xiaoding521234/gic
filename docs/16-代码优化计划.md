# 16 - 代码优化计划

> 2026-08-14 制定。目标：**不改游戏行为**的前提下系统性清理技术债，让后续开发（尤其战斗系统）不用反复返工。
> 执行方式：分批次，**每次对话只做一个批次**；每批次以「编译零错误 + 用户自测通过 + git commit」收尾，再进入下一批。

## 原则

1. **不改行为**：纯结构优化。不新增功能、不改数值、不改 UI 表现（明示的 bug 修复除外）。
2. **每批独立验收**：`start_compilation_pipeline` 后 console 零错误零警告（新增），用户手动测试涉及的界面流程。
3. **不使用 asmdef**（2026-08-01 决定）：保持单一程序集 + 命名空间隔离。
4. **战斗核心不在本计划**：ActionQueue+DamagePipeline、Buff 体系、技能结算属新功能开发，落地时另行设计；本计划只做不依赖战斗核心的部分。
5. **遵循既有模式**：DI 用 [Component]/[Autowired]、UI 本地化用 TextCombiner、客户端→Host 请求事件 Immediate=true 等（见项目记忆与 skills）。

横切问题：
