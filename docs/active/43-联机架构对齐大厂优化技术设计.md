## 1. 现状核实（2026-10-13 代码级；含拍板轮两处勘正依据）

- **掉线处置 v1**（docs/41 §5.5）：客户端掉线→`RoomManager.HandleServerDisconnect`=名册移除+`RemovePlayerEvent`，其单位照常吃超时自动 Pass；Host 掉线→客户端 `MyNetworkManager.OnClientDisconnect` 判战斗场景直接回大厅+`Coop_HostDisconnected` toast。
- **ack 期望=活 lambda 动态收缩**：`TurnFlowController.ExpectedAckerCount`（`Func<int>`=`() => 1 + MirrorBattleTransport.RemoteClientCount()`，L418）每次判 ack 时求值——客户端掉线后连接离开 `NetworkServer.connections`，期望自动 -1，不会「每片吃 15s 超时」（设计稿初版假设经核验不成立，勘正记录在此；15s 超时快进兜底仍在=TurnResolver 消费 `BattleMetrics.SegmentAckTimeoutSeconds`）。
- **快照=选择阶段头全量**（`BattleSnapshot`：units+resources+手牌条目 HandCard；`SnapshotMessage.selectLimitSeconds` 已带）；`BattleSnapshot.cs` 注释明文重连语义：「**断线重连 = 重发快照 + 跳过演算**」——重连地基已在，缺的是协议/名册/客户端侧整链（本稿 §3.2 勘正其形态细节）。
- **掉线客户端必回大厅**（拍板轮新核验）：`MyNetworkManager.OnClientDisconnect` 判「非服务器+当前场景=BattleScreen」直接 `MainHall.Load()`——战斗场景卸载、本地名册 Clear。**推论：重连恢复链必须重建棋盘（定向重发 BattleStart 含地图），仅发快照零效果**——客户端唯一建盘入口=`BattlePlayer.OnBattleStart`（board.Build+逐单位 CreateView）；`OnSnapshot` 只对**已存在**的 view 同步权威态（TryGetValue 全 miss=什么都不做）。
- **快照按需现场构建**（拍板轮新核验）：`_sim.TakeSnapshot(turnNumber)` 在 BeginSelectPhase/StartBattle 现调（非缓存）——**任意时刻可取**，host 在片间 ack 等待间隙取=一致态（「当下快照+后续片无缝续播」的技术地基）。
- **`BattleMessageType.Pause/Resume` = B1 占位零消费**（全库无引用，重连暂停语义可直接启用）。
- **无自动重连**：`MyNetworkManager.JoinRoom(ip, port)` 手动；无重连循环、无重连身份认领协议。
- **无定向发送原语（战斗通道）**：`IBattleTransport.HostSend`=广播式（host 本机直投+逐远端全发），无「发到指定连接」能力；房间通道已有 `EventBusHub.PublishToPlayer`（HandleServerConnect 在用）——定向非代码库新概念，战斗专用通道补齐同款即可。

## 2. 核心工程发现：定向发送原语（三个议题的共同地基）

**重连恢复 / 观战晚入 / 信息隐藏裁剪**三议题共同依赖「Host→单连接定向发送」：

- `IBattleTransport` 增 `HostSendTo(targetSenderId, type, message)`（senderId=RegisterHostHandler 携带的连接标识，与 ack 计数同一口径）；MirrorBattleTransport 落地=`conn.Send`（本机 host 视图=target=="local" 直投）；LocalBattleTransport=回环直调。
- **信息隐藏**=快照序列化按接收方裁剪（HandCard 条目只发本人）；**观战晚入**=定向补发 BattleStart+当下快照；**重连**=定向重发 BattleStart+当下快照（见 §3.2）。三者共享同一原语与「按 receiver 变体序列化」骨架。
- 前置改动小：传输层一处接口+两实现，HostSend 广播语义保持不变。

## 3. 议题一：断线重连（P0；拍板=A token 认领 + 接续当下 + 名册保留 + AI 代打）

### 3.1 身份认领（拍板=A 重连 token）

- **A 案（拍板）**：host 在注册完成时给每人发一枚 `RoomToken`（int 随机即可，LAN 无防猜测压力；随 `SetSelfPlayerEvent` 下发或并入注册回执），客户端存**进程内存**（断线重连=同进程）；重连时随首条消息带上。B 玩家名映射（同名撞车不可靠）已否决；C 不认领（重连=新玩家，战局中无意义）已否决。
- **注册时序（拍板轮勘正——初稿遗漏的实现硬伤）**：Mirror `OnServerConnect`→`HandleServerConnect` **无条件** `RegisterPlayer(conn.connectionId)`，发生在 token 到达**之前**——不处理=同一人新旧条目并存（开局门/颜色/ack 全乱）。**正解=注册延迟**：连接先挂起「待认领」，等客户端首条消息再定身份——**复用既有链路最小改动**：客户端连接成功即发 `SetPlayerNameRequestEvent`（OnClientConnect 现行即发链），给它加 `RoomToken` 字段；host 收到时先查 token 命中→**认领旧条目**（connectionId 字段更新+清掉线标记），未带 token/查无→按新玩家注册（现状流程）；超时守卫（如 3s 无消息）兜底按新玩家注册「玩家N」。
- **名册改动**：掉线玩家条目**保留并标记掉线**；`PlayerInfo` 持 connectionId 字段（主键仍是 playerId），`PlayerManager` 加 token→playerId 映射。

### 3.2 恢复语义（拍板=改判「接续当下」；初稿「重发回合头快照+跳过演算」经核验证伪）

初稿方案两处硬伤（代码级证伪，勘正记录）：

1. **只发快照恢复不了**：掉线端 v1 必回大厅（§1），场景已卸载——`OnSnapshot` 对空 `_views` 全 miss=零效果；唯一建盘入口=`OnBattleStart`（含地图）。
2. **回合头快照与新片错位**：回合头=演算前状态；「吸收后续到达的新片」时片内命令假设此前片已应用（单位先移后打，重连端从旧位置播攻击片=世界态错位）。

**正解=BattleStart（地图+当下快照）接续链**——七步时序：

1. 客户端 `JoinRoom(ip,port)` 重连 → host `OnServerConnect` 挂起待认领（§3.1 延迟注册）；
2. 客户端连接成功即发 `SetPlayerNameRequestEvent{name, RoomToken}`（首条消息，复用现行即发链）；
3. host token 命中→认领（条目 connectionId 更新+清掉线标记+**停 AI 代打脑** §3.4）→广播 `UpdatePlayerInfoEvent`（房间行刷「已回归」）；
4. host 判战斗中→经**房间通道**定向发恢复事件（专用 `ReconnectResumeEvent`：map 名+名册——驱动客户端转场，`StartGameTransition` 本端版复用）；
5. 客户端转场进 BattleScreen→`CreateClient` 装配→`RegisterClientHandler`→早到队列冲刷（≤64 保序既有机制兜底；战斗消息按 Mirror 连接序到达，片量随播随至不会堆积）；
6. host（**片间一致态**）定向发 **`BattleStartMessage{map, initialSnapshot=TakeSnapshot(当下)}`**——客户端建盘即当下状态；选择阶段中再补 `SnapshotMessage{selectLimitSeconds=剩余秒}`——**host 侧 `SelectRemainingSeconds` 现成 float，勿发满值**（否则重连端倒数从满值重启、host 早已超时 Pass，玩家操作被静默丢）；
7. 客户端建盘完成→回 `ClientBattleReadyEvent`（**复用既有开局握手**）→host 把该连接计入 ack 期望。

**ack 期望升级**：`ExpectedAckerCount` 从 `1+RemoteClientCount()` 改 `1+已就绪连接数`（ready 连接集合）——初次开局天然成立（决策六十五：host 收齐 ClientBattleReadyEvent 才广播开局）；重连端转场加载期（场景加载 2~3s）不计入，**防 15s 段超时快进误伤**（加载期其他客户端照常播片）。

**恢复效果**：重连端从**当下状态**续播——只错过断线期间的已播历史（对在场者零影响），后续片实时续看；选择阶段中重连=完美恢复（重入倒数、继续上交）。初稿「跳过演算尾巴」口径就此升级为「**接续当下**」。

- A' 暂停等待+历史片重推（观感完全无损但复杂度高，含早到队列容量评估）：挂账增强，v1 不做（`Pause/Resume` 占位保留备用）。

### 3.3 客户端重连循环

- v1（拍板）：**手动重进+自动认领**——掉线回大厅 toast 附「重新加入」按钮（ip/port 记忆=discovery 期既有），连上后带 token 自动认领，战斗中则走 §3.2 接续链；房间阶段重进=普通加房（名册已移除）。
- v2（挂账）：自动重连循环（N 秒退避×上限）——LAN 断网场景收益有限，复杂度不小，后置。

### 3.4 战斗中掉线的名册/单位处置 + AI 临时代打（拍板）

- **名册**：战斗中掉线=条目保留+标记掉线+单位照常在场→重连恢复操控；只有战终/踢出才移除。房间（非战斗）阶段掉线维持现状即移除（重进=普通加房）。
- **AI 临时代打（用户拍板「掉线的玩家，临时用AI玩家顶替」）**：掉线标记的同时 host 侧为该 playerId 启配额脑（`PlayerQuotaBrain`，默认难度/人格=**棋圣·经济家**——AIPlayerConfig 默认档）——每回合正常提交行动，**超时自动 Pass 降级为异常兜底**（不再每回合干等 7~30s 超时，战局节奏不受掉线拖累）；掉线期间即时行动通道缺失=可接受（回合决策覆盖主要行动）。重连认领=停代打脑、恢复真人操控；**AI 已替交的当前回合不撤销**（toast「AI 已代打本回合」），下一回合起恢复。
- 接线：`RoomManager` 战斗期掉线改「标记+广播掉线事件」（房间通道），`BattleScreen` host 侧订阅→启/停代打脑；消费既有 AI 批基础设施（配额脑/AIPlayerConfig/PersonaPack）零新建脑；对手画像采集（OpponentProfiler）照常把 AI 行动记账=预期。
- **主动退房 vs 掉线不区分**（拍板=最简案）：战斗中一律保留+代打至战终——现状「退出房间」=直接断线、Mirror 断开无原因位，**不建显式 LeaveRoom 协议**；房间阶段退房维持即移除。
- N4 连打衔接：战后房间保持时掉线玩家跨局仍以代打身份参战（开局门按 AI 恒就绪口径），重连随时接管。

### 3.5 已知边界（明示）

- **host 进程死亡=战局真终局**：本重连方案只覆盖客户端掉线（host 进程活着——含 host 侧网络抖动：server 仍在 host 机上，客户端重连即恢复）；host 进程死亡客户端回大厅现状维持。
- **token=进程内存**：客户端进程重启则认领失效（条目继续 AI 代打至战终；重进=观战或下一局普通身份）。
- 重连错过本回合 `TurnPlanMessage`=执行预览行本回合空（下回合自愈）。

## 4. 议题二：信息隐藏/防透视（P0；拍板=随 N1 立即做）

- 快照与 BattleStart 的 `PlayerResourceState.handCards` **按接收方裁剪**：只发本人条目，他人保留 `handCardCount`（字段已在，HUD 本就只显示自己的——**纯协议收窄零行为变化**）。
- 落点：MirrorBattleTransport 的 per-connection 变体序列化（依赖 §2 定向原语骨架）；观战端（§5）无归属人=全裁剪。
- **本地模式豁免**：裁剪只做在 MirrorBattleTransport 层；**LocalBattleTransport（本地双开调试）不裁剪**——host 本机 HUD 要看双方手牌，本地模式裁剪=破坏调试视图。
- 收益：LAN 抓包/镜像调试器透视手牌被协议级杜绝；对齐大厂「服务端只发可见信息」。
- 顺手项（拍板=SubmitResult 轻量下行随 N1）：`SubmitAction` 提交回执——已受理/被拒（回合号不符）/迟到丢弃（docs/11 既有挂账，被拒/迟到客户端目前零感知）。

## 5. 议题三：观战端（P1；拍板=v1 只做战败转观战）

- **战败转观战**：docs/02「战败玩家进入观战模式」既有玩法语义接 LAN——**局内切换无转场**（玩家已在战斗场景，仅 HUD 切观战态：隐藏手牌/技能盘/提交通道，保留战场表现与头顶条）；战败≠踢出，转观战位收快照+片流。主动观战位（房间界面「加入观战」）后置。
- 晚入观战=§3.2 接续链同款（BattleStart+当下快照定向补发——重连的特例化）。
- **ack 处置（拍板轮实现建议）**：观战端**自动回 ack（哑等）**——不改 `ExpectedAckerCount` 口径（RemoteClientCount 含观战连接，自动 ack 天然满足；就绪连接集合语义下观战端入座即发就绪握手）；比显式排除实现更小、未来加连接类型零维护。
- 观战端快照=全裁剪（无归属人）；传输=单向只收（快照+片流），无提交通道。

## 6. 议题四：战后房间保持/连打（P1；拍板=入路线图）

- v1=战后回大厅 `CoopScreen.OnShow` 统一拆线解散。保持方案：**不拆线**——名册保留、房间 UI 直接可再开（`StartBattleEvent` 广播→各端统一转场链全部复用；「连接贯穿战斗不拆线」本就是 v1 既有事实，改动量集中在解散逻辑开关+再开局校验门复用）。
- **再开局就绪态=保持直开**（拍板）：`ResetBattleExchange` 清卡组/握手台账但不清名册 isReady——连打时全员保持就绪、host 单权直开（开局门校验链原样复用）；「全员再来一局确认门」不建（备拍板案作废）。
- **掉线玩家跨局=代打身份延续**（§3.4）：房间行显示代打态（UI 细节随批）。
- 大厂对照=广场服常驻、战斗服按局重建——`BattleSession` 生命周期已独立（ReplaceHandler 替换语义，再开局不叠加），保持房间=自然延伸。

## 7. 议题五：Host 校验层收编（P2；docs/11 既有挂账）

三项既有挂账收编进联机线：①0 步移动协议拦截（`moveMagnitude=0` UI 不可达但协议可交）；②斜向上交归一主轴或落空（方向纪律防作弊层）；③提交回执（已并入 §4 随 N1）。定位=防作弊硬化，LAN 信任环境下优先级低于重连/信息隐藏。

## 8. 议题六：Replay/回归 harness（P2/P3；docs/11 已立项件）

- 立项原文（docs/11）：Host 演算零 RNG=「初始配置+人类行动序列」确定性复现全部命令流；落地=TurnResolver headless 化+ActionData 录制落盘+离线回归断言。
- 大厂对照=帧同步录像回放/desync 调试底座。**收益排序对 GIC 反转**：先做录制+离线断言=AI 批/平衡批的回归安全网（观察局 harness 已在用同族技术，docs/14 §115），联机 desync 调试底座为次级收益。

## 9. 议题七：战斗组合根域内化（拍板=与 N1 合批）

- 现状=`BattleScreen`（UI 层）兼任组合根（三形态装配/Sim/Flow/AI 脑挂载/HUD Bind）。

## 10. 议题八：单人局浏览 UI 自动暂停（P0 独立小批 N0；用户拍板定夺方案）

> 用户拍板（2026-10-13）：「在只有1个真人玩家时，开布局编辑，打开设置，查看卡牌详情时等，自动暂停」——取代 docs/11 旧挂账的「禁用入口/维持现状」两案（docs/18 决策六十七 #11）。

- **判据（单源）**：需要人工提交行动的玩家数==1——`Roster.Count(!IsAI)`（本地房间开局与 LAN 同构）−沙盒空座（`sim.SandboxAutoPassPlayerId` 即时自动 Pass 无人操作）；Roster 空缺（调试直开）按 2 计。推演：本地单人 vs AI=1 ✅暂停；LAN 单真人+AI=1 ✅；试招沙盒（P1 真人+木桩）=2−1=1 ✅（试招无时限压力）；本地调试双开 P1/P2=2 ❌不暂停；LAN 多真人≥2 ❌不暂停。
- **入口（登记制）**：布局编辑（既有 SelectTimerPaused 通道）/设置面板/卡牌详情（手牌点开+单位详情）/同类覆盖型浏览 UI（「等」——实施批按「打开即覆盖战斗交互的浏览型弹层」枚举归类）；**暂停请求=打开期间持续保持**（布尔聚合，跨阶段边界自洽：设置开着进入选择阶段=倒计时冻结不偷跑）。
- **机制**：host 侧 `SelectTimerPaused` 真停（单人局唯一真人=host 本人，冻结只影响 AI=无真人受损）；Resolving 期无倒计时不适用（段照播；Resolving 期暂停=启用 `Pause/Resume` 占位，挂账增强）。
- **多人局门控（现行为修正）**：现状 host 开布局编辑**无条件**全局冻结 `SelectTimerPaused`（LAN 多真人局=host 一人编辑全员干等）——改为判据门控：多人局 host 打开这些 UI **不冻结权威计时**（编辑照常、倒计时照跑、各端自担）；客户端本地显示冻结（`ClientPhasePaused`）语义不变。
- 独立小批无网络依赖，随时可做（建议先行——用户可感收益）。
