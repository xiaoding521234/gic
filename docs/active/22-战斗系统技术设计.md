## 1. 三层时间模型

| 时间层 | 判定粒度 | 语义 | 读取状态 |
|---|---|---|---|
| 片间（攻速差） | 攻速片 | 硬先后：片 N 全部结算并应用后，片 N+1 才结算 | 当前状态（前序片已应用） |
| 片内（同攻速） | 瞬发效应 | **真同时（快照结算）**：读取片前快照、独立结算、效应统一应用 | 片前快照 |
| 块内（行动→衍生链） | 行动块 | 因果序：延奏→变奏等衍生效果在行动块内部串行展开 | 块内继承 |

- 攻速片：**攻速值完全相同**的单位才同片；片开始时刻 =（全场最高攻速 − 自身攻速）÷ 10 秒（连续换算，非 10 点分档）
- 死亡中断仅跨片发生（"开始执行前被击杀才落空"）；同片互杀 = 同归于尽（快照合并 HP）
- 枚举序（unitID 升序）仅决定命令在流中的排列与写-写冲突合并依据，**不影响结算结果**

## 2. 执行阶段：分步流式演算

结构对标王者荣耀/原神的服务器权威（客户端实时表现+输入随时上交），tick 粒度换成攻速片。

**片循环（Host 侧）**：
1. 收集本片全部行动 → 快照片前状态 → 各行动独立结算（只读快照）→ 效应统一应用 → 产出片命令块
2. 立即推送本片命令块 → 等全体客户端 ack 或超时快进 → 结算下一片
3. **片边界 poll 即时行动队列**（连携/契约类），有则插入结算（产出独立插入块）
4. 末片完成 → 回合结束效果（按注册序）→ 阶段切换前扫 WaitConditions（如连携 2 秒窗未走完 → 等待）→ 广播回合结束 → 下一选择阶段

**门控与约束**：
- **Host 永不跑在客户端前面**（片级 ack）：即时输入永远作用于"当前演算点之后"，无回滚
- 两类交互点：软窗（演算照走，阶段切换前等待）、硬停（Pause→收输入→Resume）；**交互窗时间不可被"提前完成"压缩**
- "提前完成不空等" = 播放器侧压缩片间等待，仅对纯演算片生效

**片内快照结算**：
```
effects = []
foreach action in slice.actions（枚举序）:
    effects += action.Resolve(stateBeforeSlice)   // 只读片前快照
state = Apply(state, effects)                     // 效应统一应用
segment = Serialize(effects)                      // 产出片命令块
```
写-写冲突（伤害/治疗合并 HP 天然成立；同格超体积、双元素同附等）走确定性合并规则（§7.4 / docs/11）。

**瞬发×移动并存**：快照结算管瞬发效应（伤害/命中按片初位置），移动在同片内按 §7 动态逐步展开；瞬发命中判定暂定按片初位置（docs/11 跟踪确认）。

## 3. 数据模型

### 3.1 ActionData（选择阶段上交）
- `ActionType { Move, Skill, Burst, DeployUnit, DeployBuilding, UpgradeConstellation, BuyCard, UseItem, EquipItem, FactionSkill, OpenChest, Pass }`
- 字段：playerID / unitId / ActionType / SkillContext 型参数（目标格/方向/目标单位）/ ForceData（移动）/ cardId 等，按类型部分有效
- B1 先实现 Move / Skill / Pass，其余枚举占位、B6 补全

### 3.2 BattleCommand（单命令，union 风格）
- `BattleCommandType { Move, Damage, Death, Heal, ApplyBuff, RemoveBuff, ElementAttach, Reaction, StatChange, Summon, Effect, UI, Pause, Resume, ... }`
- 字段：type / actorUnitId / 片号 / 片内序 / **visibilityScope（预留，切片恒全可见）** / 平铺 payload（目标格/方向/数值/位移路径…）
- 命令粒度 = 一次原子视觉事件（沿用 docs/18 决策一）

### 3.3 Segment（片命令块）
- `{ turnNumber, sliceIndex, insertedInstantAction 标记位, List<BattleCommand> }`
- 回合输出 = Segment 流（逐片推送；**不再有回合级整块 TurnScript**）

### 3.4 BattleSnapshot（选择阶段头全量）
- `{ turnNumber, List<UnitState>{ unitId/位置/HP/攻速/元素附着/Buff 列表/尸体态/阵营/体积 }, 双方资源（摩拉/体力/手牌/牌库） }`
- 地形全量仅对局开始发一次（迷雾后置；地形变化 B8 走增量命令）

### 3.5 序列化
- **JSON**（JsonUtility；平铺字段适配其序列化能力，不用 Dictionary——列表+枚举索引代替）
- `IBattleSerializer` 接口隔离，将来可换二进制且不改调用方
- 调试友好优先：片级消息肉眼可读

## 4. 逻辑层载体与双端形状

- **逻辑 Unit = 现有 MonoBehaviour 组件容器**（Unit + 8 组件 + Skills/Buffs），仅 Host 场景实例化（可隐藏层），零重构复用 UnitStats/UnitElement/UnitMoveable/UnitStatus
- **UnitView = 双端同构表现层**（客户端与 Host 显示侧同一套代码）：Snapshot 建场、Segment 驱动动画，不持逻辑状态
- 本地/单机（B1-B6）：Host 与 Client 同进程，走 IBattleTransport-Local 直通；B7 LAN：同一接口换 Mirror 实现，上层零改动
- 铁律：**战斗逻辑不走 EventBusHub**；战斗内消息只走 IBattleTransport 专用通道

## 5. 回合流程骨架（B1 核心）

新增类（GIC.Battle 命名空间，Battle/ 下按 Unit/Skill/Tile/Buff 同级新增 Flow/ 目录）：

| 类 | 职责 |
|---|---|
| TurnFlowController | 回合状态机：最小版 = 选择阶段（收齐行动）→ 执行阶段 → 回合结束循环；五阶段完整版（AI 决策→玩家选择→玩家执行→AI 执行→回合结束，docs/04 §4.1）B6 落地 |
| TurnResolver | 执行阶段片循环：攻速分桶→片内快照结算→应用→产出 Segment→ack 等待→即时行动 poll |

| BattleSimState | Host 侧战场状态访问门面（快照生成/效应应用/unitId 注册） |

- B1 的技能 = DebugAttackSkill（硬编码固定伤害），用于跑通 DamagePipeline；B4 换正式 BaseSkill 子类 + SkillConfig.asset

## 6. DamagePipeline

核心公式（docs/05 §5.6）：
```
最终伤害 = (攻击力 × 攻击百分比 + 额外伤害) × (增伤 − 免伤) × 易伤
易伤 = 防御 ≥ 0 ? 100/(100+防御) : 1 − 防御/100
```
Phase hooks（B1 预留点位，B2-B4 接线）：
1. PreDamage：命中判定 / 元素反应预判（B4）
2. 乘区修改：Buff/技能/激化"+10"类插入
3. PostDamage：命中触发（获元能/吸血）+ 死亡判定

死亡判定：HP≤0 → 尸体态（UnitStatus 切换），碰撞/体积/属性/势力保留（docs/05 §5.4）。

## 7. 移动系统

### 7.1 判定链（逐格步进，每步依序）
1. **体积绝对层**：格内现有体积 + 自身体积 ≤ 3，否则停在格前——**无视阻挡能力也不可绕过**
2. **阻挡规则层**：UnitMoveable 三配置（blockAllies/blockEnemies/blockedByEnemies）——无视阻挡单位跳过本层
3. **地形层**：TileType 标签（AllowWalk/AllowFly/WaterTerrain）按 ForceType 判定

### 7.2 逐步判定原则
- 只判定**将要进入的下一个格**；移动者**当前所在格不参与判定**（同格共存单位不阻挡彼此离开/途经）
- 完全进入下一格前，位置判定仍在上一步的格

### 7.3 同片同步逐步结算
同片全部移动行动按"轮"推进（每轮所有未完成移动者各走一步）：
- 每轮先做各移动者的"下一格判定"（读本轮开始时的位置判定），通过者同轮进入
- 对方已离开的格不再阻挡 → **相向对穿 = 互相穿过**、中途同格瞬时共存不判定
- 跨片：前序片位置更新后才结算后续片（硬先后）

### 7.4 写-写冲突合并（B4 拍板，B1 留接口）
- 同轮多单位移入同格超体积：候选 = 枚举序前 N 入格 / 全部争格失败（docs/11）
- 双元素同时附着同一目标 / 双推力同时施加：确定性合并规则待定（docs/11）
- 同片多伤害/治疗：数值合并，天然成立

### 7.5 位移类型
ForceType { Walk, Fly, Amphibious, Knockback, Pull, Jump, Teleport }：Pull 无视阻挡规则但受体积封顶；建筑免疫强制位移。

## 8. 消息协议（IBattleTransport）

| 消息 | 方向 | 说明 |
|---|---|---|
| BattleStartMessage | Host→Client | 对局开始：地形全量 + 初始 Snapshot |
| SnapshotMessage | Host→Client | 每选择阶段头：全量状态 |
| SubmitActionRequest | Client→Host | 行动选择上交（B7 LAN 时挂 NetworkEventBus OnlyHost+Immediate） |
| SegmentMessage | Host→Client | 片命令块推流 |
| SegmentAck | Client→Host | 片播放完成确认（超时快进） |
| SubmitInstantAction | Client→Host | 即时行动（连携/投票），片边界 poll——B1 占位 |
| PauseMessage / ResumeMessage | Host↔Client | 硬停交互点（契约谈判）——B1 占位 |
| TurnEndMessage | Host→Client | 回合结束 + WaitConditions 结果 |

B1-B6 本地模式 = Local 实现（同进程直调）；B7 增加 Mirror 实现。

## 11. 表现层：立牌队形与判定区（2026-09-12 补充，B5 基线）

决策本体见 docs/18 决策二（2026-09-12 补充条目）；表现层时序与逻辑层解耦不变（逻辑即时结算，BattlePlayer 只管"何时播"）。

- **立牌风格参考饥荒**：2D 立牌 + 底座投影；格子表现尺寸明显大于单位立牌（一格容纳 3 点体积多单位）
- **同格队形布局（UnitView 职责）**：1 单位居中；2 单位并排；3 单位 2 前 1 后三角队形；占据数变化实时重排。灰盒期即按此布局（B1 同格共存调试的可视化依赖）
- **格子判定区（hitbox）内缩**：命中判定用小于格子表现范围的内缩判定区，同格全部单位共用——避免"箭矢未碰到立牌就先播伤害动画"
- **投射物真实飞行**：按弹道飞行（非逐格瞬移），命中表现 = 接触目标格判定区之时，命中即对该格全部适用目标生效（逻辑判定层不变：格子覆盖、Host 即时结算）
- **弹射物路径与截停**：直线飞行型覆盖由 Host 逻辑即定（发射格 → 首个敌方单位格截停，或 24 格上限消散——docs/05 §5.3）；Segment 命令携带发射格与截停格，BattlePlayer 按路径播飞行、按判定区时机播命中
- **投放形态由技能数据驱动**：直线飞行（安柏战技）/ 整线天降斜落（安柏爆发）/ 单位指向无投射（延奏、契约——直接对目标单位生效，不经格子判定）；Segment 的 Damage 命令带 delivery 元数据或 BattlePlayer 按 skillId 查表（B4 定）
