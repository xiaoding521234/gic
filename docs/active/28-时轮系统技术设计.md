# 时轮系统技术设计（SkillTimeline）

> 2026-09-23 立项并落地 B-S1（判定侧）。决策本体=docs/18 决策八；网检信源=.codely-cli/webrefs/skill-timeline-system/（EGamePlay 源码 18 文件已入库 EGamePlay_src/）。
> 命名对齐 GG 系统（docs/26）的"短名+功能类比"惯例——**时轮 = 技能的多轨道时间轮**（时间+轨道轮盘意象）；代码层命名=SkillTimeline。
> 学习对象：[m969/EGamePlay](https://github.com/m969/EGamePlay)（Ability/Execution/Status 三分）——**只取概念模型**（其运行时=EC 实时 ACT 框架+Odin 依赖，直接引入不可行）。

## 1. 定位

- **技能的演出与判定时间轴单一真源**：把"前摇→发射→飞行→命中→后摇"的时序结构从代码硬编码升级为数据资产，像拼积木一样组装技能。
- B-S1（已落地 2026-09-23）：数据层 + Host 判定接线 + 命令协议扩展 + 安柏双技能迁移。
- B-S2：编辑器（UI Toolkit 多轨道时间轴窗）。
- B-S3：表现素材落地（立牌动作段/战斗 SFX/箭矢正式素材）+ 客户端表现轨消费。

## 2. 概念对照（EGamePlay ↔ 时轮）

| EGamePlay | 时轮（GIC） | 说明 |
|---|---|---|
| AbilityConfigObject（技能配置：效果列表/触发点） | `SkillConfig.SkillData`（既有参数表） | 保留不动——数值单一来源 |
| ExecutionObject（SO：TotalTime/TargetInputType/ExecuteClips） | `SkillTimelineAsset`（新） | totalTime/aimMode/clips 三件直接对应 |
| ExecuteClipData（clip：StartTime/EndTime/Type=ActionEvent/ItemExecute/Animation/Audio/ParticleEffect） | `SkillTimelineClip`（平铺 union） | 轨道类型 GIC 化为七轨（§3） |
| AbilityExecution（运行时执行体：OriginTime+逐帧触发 clip） | Host=片内一次性编译（ResolveEffects）+ ProjectileResolver 连续时间轴求交 | 回合制无逐帧执行体——时轮事件在片结算时编译、在连续判定时间轴上求交 |
| ExecutionTargetInputType（None/Target/Point）+指示器预制 | `SkillAimMode`（十字方向/坐标格/单位指向/无目标） | B-S1 只存不消费（HUD 瞄准数据驱动化=B-S2+） |

**关键差异**（为什么不能照抄 EGamePlay 运行时）：EGamePlay 是实时 ACT——执行体逐帧 tick、碰撞用 Unity 物理；GIC 是 Host 权威回合制——判定必须确定性（快照结算+解析求交），表现只是判定的可视化。时轮的时间轴挂在**执行阶段连续时间轴**（B5 已有）上，天然确定性。

## 3. 数据模型

```
SkillTimelineAsset（Assets/Resources/Configs/SkillTimelines/{SkillName}.asset）
├─ totalTime    总时长（秒，含后摇——演出收束/取消窗口消费，B-S3）
├─ aimMode      目标声明（SkillAimMode：CrossDirection/Cell/TargetUnit/None——B-S2+ 消费）
└─ clips[]      平铺 clip 列表（按 trackType 分组解释）
     ├─ Targeting=0  目标声明轨（B-S1 未用——aimMode 字段承载）
     ├─ Action=1     动作轨（cueName=动作段名——B-S3 接素材）
     ├─ Judgment=2   判定轨（kind=SkillJudgmentKind：LineProjectile/LineBurst/TargetedUnit/AreaBurst）
     ├─ Vfx=3        特效轨（cueName——B-S3）
     ├─ Sfx=4        音效轨（cueName——B-S3 接 AudioManager）
     ├─ Resource=5   资源轨（预留——消耗目前在 SkillExecutor 0s 即时结算）
     └─ Movement=6   位移轨（预留——冲刺/击退技能后续批次）
```

SkillTimelineClip 载荷（union 风格，同 BattleCommand）：`startTime/endTime/kind/hitInterval/projectileSpeed/hitDiameter/maxRange/cueName`。

**分工铁律（防双源漂移，2026-09-23 审查 Y7 教训）**：
- **时间与规格归时轮**——发射时刻（startTime=前摇）、连发间隔（hitInterval）、投射物速度/判定直径/射程（0=BattleMetrics 默认）；
- **数值归 SkillParamKey**——每发伤害百分比（Damage）、发数（DamageCount）、消耗（EnergyCost）。clip 不重复存伤害数值；发数默认读参数表（本地化渲染同源）。

## 4. 双消费架构

```
SkillTimelineAsset（单真源）
   │
   ├─→ Host 判定视图（B-S1 已落地）
   │     BaseSkill.ResolveEffects 读判定轨 clip → 逐发发射声明（ProjectileEffect 带
   │     LaunchSeconds/Speed/Diameter/Range）/ 逐段 AoE（LineBurst，每段独立时刻）；
   │     ProjectileResolver 在执行阶段连续时间轴上求交（B5 体系不动——发射偏移+首窗插值修正）
   │
   └─→ 客户端表现视图（B-S3 接素材）
         SkillCast 命令（段内最前发射）→ 按 skillID 加载时轮资产 → 片播放起点=clip t=0，
         播动作轨（前摇拉弓/后摇收势）/音效轨（弓弦）/特效轨；投射物起飞由 Damage/消散
         命令的 launchMs 承载（Host 下发，客户端零推算）
```

### 4.1 安柏战技（一箭双丘丘）在数据里的样子

```
totalTime: 0.80    aimMode: CrossDirection
clips:
  Action    [0.00 ── 0.30  draw_bow]           前摇：拉弓
  Judgment  @0.30  LineProjectile interval=0.05 发射（发数=参数表 DamageCount 2）
  Sfx       @0.30  bow_release                 弓弦音效
  Action    [0.30 ── 0.80  recover]            后摇：收势
```

判定产出：两发 ProjectileEffect（launch 0.30 / 0.35，每发 40% BasedOnAttack）→ 各自独立求交/命中/附着/反应 → 两条 Damage 命令（launchMs=300/350 分时弹出）或消散命令。

### 4.2 安柏爆发（箭雨）

```
totalTime: 0.98
clips:
  Action    [0.00 ── 0.30  draw_bow]
  Judgment  @0.30  LineBurst interval=0.06      整线 4 段（发数=DamageCount 4）
  Sfx       @0.30  arrow_rain_release
  Action    [0.48 ── 0.98  recover]
```

判定产出：4 段整线 AoE 各自独立时刻（0.30/0.36/0.42/0.48），每段全线扫描产出 per-launchMs 的 Damage 效应——合并键含 launchMs=逐段独立命令（天降连射节拍）。

## 5. 命令协议扩展（B-S1）

| 扩展 | 内容 |
|---|---|
| `BattleCommand.launchMs` | 发射时刻（毫秒，相对片播放起点）。Damage（投射物命中/瞬发段）与 Effect（消散）携带——客户端投射物延迟起飞、瞬发段伤害数字节拍 |
| `BattleCommandType.SkillCast`（=14） | 技能施放事件：value=skillID、direction=瞄准方向、cell=施放者片初位置。段内最前发射（Move 前）；客户端按 skillID 加载时轮资产播表现轨（B-S3 接素材，当前占位日志） |
| MergeDamageEffects 合并键 | (攻击者,目标) → **(攻击者,目标,launchMs)**——逐发不并；同发内同目标多来源仍合并（快照同刻语义） |

客户端改动（BattlePlayer）：投射物/消散协程 `yield WaitForSeconds(launchMs/1000/playbackSpeed)` 后起飞；SkillCast 占位处理。

## 6. 判定语义细则（B-S1 定稿）

1. **前摇=发射时刻偏移**：t∈[0, launch) 投射物不存在、不参与求交；发射时刻落在单位移动段中时首窗按窗口起点精确插值单位位置（勿用段起点，否则模型失真）。
2. **逐发独立判定**：每发独立求交（可命中不同目标——不同 launch 谱系独立）、独立附着/反应/伤害命令；同片快照语义不变——同片齐发各段读**同一片前附着**（增伤反应每发各享、总伤与合并口径一致；同元素附着幂等覆盖）。
3. **元能口径不变**（docs/18 决策七）：战技命中获能同片按行动者去重（MergeEnergyEffects 存在性去重天然兼容逐发）。
4. **平衡观察项**：逐发化后**冻结时长可能叠长**（每发独立 ApplyBuffEffect→B2 同类合并=时长累加/取大，两发冰元素技能打冻结目标会双份施加）——Genshin 同语义（每次施加独立），观察平衡后定是否加"同片同源施加去重"（docs/11 登记）。
5. **打断语义沿用现状**：跨片死亡中断天然覆盖（片初已死→行动落空、无发射）；同片互杀=同归于尽（发射照常）；不新增"前摇被打断"规则。
6. **无时轮兜底**：timeline=null 的技能走旧合并行为（B4 简化①延续）——存量技能零破坏渐进迁移。

## 7. B-S2 编辑器规划（UI Toolkit 多轨道窗）

- 形态：`Window/GIC/时轮编辑器`——选中 SkillTimelineAsset 打开；轨道行（七轨分区）+ 时刻标尺（0.1s 刻度）+ clip 块拖拽（改 startTime/endTime）+ 选中 clip 的属性面板（按轨道显示有效载荷字段）+ totalTime/aimMode 头部编辑。
- 开发规范走 gic-editor-tool skill（UI Toolkit、EditorPrefs、幂等）；参照 NoBugCn/ActionEditor 的轨道 UI 布局概念（无 license，只看交互形态）。
- 预览：编辑器内放一个调试战场（灰盒）+ scrub 时间轴播 clip（判定轨用可视化假想敌圆柱验证前摇/连发时序）——依赖 B-S3 素材的可先用色块占位。
- 素材接线约定：cueName → `Resources/Audios/Battle/{cueName}`（SFX）/动作段名 → 动作段配置（B-S3 定义）。
