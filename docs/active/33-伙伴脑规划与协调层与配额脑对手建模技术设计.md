## 2. 配额脑·对手建模（E-1）

### 2.1 对手预测器（「对手如我」先验）

新原语 `OpponentThreatModel.Build(sim, snapshot, myTeam, turn)`：对敌方全部存活可动单位逐一跑**确定性预测**：

| 敌方单位类型 | 预测方法 | 依据 |
|---|---|---|
| 眷属（1~2★） | **FamiliarBrain.DecideOne 原样复用**（启发式脑即对手模型——眷属行为可被玩家预测=决策三十一拍板特性，对 AI 同样可预测） | 启发式是纯函数（sim+snapshot→ActionData） |
| 伙伴（3~4★） | **共享评分骨架** `ScoreUnitCandidates`（中性档案、敌方实池——敌方伙伴体力确实从敌方玩家池扣，先验照查） | 「对手如我」业界标准先验 |
| 魔神（5★） | 同骨架（若敌方玩家操作魔神会怎么打=骨架最优猜测） | 同上 |

- **信息边界合规**（docs/active/32 §3）：预测=纯推导，只读 sim/snapshot 公共信息 + 确定性先验；**不读** Host 内敌方眷属已定行动（`_familiarUnitActions`）、不读敌方玩家未交选择——与真人玩家信息位完全对等（Frozen Synapse 哲学：信息对称，计划质量定胜负）。
- **确定性**：全链零 roll（启发式/骨架均枚举序确定性）——同快照恒同预测，回放/联机安全。
- **v1 语义简化**（登记 §10）：敌方预测 Move/Pass/缺席对威胁图零贡献（移动后二阶先验不做——保守不虚报威胁）；敌方伙伴真实决策发生在收齐我方选择后（会感知我们），单层预测不做博弈递归——预测失准空间=WEGO 本质，业界务实同款。
- 性能：敌方 3~8 单位 × 启发式/骨架一遍 ≈ 伙伴脑同量级，毫秒级。

### 2.2 威胁图（推导产物，统一数据载体）

`ThreatMap` 四件（一次构建、配额脑各候选消费）：

| 表 | 语义 | 构建 |
|---|---|---|
| `ExpectedDamageOnAlly` | 我方 unitId → 预期承伤粗估和（`EstimatePerTargetDamage`×命中数，不计防御/反应——排序用途非精确预言） | 敌预测攻击行动 → 敌方视角 `PreviewLineTargets` 扫命中我方 |
| `EnemyThreatScore` | 敌方 unitId → 该敌全部预测行动预期输出和（「威胁源」排序） | 同上累加 |
| `ThreatenedCells` | 敌方预测攻击的**火线格集合**（沿预测方向扫到技能射程、虚空格截断——与 PreviewLineTargets 几何同口径，射程提取与 AttackRangeOf per-skill 同源） | 火线扫描（移动避险「别站火线上」） |
| `DoomedAllies` | 预期承伤 ≥ 当前 hp 的我方单位（**合计致死判定**——多敌集火同一单位时在构建尾部统一判，勿逐敌判） | Build 尾部对快照 hp 收口 |

- 建筑（含协议核心）无技能无行动，零威胁贡献。
- 单位指向/自施放型预测（如敌方伙伴预测出复苏/自增益）不产直接伤害威胁，跳过。

### 2.3 配额候选风险调整（三消费点）

| 消费点 | 规则 | 常量 |
|---|---|---|
| **操魔神攻击候选**（骨架 ScoreAttackCandidates） | 目标是威胁源（EnemyThreatScore 高者）加**反威胁分**——优先拆除敌方火力核心；乘档案权重前并入 | `ThreatResponseScoreCap = 25`（`min(威胁值/2, 25)`，低于斩杀 80——反威胁优先于平打、不优先于斩杀） |
| **操魔神移动候选**（骨架 ScoreMoveCandidate 三落点档：主逼近/轴对齐/对齐探针） | 候选落点在 ThreatenedCells 内扣**避险分**（下回合白挨打）；扣后钳下限 1——保底候选不因威胁被 Offer 丢弃（tracker 初值 0 拒非正分，危险落点仍 Offer 但排后） | `ThreatenedCellPenalty = 12`（与走位进射击线加分 8 同量级正负抵偿） |
| **号令治疗候选**（EvaluateEnsoTarget Heal 分支） | 伤员在 DoomedAllies（预计将被击杀）→ 治疗估值加**救命分**（预治疗保命——斩杀档的对偶） | `EnsoRescueScore = 30`（低于斩杀 80） |

- **伙伴脑不消费威胁图**（v1 拍板 #4）：`ScoreUnitCandidates` 新增可选参数 `threat = null`——配额脑传、伙伴脑不传=零行为变化；伙伴脑消费（走位避险）登记 §10 待观察。

## 3. 伙伴脑·协调层（E-2，已落地 2026-10-03）

决策序内意图板 `CompanionBrain.TeamIntentBoard`：伙伴按 unitId 升序决策时前位已定行动入板（`DeclareIntent`——按决策快照反推声明面），后位评分消费。与 staminaReserve/committed 虚拟池同构（决策序内登记-消费）；决策序=unitId 升序不变，确定性零损。配额脑不使用（每回合仅 1 配额行动，无跨单位声明域——`ScoreUnitCandidates` 的 `board=null` 默认参数）。

| 板表 | 消费规则（落地口径） |
|---|---|
| `DeclaredDamageOnEnemy`（敌 unitId→估伤和） | **伤害溢出去重**：`remaining = target.hp − 已声明伤害`；remaining ≤ 0 =前位足杀，本发边际价值 0（伤害贡献与斩杀加成均不记——击杀已被前位拿走）；评分机制自然转向次优目标，勿显式降档。`board=null`（配额脑）时 remaining=target.hp 与原逻辑恒等 |
| `DeclaredHealOnAlly`（我 unitId→有效治疗和） | **治疗去重**：有效治疗对「剩余缺口」计（`min(heal, missing−已声明)`），半量门槛同对剩余缺口——伤员被前位覆盖满后后位治疗估值自然归零。`EnumerateSkillHeals` 单源（估值/声明共用，声明端全量口径） |
| `FocusedEnemies`（被声明攻击的敌集） | **集火跟随**：档案「集火权重」>0 时对**未死**（remaining>0）的已集火目标加 `FocusFireScorePerRank(3) × 权重`——量级低于战技获能 12 与斩杀 80（只影响同分域目标选择） |

- **声明口径=估值**（与评分同源：EstimatePerTargetDamage/有效治疗）——结算偏差（防御/反应/被挡落空）由下回合重决策自然吸收。
- **档案新字段**：「集火权重」int 默认 0（全 35 单位资产零迁移）；首批配置=安柏/凯亚 5（测试观察值，UnitConfig.asset）。
- **验收**：多伙伴打同一残血敌时不再全堆一发（后位转向次优目标）；双治疗者不重复奶同一伤员；安柏/凯亚在可选目标间倾向已被我方攻击者；配额脑与眷属脑路径零行为变化。

## 4. 伙伴脑·规划层（E-3，已落地 2026-10-03）

- **移动锚延续槽（意图延续的收敛形态）**：跨回合规划的病灶=多锚贪心抖动（朝敌1走→敌2 变近改道→又回敌1 的边界震荡），病灶在**锚**不在行动——延续对象收敛为移动锚（CR 式 target lock）而非完整行动延续。`CompanionBrain._lastMoveAnchors`（unitId→上回合锚 unitId）：①记录=评分期锚循环现场四个移动候选产出点（主逼近/轴对齐/探针/兜底——「承诺朝谁」），**只记敌方锚**（支援伤员锚奶满即失效，锁定反而滞后）；②消费=下回合 `ScoreMoveCandidate` 锚序构建时锁定敌**插队敌序首**（支援伤员锚之后、其余敌之前）；③自动解锁=锚死（GetUnit null/IsDead 不插队自然回落距离序）/不可达（BFS 0 换下一锚）；④生命周期=static+DecideAll turn≤1 自清（StartBattle 恒从回合 1 起=新战斗自动清零，TurnFlow 零接线）。确定性：插队/记录全在决策序内，无随机源。
- **反应预期分（估值感知①——跨单位连招基础）**：targets 循环内读快照附着×技能元素经 `ElementReactionResolver.Preview` 单源预判——增伤反应（蒸发/融化 1 级 +50% 乘区）加 `折减伤害/2`；冻结控制反应无增伤乘区不计分。技能元素=`SkillHitResolver.SkillElementOf`（E-3 从 ResolveProjectileElement 抽提的公共单源：OnHit 首个 Damage 原子优先、Physical=施法者元素回落）。效果：凯亚挂冰→安柏跟火自动蒸发=事实上的跨单位连招，零新基建。
- **防御折减（估值感知②）**：`MitigatedDamage`——DamagePipeline 易伤乘区轻量镜像（正防御 100/(100+防御) 除法递减/负防御每点 +1%），评分与 `DeclareIntent` 声明共用单源（声明不过称高防敌足杀——E-2 去重的声明口径与评分同源）。修「对高防目标伤害虚高」盲区（原 `EstimatePerTargetDamage` 自注「未计防御/反应乘区」）。
- **骨架级修正的波及面**：防御折减+反应分在共享骨架（ScoreAttackCandidates）内——配额脑操魔神档同享受益（估值更准=预期改进非回归）；眷属脑不消费估值零影响；技能级门槛（perTarget≤0 跳过）与 WouldHaveFiringLineFrom 线判定维持原口径不动。
- **验收**：①多敌边界震荡消失（伙伴锁定一个敌逼近到死/不可达）；②安柏对「挂冰/挂水的敌」优先开火（同分域内）；③对高防敌伤害预期不再虚高、斩杀判定更保守；④声明去重口径=折减后（前位声明不虚高）；⑤同 seed 重开局行为逐回合一致。

## 5. 确定性纪律（全批红线）

- 全链**零新 roll**：预测=确定性枚举推导；意图验证=纯函数；意图表=决策序内确定性登记。
- **信息边界**：不偷看 Host 内敌方已定行动/未交选择（预测只读公共信息）；己方眷属意图对伙伴脑不可见口径维持（docs/active/32 §3）。
- 决策序铁律（unitId 升序 × skillIndex 升序 × 十字枚举序、严格大于替换）不变。

## 6. 纳西妲读心预留（不实现，登记）

## 9. 验收要点（E-1）

- **回归零变化**：真人玩家对局行为零变化（威胁图只在配额脑=AI 玩家构建与消费）；伙伴脑 threat=null 路径与改前逐字节同行为。
- **AI 玩家操魔神会拆威胁源**：敌高威胁单位（如攒满槽的凯亚）被优先攻击（反威胁分可见生效）。
- **AI 魔神不站火线**：移动候选落点在敌预测火线内时倾向换位（同分候选间可见差异）。
- **救命号令**：我方单位预计被集火致死时，AI 玩家治疗号令优先指向它。
- **确定性**：同 seed 同命令序列=同战局（预测零 roll，回放一致）。
- **信息边界**：配额脑不读 _familiarUnitActions/_pendingActions（代码审查项）。
