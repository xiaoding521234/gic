> 2026-11-23 立项。**毕设选题**：《基于大模型的Unity即时卡牌战棋游戏设计与实现》（长沙学院计算机科学与工程学院，2027 届，2027.05 答辩）。**工程载体 = gic**：即时卡牌战棋本体（决策九十五即时制已收官）与既有大模型基建直接复用，毕设改造 = 把大模型从"周边陪聊"升级为**深度参与玩法循环的核心系统**。

> 毕设书面材料（课题申报表/开题报告，2026-11 已交/备交）存 `.codely-cli/biye/`（不入库）。GG 指挥与战场外交的设计在 docs/26 §10，本文只留指针。

## 1. 总原则（全改造的硬约束）

### 1.1 混合智能架构（神经＋符号）

- **业界依据**（一手调研存档 `.codely-cli/webrefs/ai-commerce-2026-10/`）：商业战棋/策略战术层全部=打分制零搜索树（Into the Breach/XCOM2 公开资料）；LLM 直接做战术决策生产零落地（延迟秒级 vs 决策帧级、成本、不可解释三重约束）。
- **落地方案**：神经网络（LLM/TTS）负责语言、语音与宏观战略（慢思考），符号系统（规则三脑/评估函数）负责微观战术（快反应）。学术对标 Meta CICERO（Diplomacy 外交 AI）"自然语言谈判＋行为履约"路线、PUBG Ally 快慢分离架构。
- **答辩口径**：游戏 AI 是"神经+符号"混合架构，不是全神经网络；语音模块含本人完成的深度学习声音克隆训练（docs/27 v4 管线）——这是对"你自己训了模型吗"的标准答案。

### 1.2 确定性纪律（LLM 不许破坏回放/帧同步）

- **LLM 是 AI 玩家的"手"**：LLM 的解析/决策结果一律以**命令**形式落入命令流（与玩家手动指挥同构），回放录制命令而非 LLM 输出；状态 hash 只覆盖命令驱动的确定性状态。
- LLM 调用只发生在**战略节拍**（秒级延迟可接受），战术层与模拟核心零接触；`RollChance` 单出口规则不变（决策层禁消耗战斗 RNG——2026-10-25 锚点滞回先例）。
- LLM 原文/结构化意图落**外交/决策日志**（评估实验素材），不进 hash、不进回放。
- 新增确定性状态字段（如同盟状态）必须同步进 `ComputeStateHash`（F2 铁律）。

### 1.3 素材口径

毕设文档/答辩演示**去 IP 化**：材料中泛称"即时卡牌战棋游戏"，不出现原神字眼；答辩演示用录屏而非现场跑工程（防环境风险）。

## 3. 新增子系统设计（毕设优先级序）

### 3.1 LLM 战斗解说系统【必做·演示王牌】

- **输入**：战斗事件流（击杀/元素反应/经济变化/胜负转折）——从命令流与 `BattleRecorder` 抽象 `CommentaryEvent`（类型/主体/数值/时刻），滑动窗口聚合成上下文摘要。
- **生成**：LLM 按解说员人设（SystemPrompt 模板）流式生成解说词；事件稀疏期不生成（窗口+阈值节流，复用 `BattleVoiceDirector` 三道闸范式：主/副通道、最小间隔、同窗合并）。
- **呈现**：滚动字幕条（HUD）+ 可选 TTS 播报（复用 `PetTtsClient`，走 Voice 通道规则：不 ducking 音乐）。
- **确定性**：纯客户端表现层，不进命令流/回放——零风险模块。
- **验收**：典型战局 3 分钟内解说密度/延迟/事实准确率；节流下无重复刷屏。

### 3.2 LLM 战术参谋系统【必做】

- **输入**：战场结构化快照（双方存活/战力/经济/关键单位/局势指标），由 Host 快照序列化器产出 JSON（新增；只读）。
- **交互**：玩家经派蒙/GG 问"这局面怎么办"→ LLM 读快照+RAG 规则检索 → 输出局势分析+行动建议；建议经 `PetGameBridge` 工具调用格式输出，玩家确认后命令化执行（不自动执行）。
- **验收**：建议与战局事实的一致率（人工抽评 20 局）、意图解析成功率、建议执行链 e2e。

### 3.3 自然语言指令入口【必做】

- **输入**：玩家口语（"给我加一百摩拉"）→ LLM 意图识别 → 映射到指令系统命令域（docs/25 可枚举域 + 补全表即 schema）。
- **落地**：复用 `PetChatIntent` 桥 + `RunCommandDirect` 路由；输出带参数 JSON（Schema 校验），失败走澄清追问。
- **验收**：指令域覆盖率、参数提取准确率、拒绝域外请求的安全性（不新增命令面，仅消费既有域）。

### 3.4 LLM Agent 对手战略层【核心加分项·快慢分层落地】

- **架构**：LLM 战略层以固定周期（≥5s 节拍）读局势快照，输出**战略意图**（经济发展/阵容扩张/集火目标/防守重心）；`AIStrategist` 五态机消费意图做态势调节，`PlayerQuotaBrain`/三脑按既有规则执行战术。LLM 输出=该 AI 玩家的"玩家输入"级命令（购买/部署/号令域），走命令流。
- **人格接入**：`PersonaPack` 八人格作为 Prompt 参数注入（经济家/狂战士/交涉家…战略风格差异化）。
- **降级**：LLM 不可用/超时 → 回落纯规则 AI（现有三脑零改动即可跑）——天然 A/B 实验开关。
- **验收**：见 §5 对照实验。

### 3.5 语音交互闭环【可选加分】

STT 输入（新增，候选：系统级/云端 ASR）→ 3.3 意图链或派蒙对话 → 既有 TTS 输出。毕设时间富余才做；答辩演示可用"语音问参谋"场景。

### 3.6 GG 指挥与战场外交【设计已定稿】

**全部见 docs/26 §10**（GG 从 IM 升级为指挥与外交频道：P4 AI 队友指挥=意图板注入；P5 混战外交=DiplomacyState 同盟状态机+说服判定链+履约监督）。依赖链：本节 3.4（LLM 战略层）→ P4 → P5（另需混战对局形态新玩法）。

## 5. 评估实验设计（毕设说明书第六章素材）

1. **子系统质量评估**：各子系统响应延迟（P50/P95）、结构化输出格式合规率、内容质量人工评分（解说事实准确率/参谋建议一致率/指令解析成功率）。
2. **对照实验（核心）**：同 seed 组、`LLM 战略层+规则战术层` vs `纯规则 AI`，各 ≥30 局——胜率分布、回合长度、行为多样性指标（单位移动熵/技能使用方差/购买路线差异）；人格参数对战略风格的影响分组对比。
3. **外交评估**（若 P5 落地）：说服成功率×提案合理性相关性、同盟履约率、八人格外交风格差异；外交日志（LLM 原文）作定性素材。
4. **数据采集**：`ai-metrics` 工具链扩展采集事件 + 回放批量重演统计。
