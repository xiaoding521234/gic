# 伙伴脑讨论批（I 批次）技术设计

> 2026-10-04 立项。用户拍板：
> ①**玩家做出的选择（魔神战技/爆发、伙伴号令、部署单位等）伙伴脑需要考虑进去**；
> ②**采用最优质量的做法**——本项目后续会有大量伙伴单位、需要做大量 AI，讨论机制必须一次做扎实（业界最优形态，前瞻规模化）；
> ③随凯亚报障「开局只走一格、移速 30 没发挥」同批落地移动协调（坑⑧ 返修 + 移动意图占位）。
> 背景核验（2026-10-04）：伙伴脑阶段三时序**已感知**玩家选择（playerActions 传入：号令跳过+体力预留）——用户例「体力 20、魔神耗 10、剩 10 给伙伴」伙伴脑已知道；缺的是**分配讨论**（现状=unitId 升序先到先得）与**内容感知**（玩家魔神打了谁伙伴不知道）。
> 业界对照（docs/active/33 §头 + 2026-10-03 三路网检维持）：生产界「伙伴讨论」全是黑板/两遍法轻量形态；预算分配标准解=两遍法（申报一遍+按边际价值装包一遍）；合同网/拍卖/显式任务分配器 E 批已否决（规模不匹配），本批维持否决。

## 1. 规则总表

| 组件 | 落地形态 | 否决的备选 |
|---|---|---|
| I-A 体力预算讨论分配 | **两遍法**：①申报遍（全员裸分取各自最优候选）→ ②装包遍（按单位体力价值装包分配名额）→ ③执行遍（获名额者带意图板重评分定具体行动） | 真组合枚举（6 伙伴 3 候选=729 组合，无必要）；单遍顺序贪心=现状（先到先得，移速价值不敏感） |
| I-B 全玩家行动入板 | 玩家已提交行动（Skill/Move/Deploy/Pass）经同一 `DeclareIntent` 口径入本方意图板——攻击估伤/治疗面/集火集/落格占位对伙伴评分生效 | 深度感知玩家行动的完整结算预演（克隆模拟依赖，E 批已否决同族）；只入攻击不入治疗/移动（半感知=去重三表口径不一） |
| I-C 跟随目标分配 | 意图板 `DeclaredVanguardFollow`（先锋→跟随者数）：后位支援型选**跟随者最少**的先锋（同数取 unitId 小）——「你跟凯亚、我跟丘丘人」 | 软偏好（跟随价值×跟随者数衰减评分——评分骨架再开一族权重，硬规则更确定） |
| I-D 移动意图占位 | 意图板 `DeclaredMovement`（单位→决策落点）：后位伙伴 BFS 把前位已声明落点视作占位——集团推进不互撞；消费点=BuildApproachField 单点（全 BFS 消费方自动感知） | 决策层直线扫描查快照占位（结算前友军可能移走——过度保守；部分行进语义维持）；站位评分器接占位（v1 不接，下回合重决策吸收） |

## 2. I-A 两遍法体力预算分配

### 2.1 三遍链（最优质量形态）

```
申报遍：全可动伙伴（未被号令）按 unitId 升序，dryRun=true、board=null、满池（实池−玩家预留）
        → 产出 (bestScore, bestAction, cost) 申报表（纯读、零槽写入、零板声明）
装包遍：按队伍分组（池 per-playerId）独立装包：
        cost=0 的申报=白给，直接获名额；cost>0 按单位体力价值（score×costB vs scoreB×costA 交叉比较，
        long 防溢出）降序、同价 unitId 升序，逐个扣虚拟池直到预算尽
执行遍：按（Team 枚举升序 → 队内装包序）逐个带正式板重评分（board+递减池+dryRun=false）
        → 定稿行动 → DeclareIntent 入板 + 槽记录（E-3/H-4）+ I-C/I-D 声明
```

- **名额分配依据与执行依据分离**（招标/执行分离）：申报分=「假如只有我」的裸价值（公平排序基准）；执行分=带板协调后的真实行动（E-2 去重语义保留——已验证资产不丢弃）。
- **执行遍重评结果可能与申报不同**（前位声明改变后位最优目标——正常重定向）；重评 null=名额浪费（罕见，下回合自愈，声明口径偏差同 E-2 哲学）。
- **确定性**：三遍全确定性序（申报=unitId 升序、装包=价值交叉比较+unitId 决胜、执行=Team+装包序）；零新 roll。
- **成本**：申报+执行两遍评分 ≈ 现状 1.x 倍（现状本来全场一遍）；毫秒级，前瞻大量伙伴单位线性扩展。
- **规模化**：新伙伴零新代码（数据驱动行为档案维持）；装包交叉比较对 cost 差异化（未来高价技能）天然近优。

### 2.2 副作用槽纪律（两遍防脏写）

E-3 `_lastMoveAnchors`/H-4 `_vanguardTrack` 槽写入与板声明**只允许执行遍发生**——申报遍 `dryRun=true` 抑制全部槽写入（评分器内 RememberMoveAnchor 调用点×3 + _vanguardTrack 写点×1）；未获名额伙伴零槽写入（「没承诺不记槽」语义）。

### 2.3 边界

- 配额脑（每回合 1 行动，无跨单位名额域）与眷属脑（不占体力）零行为变化；`ScoreUnitCandidates` 共享骨架只加 dryRun/board 透传参数。
- 玩家号令占用的伙伴（commanded）不进申报遍（其行动=号令技能，I-B 预载声明）。

## 3. I-B 全玩家行动入板

阶段三=收齐全部玩家选择后（D 批既定口径：玩家选择已定稿=非隐私，体力预留/号令跳过已消费）；本批把**内容**也提取进板：

| 玩家行动类型 | 声明口径（与伙伴 DeclareIntent 同源单出口） |
|---|---|
| Skill（魔神战技/爆发、伙伴 Enso/Contract 号令） | 方向攻击技能：PreviewLineTargets 逐目标估伤入 `DeclaredDamageOnEnemy`+集火集；治疗原子入 `DeclaredHealOnAlly`（号令治疗救命=伙伴预治疗估值自动让位）；自施放/单位指向增益：零伤害声明 |
| Move（魔神移动） | 落点入 `DeclaredMovement`（I-D 占位）——魔神换位伙伴不再撞位 |
| DeployUnit（出战） | 落格入 `DeclaredMovement`（占位感知）；战力感知 v1 不做（结算后下回合自然在场） |
| Pass | 零声明 |

- **天然跨队安全（无需分板）**：三表全按目标单位 id 键控、id 空间按队分割——敌玩家声明键=我方单位 id，落在我方伙伴「敌集」语义之外，任何查询不命中=零信息泄漏零行为影响（E-2 单板双队共用已实证同机制）。
- **信息边界**：仅「已提交」玩家行动入板；Host 内眷属已定行动（`_familiarUnitActions`）维持对伙伴脑不可见（docs/active/32 §3 口径不变）。

## 4. I-C 跟随目标分配

- `TeamIntentBoard.DeclaredVanguardFollow`（先锋 unitId→跟随者数）。
- **消费**：`FindMeleeVanguard` 加 board 可选参数——本方近战先锋中选**跟随者最少**者（同数取 unitId 小；board=null=现状首先锋，眷属/无板路径零变化）。
- **声明**：执行遍支援型伙伴先锋伴随模式定稿时声明（vanguard 确定且产出伴随候选）——后位支援型自动换次选先锋。
- 效果：两个奶妈两个先锋=一对一伴随；单先锋多支援=全跟（无次选时回落）。

## 4b. 追随直连返修（2026-10-04 首轮实测「凯亚走 3 格芭芭拉没立刻跟上」）

**根因**：WEGO 快照滞后首拍窗口——T1 芭芭拉决策时凯亚尚未结算（快照仍在出生区），她「已贴伴随位」→驻位无候选→**申报遍 Best=null→无名额→T1 缺席**；H-4 外推槽 T1 为空（新战斗自清）救不了首拍。凯亚的移动申报其实早就有（申报表内），缺的是**让跟随者消费到**。

**三处修复（讨论数据流补全）**：
1. **追逐锚直连声明落点**：H-4 段 `vanguardPos` 优先=board.DeclaredMovement[先锋 id]（申报遍读申报落点/执行遍读正式声明落点——「凯亚告诉芭芭拉我要走到 X」当回合即消费）；声明落点=真实决策位 > 外推猜测 > 快照滞后位，有声明跳过外推（双外推过度），无声明回落外推链不变。
2. **申报遍拆两轮**：输出型先申报（纯独立视角 board=null），支援型后申报且消费「申报落点板」（bidBoard=输出型申报移动落点预广播——申报表=意图的第一次广播、讨论的起点）；跟随者的独立视角原则修正为「消费先锋申报」（支援型=天然响应者）。
3. **执行序支援型稳定殿后**：grants 按（Team 升序→同队内 isSupport 后置，OrderBy 稳定保持装包价值序）——先锋先正式声明落点、跟随者后重评分消费正式声明；无支援型队伍=恒等重排零变化；支援型后决策兼得更多板信息（输出型伤害/集火声明）=决策质量只增不减。

**预期行为**：T1 凯亚申报走 3 格→芭芭拉申报轮读到落点→申报追随候选（有价值分）→双双获名额→执行凯亚先声明正式落点→芭芭拉重评分追逐锚=正式落点→**同回合走 3 格跟上**（治「下回合才跟上」）；此后每回合同步集团推进。

**残留观察**：执行重评改变先锋行动（凯亚申报移动→执行改施放战技）时跟随者回落外推链、名额可能浪费（罕见，下回合自愈——与 §9 名额浪费观察项同族）；H-3 视野敌集仍以先锋快照位置为中心（轻微信息滞后，不阻塞跟随——观察后再评落点中心化）。

## 5. I-D 移动意图占位

- `TeamIntentBoard.DeclaredMovement`（unitId→决策落点 BattleCell）。
- **声明**：执行遍伙伴移动行动定稿时（决策落点=projectedCell 口径，乐观）；玩家 Move/DeployUnit 预载（I-B）。
- **消费**：`BuildApproachField` 加 board 可选参数——occupied 构建尾部并入已声明落点（跳过自身声明）——**单点接入**，锚循环/伴随绕行/兜底全 BFS 消费方自动感知；眷属脑/配额脑不传=零变化。
- **口径**：声明落点 vs 结算实际落点偏差（执行层停格/推动）为保守向（后位多绕路不会死锁；真实结算后下回合重算吸收）——与伤害/治疗声明同哲学。
- **连续避让收敛**：A 声明→B 避让声明→C 避让……有限格数单调收敛，无环。

## 6. 坑⑧ 返修（随批先落，凯亚报障根因）

- **根因**：伙伴锚循环直线前缀化用 `ApproachStraightPrefix`（切比判据）——集团拥挤场景 BFS 首步=侧向绕行、到锚切比距离不严格递减=前缀恒 1 格（移速被结构性吞掉；docs/14 §115 坑⑧ H 批已记载但当时只回填支援伴随路径）。
- **修复**：锚循环换 `FindApproachStraightSteps`（BFS dist 场递减判据——沿最短路实格推进，逐格已查单位占位+地形）；方向改用 dist 场首向。旧原语退役保留+标注勿新增消费方。
- **预期**：开局集团推进凯亚满 3 格；绕行段照常走满预算（最短路实格）。

## 7. 确定性纪律（全批红线）

- 全链**零新 roll**：申报/装包/执行三遍全确定性序。
- **决策序**：从「单遍 unitId 升序」改为「装包序（价值交叉比较+unitId 决胜，Team 升序合并）」——同为确定性铁律（同快照恒同结果）。
- **信息边界**：仅玩家已提交行动入板；眷属已定行动维持不可见。

## 8. 验收要点

- **体力分配**：体力 20、玩家魔神耗 10 时，剩 10=获名额的是申报价值最高的两个伙伴（非 unitId 靠前者）；斩杀/救命奶候选优先获名额。
- **玩家魔神联动**：魔神打残的敌伙伴自动补刀；魔神已足杀的目标伙伴转火；集火权重对魔神目标生效。
- **部署/魔神移动占位**：伙伴不撞魔神换位落点、不撞新出战单位落格。
- **跟随分散**：双先锋双奶妈=一对一伴随（探针可验跟随者数）。
- **集团推进**：开局密集站位下伙伴移动步数满移速（坑⑧）；后位不撞前位已声明落点。
- **回归零变化**：配额脑/眷属脑路径逐字节同行为（board/dryRun 默认参数=现状）；同 seed 重开局逐回合一致。
