# 48 - 战斗画面商业级增强路线图（候选）

> 状态：**候选方案，未拍板、未开工**。本文把「战斗场景还有哪些增强画面的办法」整理为可分批实施的路线，不代表新增既定需求。
> 当前基础：URP 棋盘 + 纸片人单位 + 局部 3D 建筑；总部局部画面增强已收官（docs/18 决策九十六，提交 31304f2）。
> 关联文档：docs/17（架构现状）、docs/18 决策七十九（迷雾）、八十五（悬停）、九十一（地脉）、九十三（资源点与 HD-2D）、九十五/九十六（总部）。

## 1. 目标与非目标

### 1.1 目标

在不改变回合制规则、Host 命令流和既有纸片人路线的前提下，使战斗画面达到商业级应有的：

- **统一**：地形、单位、建筑、技能、UI 像同一款游戏，而不是各自调色。
- **可读**：玩家首先看见技能预警、命中与危险，其次才是单位、地形和装饰。
- **落地**：单位与建筑真实站在棋盘上，移动、飞行、灵魂和尸体有明确空间关系。
- **手感**：施法、飞行、命中、受击、死亡与复苏形成完整且同步的演出。
- **稳定**：白天、夜晚、迷雾、地脉、2v2 多建筑和技能高峰下均无穿帮或明显性能失控。

### 1.2 非目标

- 不把全部纸片人直接替换为风格未统一的 3D 模型。
- 不靠强 Bloom、全屏粗描边、无差别提高饱和度或满屏粒子制造“商业感”。
- 不默认增加每窗实时灯、高成本实时反射或大量动态阴影灯。
- 不因画面增强修改战斗规则、AI、协议、部署格、拾取或回放命令流。
- 全局曝光、全场灯光和全屏后处理若需调整，必须单独拍板，不能沿用上批局部授权。

## 2. 商业级验收口径

每批实现必须同时满足以下标准，而不只是“截图更亮/更华丽”：

1. **信息层级正确**：技能预警与命中、合法/非法落点、敌我关系先于装饰被识别。
2. **同一视觉语言**：光向、色温、阴影、描边、图标线宽、立牌视角和脚底高度一致。
3. **动态状态完整**：增强效果覆盖部署、移动、冻结、尸体、受击、消散、复苏、迷雾和地脉，不停留在静态展示。
4. **克制发光**：发光主要服务窗灯、技能与关键物件，不损害墙面、立绘、屋顶或 UI 纹理。
5. **可复验**：同一回放、同一机位可做增强前后对照；运行时结果由用户复测确认。
6. **高峰可承受**：以实机基线和最差场景验收帧率、内存、GC、RT 与解码峰值，不凭编辑器静态帧推断性能。

## 3. 先建立战斗视觉规范

### 3.1 固定色彩脚本

- **白天**：暖中性主光，暗部保留色彩，不把全场抬成平光。
- **夜晚**：冷色环境光与较低暗部亮度，窗灯和技能提供局部暖色/元素色对照。
- **地脉**：靛蓝、冷紫或青灰为环境倾向，但队伍色、元素色、危险色和合法落点色必须保持可辨。
- **发光预算**：窗灯、技能、关键交互物件优先；普通地形和装饰不大面积自发光。

### 3.2 固定表现规则

- 主光方向、阴影方向和 softness 全场景一致。
- 立牌视角、显示高度、脚底基准和底座盘关系统一。
- 描边只服务选中、悬停、命中预览等交互状态，不作为全场常驻滤镜。
- 图标、伤害数字、Buff、装备与命座角标使用统一尺寸、线宽和动画节奏。
- 贴地硬边 props 继续走 cutout/深度；水面、雾面、立牌视频等连续 alpha 表现继续走 blend/层梯，不破坏决策九十三的 HD-2D 分工。

### 3.3 固定基准画面

建立三组同机位基准图，后续每批复用：

1. 白天常规战斗。
2. 夜晚常规战斗（窗灯与技能同时出现）。
3. 地脉或迷雾战斗。

另设两张压力图：2v2 多建筑、多单位技能高峰。基准图只用于对照，不替代用户运行时验收。

## 4. P0：视觉统一与落地感

### 4.1 全单位接触阴影

将总部决策九十六的思路扩展为统一落地系统：

- 建筑继续使用实际 footprint 柔性阴影。
- 纸片人使用小型、低强度、与脚底对齐的软阴影，不能套用总部大网格。
- 移动、飞行、灵魂以阴影位置/透明度表达离地高度；禁止用阴影改变真实碰撞或拾取。
- 部署可有短促落地脉冲或尘环；尸体、冻结、消散、迷雾、地脉共享既有显隐和淡出链。

候选落点：`UnitView` 底座与状态链、`BuildingModelView` 辅助表现件生命周期、`BattleViewFactory` 材质工厂。

### 4.2 地形接缝与边缘

- 地块边缘增加轻量倒角或高度变化，降低均匀塑料方块感。
- 草地—水面、草地—薄冰使用窄带过渡、湿润边或岸线泡沫。
- 以固定种子添加少量碎石、草叶、泥土 decal；战斗操作区域保持干净。
- 非操作阶段减弱格线，悬停、部署和瞄准时再提高网格可读性。
- 不为了过渡效果重新引入透明排序、z-fighting 或遮挡底座盘问题。

候选落点：`BattleBoard` 地块生成、`TileVisualsConfig` 变体、`BattleViewFactory` 贴地材质与层序。

### 4.3 材质与光照一致性

- 统一主光、柔和补光与轮廓光关系；只有主光承担必要的实时阴影。
- 单位和建筑共享光向，避免各自打光形成拼贴感。
- 检查材质的 smoothness/specular，防止金属、墙面、屋顶、地面出现不合理塑料反光。
- 夜间改变环境色温与暗部层次，不简单把全场压黑。
- 窗光外溢和技能短促光优先对象级实现，避免灯光数量随单位/窗户增长。

## 5. P1：技能与单位动作手感

### 5.1 技能四段演出

每个技能按同一节奏拆解，允许不同技能省略非必要段，但不能缺少命中反馈：

| 段落 | 画面职责 | 候选表现 |
|---|---|---|
| 前摇 | 告知施法者与方向 | 姿态变化、蓄力、局部收缩光、起手轨迹 |
| 飞行 | 建立空间与时间预期 | 投射物、拖尾、轨迹、逐格到达 |
| 命中 | 给出最强但最短反馈 | 短促闪光、粒子、受击动作、伤害数字同拍 |
| 余韵 | 保留元素特征并收尾 | 焦痕、冰晶、水汽、碎屑、淡出 decal |

优先把“命中时刻”做准，不以单纯增加粒子数量替代手感。默认复用 `launchMs`、逐层拍和既有命令播放时序，不为演出另造结算时钟。

### 5.2 元素与反应形状语言

元素差异不能只靠换色：

- 火：扩张、碎裂、向上卷动。
- 水：环形波纹、柔和扩散、水汽。
- 冰：尖锐结晶、径向生长、碎冰。
- 雷：瞬时分支、短促频闪。
- 风：旋转流线、吸入或推离轨迹。
- 岩：厚重碎块、地面震荡。
- 草：藤蔓、叶片、连续生长。

蒸发、融化、冻结、超导等反应应有独立命中轮廓，使玩家不看名称也能区分。现有伤害数字配色和反应名称继续保留，不用新特效覆盖文字。

### 5.3 单位动作反馈

- 施法前摇、命中顿挫、受击后仰、死亡消散采用统一时长与节奏档。
- 近战补短距离冲刺或挥击轨迹，远程补起手、飞行与命中闭环。
- 冻结、灵魂、尸体、复苏在 tint 之外增加少量状态粒子或形态变化。
- 大招可使用轻微镜头推进或背景压暗，但不能遮挡目标和操作 UI。
- 新效果必须复用 `UnitView` 状态链，禁止各技能自行维护冻结/尸体/消散状态。

## 6. P2：镜头、后处理与 HUD

### 6.1 镜头反馈

- 普通命中不摇镜头；大招、破核等关键时刻才允许低幅短促冲击。
- 部署、升命、复苏可轻微聚焦，避免频繁自动缩放。
- 瞄准相机优先保证施法者、目标和落点同时可见。
- 震动幅度/频率应有关闭或降低选项，避免晕动。

候选落点：`BattleCameraController` 与既有瞄准跟随，不新建第二套相机权威。

### 6.2 后处理候选（须单独拍板）

若后续允许全局后处理，按以下顺序逐项验证：

1. 抗锯齿（优先解决立牌、建筑边缘与细线闪烁）。
2. 轻度色彩分级/LUT，统一白天、夜晚和地脉色彩脚本。
3. 克制 SSAO，服务脚底、建筑接缝和地形接触。
4. 只作用于高亮发光源的弱 Bloom。
5. 很轻的暗角；不得压暗棋盘边缘操作信息。

每项都要做同机位开/关对照和移动端性能检查，不打包一次性开启。

### 6.3 HUD 信息层级

- 普通伤害、暴击、反应、治疗、格挡使用不同尺寸与运动节奏，不只换颜色。
- 血条可增加平滑扣血与延迟损失条，使爆发伤害更易读。
- Buff 层数、持续时间、命座和装备角标位置统一。
- 瞄准范围、合法/非法落点、预计命中继续共享同一形状语言。
- 常态减少发光和边框，只在可操作、悬停、危险和命中时提升亮度。

候选落点：`BattleHud`、`BattleOverheadBars`、伤害数字与瞄准预览既有出口。

## 7. P3：性能与稳定验收

### 7.1 固定压力矩阵

至少覆盖：

- 白天、夜晚、地脉、迷雾。
- 2v2 多建筑、多单位与多常驻视频。
- 多技能同段、箭雨、光环 tick、伤害数字高峰。
- 反复部署/死亡消散、反复切换地脉和迷雾。

### 7.2 记录指标

- 帧率与帧时间峰值，不只看平均值。
- 粒子、投射物和伤害数字峰值及池化命中情况。
- 材质实例、临时 RT、视频解码器与常驻内存。
- GC 分配、shader 变体、draw call 与透明 overdraw。
- Android 实机发热、降频和长时间运行表现。

继续复用 `ActionRtPool`、`ResidentVideoBudget`、`IdleClipPrewarmPool` 和现有池化/预算机制；不为新效果另建无界资源表。

## 8. 推荐批次路线

每批独立拍板、独立验证、独立复测、独立提交，不一次性全量施工。

| 批次 | 内容 | 主要验收 |
|---|---|---|
| A. 视觉统一批（推荐首批） | 视觉规范、全单位接触阴影、地形接缝与过渡、材质光向统一 | 单位落地、无排序穿帮、地形不抢信息、普通单位零回归 |
| B. 战斗手感批 | 技能四段演出、元素/反应形状语言、受击/死亡/复苏反馈 | 命中同拍、元素可辨、冻结/消散/迷雾/地脉状态完整 |
| C. 镜头与色彩批 | 昼夜色彩脚本、镜头反馈、逐项后处理候选 | 白天/夜晚/地脉各自统一，操作信息不被压暗或震动干扰 |
| D. HUD 与性能批 | 信息层级、血条与数字反馈、压力矩阵和资源预算 | 高峰可读、移动端稳定、无无界资源增长 |

## 9. 每批交付验证模板

1. `unity_editor.refresh` 无新增 C# 错误。
2. 相关编辑器离线自检通过；涉及 shader 时编译使用变体。
3. 同回放、同机位输出增强前后静态对照。
4. 用户运行时复测：常规战斗、白天/夜晚、冻结、尸体灰、受击闪红、消散、迷雾、地脉、普通立牌零回归。
5. 涉及技能高峰时追加 2v2 多建筑与多单位压力场景。
6. 用户复测通过前不提交；提交时排除其他会话与工具自动产生的非本批改动。

## 10. 风险与禁止捷径

- **只做静态截图**：无法发现时序、状态残留和显隐问题，禁止作为唯一验收。
- **全场统一提亮**：会抹平材质和光照层次，正立面补光类需求仍优先局部实现。
- **透明排序手排一切**：高度与遮挡关系优先由深度管线裁决，层梯只用于合适的半透明介质。
- **每窗/每技能一盏实时灯**：灯光数量随内容增长，禁止无预算扩张。
- **各技能自建状态链**：冻结、尸体、消散、迷雾和地脉必须继续由既有单源驱动。
- **先堆素材再定风格**：先确定基准画面与视觉规范，再批量生产素材。

## 11. 开工前待拍板

1. 是否按推荐先做 **A. 视觉统一批**。
2. 美术目标是否采用“原神式鲜亮色彩 + 清晰克制的战场信息层级”。
3. 是否允许后续 C 批逐项评估全局后处理；不允许时保留局部灯光/材质路线。
4. 性能验收以哪些设备为基准，帧率目标与压力场景由实测后拍板。
5. 首批是否同时包含全单位接触阴影与地形接缝，或先只做接触阴影作为小样验证。
