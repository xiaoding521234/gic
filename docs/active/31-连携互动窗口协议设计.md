## 1. 规则输入（docs/07 既有设计，本稿不改规则）

**稻妻连携（软窗型）**：①执行阶段中达成特定条件→获 1 勾玉+连携按钮出现 ②**现实 2 秒**内可点击，超时=放弃（勾玉保留）③点击→消耗 1 勾玉发动 ④发动后按存量勾玉可续开窗（新窗重新计时，同一次触发至多追加 2 次=合计 3 次）⑤勾玉至多存 3 ⑥**阶段推进等待**：进入下回合选择阶段前先等 2 秒窗走完。
**璃月契约谈判（硬停型）**：执行阶段时停 3 秒（协议 Pause/Resume 即为此预留）。
**时间轴口径（docs/04 §4.1）**：连携窗/契约时停=「现实秒制」，只在执行阶段即时演算时轴上流动；**交互窗时间不可被"提前完成"压缩**（active/22 门控约束——播放器压缩片间等待仅对纯演算片生效，窗口计时与 _playbackSpeed 无关）。
**配额**：连携=被动型即时行动，消耗勾玉不占每回合行动配额（docs/05 §5.0 拍板清单不含连携；与部署/延奏的"占配额"区分）。

## 3. 协议设计四件套

### 3.1 窗口命令族（Host→Client 新增两条；软窗旁路不进 Segment 流）

```
InteractiveWindowOpen   // {windowId, windowKind(Renkei/Contract), ownerId, durationMs, context}
InteractiveWindowClosed // {windowId, result(Expired/Consumed/Cancelled)}——统一关窗信令（清按钮/停计时）
```

- **窗口是实时信令非演算内容**：不塞进 Segment 命令块（片命令=演算产物；窗口=演出期间的并行 UI 态），走独立消息——BattlePlayer 路由到事件、HUD 消费。
- 契约时停走 `Pause/Resume` 硬停链（预留号启用）；连携走软窗链（演算照走、窗口并行）——**软窗/硬停按机制分型**，不统一方案。
- 点击→`BattleSession.SubmitInstantAction`（复用通道零新消息），`ActionData` 增 `windowId` 字段（Host 对账用）。

### 3.2 窗口时钟权威（三案，推荐 B）

| 案 | 机制 | 评价 |
|---|---|---|
| A | Host 计时+网络余量：Host 起窗自计时 duration+slack | 简单；但 LAN 下玩家屏幕上的 2 秒被网络吃尾巴，slack 两难 |
| **B（推荐）** | **Client 计时+过期上报**：客户端到点自动发 `InteractiveWindowClosed(Expired)`；Host WaitCondition 等 Open 窗的终态回执（Consumed/Expired），不自计时 | 所见即所得（屏幕 2 秒=真 2 秒）；本地双开与 LAN 同语义。**作弊面由 Host 硬上限兜底**：Closed/action 到达时刻 > Open+duration+最大容忍（如 +1s）=丢弃+Warn——客户端谎报晚过期进不来 |
| C | 双钟折中 | 复杂度无收益，弃 |

配套：客户端窗口计时用**unscaled 实时**（不受 _playbackSpeed 压缩——§1 门控约束）；输入锁冻结语义见 §7 拍板 3。

### 3.3 插入粒度（连携=软窗片边界插入起步）

- **连携（软窗）**：点击→即时行动入队→**下个片边界插入结算**（独立插入块，现状机制零增量）。点击→效果延迟=当前片剩余播放时长（~0.3-3s）。**增强备选 A′**：窗口开启期间 Host 把在途片提前收尾/细化切片（软窗语义保持，延迟压缩）——实测手感不达标再上，协议不变。
- **契约（硬停）**：Pause→收输入→Resume，效果紧随确认（延迟≈RTT）——预留号直接启用。
- 不采用"连携也时停"统一案：稻妻规则「2 秒内随时可点击+演算照走」=软窗语义，时停违背规则本体。

### 3.4 过期语义（即时行动队列收口，销 docs/11 既有行）

- 即时行动带 `windowId`：窗口关闭（Expired/Consumed/超硬上限）后到达的同窗 action=**丢弃+Warn**（作弊口封死）。
- 每窗连发上限（稻妻=3 次）：Host 按 ownerId+windowId 计数，超限丢弃。
- **Selecting 期/窗口外 SubmitInstantAction 一律丢弃**（现行「滞留至下回合片边界」口径废除——连携窗只在 Resolving 开，窗口外即时行动无合法来源；docs/11「即时行动队列过期语义」行随 R-1 勘正销案）。

## 4. 勾玉状态真源

- `PlayerResourceState` 新字段 `renkeiTokens`（玩家局内资源，快照下发权威）+ 命令增量（专用 StatKind 或独立命令，对齐 B6d 摩拉/体力模式）。
- 获得产出=连携触发条件命中（Host 演算期产出——通用条件原子随稻妻首单位定，先留「受击获得」类接口）。
- 显示=连携按钮角标计数（**不入手牌**——勾玉非卡牌资源；左上角 chip 备选见拍板 5）。

## 5. 客户端互动子系统（职责划分）

- **HUD（Resolving 期新组件）**：连携按钮+倒计时环（订阅 WindowOpen/Closed 事件）→点击 `SubmitInstantAction`；「演算照走」=片命令照常推流播放，窗口 UI 并行浮层。
- **BattlePlayer**：两新消息路由到事件（表现层旁路，不动片播放循环）。
- **TurnFlowController**：WaitConditions 扫描实装（末片后、回合结束效果后、广播 TurnEnd 前——active/22 §2 步骤 4 顺序）；硬停路径挂 Pause/Resume。
