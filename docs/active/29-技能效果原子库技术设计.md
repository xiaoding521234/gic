> 2026-09-25 立项（用户拍板「开始B」）。定位：把技能效果产出从「每形制一个 C# 技能类」升级为「效果原子配置组合」——加技能=纯配置，程序员只扩原子库。
> 决策归属：docs/18 决策九（B 方向拍板）；信源=.codely-cli/webrefs/skill-timeline-system/EGamePlay_src/（一手源码全读）。
> 命名沿用惯例：时轮（SkillTimeline）→ 本系统命名**技能效果原子（SkillEffect）**。

## 1. 立项依据（对照评估结论）

现状=「程序员工厂模式」：安柏战技/箭雨/凯亚霜袭/延奏各自手写 `ResolveEffects`——数值/时间已数据化，**效果产出仍硬编码**。王者级=「效果原子+触发器」：技能=效果列表（策划拼积木），加新技能零代码（除非新形制）。

## 2. 业界参照对照表（EGamePlay 一手源码，2026-09-25 全读）

| EGamePlay 组件 | 结构 | GIC 对应物 / B 方案落点 |
|---|---|---|
| AbilityConfigObject.Effects | `[EffectAttribute]` 注册的多态效果列表（Odin 序列化进 SO） | → SkillData.effects（**union 平铺**，勿用 SerializeReference 多态——见 §4-D1） |
| Effect 子类族 | DamageEffect/CureEffect/AddStatusEffect/AttributeModifyEffect/ActionControlEffect/ShieldDefenseEffect | → SkillEffectConfig union 载荷按 kind 解释（SkillTimelineClip 先例） |
| TriggerActions（触发点） | 触发类型（执行触发/自动触发）→ 行动（赋效果/触发新执行体） | → 触发时机枚举 OnCast/OnHit/OnVanish 挂效果组（§4-D3） |
| ActionEventData.FireType | 开始/碰撞单次/碰撞多次/结束 | → 回合制退化：OnCast（片初瞬发）/OnHit（每命中）/OnVanish |
| TriggerNewExecution | 技能链：事件→加载另一 ExecutionObject→继承目标再执行 | → 技能链触发（变奏/命座触发器框架位，B-3） |
| CollisionShape×CollisionMoveType | 形状库（圆/盒/扇形）×弹道库（选中方向/目标飞行/前方飞行/路径贝塞尔/固定） | → SkillJudgmentKind 扩容按需走（B-3，勿预设） |
| SkillEffectType（策划效果类型表） | 伤害/治疗/施状态/移状态/数值修改/护盾/叠层标记 | → 原子 kind 枚举的命名参照 |
| ExecutionObject | 时间轴 SO | → SkillTimelineAsset（已有，B-S1 落地，**不动**） |

**分工边界（三条真源不动）**：时轮=时间与判定规格（WHERE/WHEN）；参数表=数值（HOW MUCH）；**效果原子=效果产出声明（WHAT）**——三者组合成技能，各自单一真源。

## 3. 数据模型（B-1 核心）

```csharp
// Data/Battle/Skill/SkillEffectConfig.cs（新，union 平铺风格=BattleCommand/SkillTimelineClip 先例）
[Serializable]
public class SkillEffectConfig
{
    public SkillEffectTrigger trigger;     // OnCast=0 / OnHit=1 / OnVanish=2
    public SkillEffectKind kind;           // Damage=1 / Heal=2 / ApplyBuff=3 / AttachElement=4 / EnergyGain=5 / TriggerSkill=6 / MoraPlunder=7（2026-09-25 B-3 首扩——首个资源类原子）
    // 载荷（按 kind 部分有效；数值一律引用 SkillParamKey，勿复制字面量——防双源）
    public SkillParamKey paramKey;         // 数值取参键（Damage→SkillParamKey.Damage 等）
    public ElementType element;             // 附着元素（AttachElement/Damage 用；0=施法者自身元素）
    public BuffType buffType;              // ApplyBuff
    public SkillName targetSkill;          // TriggerSkill（技能链：变奏/命座）
    public EffectTargetFilter targetFilter;// 作用目标筛选：命中目标/施法者/施法者队伍/目标队伍…
}
```

- SkillData 加 `public List<SkillEffectConfig> effects;`——迁移期空列表=走旧技能类（渐进双轨，零破坏）；**迁移已完成（2026-09-25 B-1）：四个手写技能类退役删除，现行分流=注册类→ConfiguredSkill（effects 非空）→UnimplementedSkill 占位（SkillFactory 三层）**；非空=走效果原子管线。
- 触发时机编译点：OnCast→SkillExecutor 施放时（替代技能类 ResolveEffects 主体）；OnHit→SkillHitResolver.Hit 遍历；OnVanish→ProjectileResolver 消散点（采集类技能，B-3 接）。
- **效果原子只做声明，产出仍编译成 BattleEffect**——应用/合并/对账/命令发射全链不动（TurnResolver/ApplyEffects/Merge*/Audit 零改）。这是与 EGamePlay（运行时 ECS 组件化）的最大差异：GIC 回合制片内快照结算不需要效果运行时实体，编译期展开即可。

## 4. 关键设计决策

- **D1 载荷形态=union 平铺**（推荐，勿用 [SerializeReference] 多态）：项目三条 union 先例（BattleCommand/Segment/SkillTimelineClip）+ Inspector 编辑按 kind 显字段已在时轮编辑器验证；SerializeReference 原生 Inspector 简陋且 Tuanjie 兼容性未验证。**已拍板（2026-09-25「全按推荐」，docs/18 决策九 D1；B-1 已落地）**。
- **D3 触发时机首批只做 OnCast/OnHit**：OnVanish（消散点效果）留 B-3；回合制无 EGamePlay 的实时碰撞多次触发，OnHit 的"同片同目标去重"沿用效应层合并口径（B6a/审查 R1 语义不变）。**已拍板（同上，决策九 D3；B-1 已落地——OnCast/OnHit 生效）**。
- **D5 迁移=渐进双轨**：effects 空→旧技能类兜底；现有四技能（安柏战技/箭雨/霜袭/延奏）迁 effects 后技能类退役；`WouldHitEnemyInDirection` 预判按判定 kind 泛化进工厂（LineProjectile=投射物圆柱形态/LineBurst=整线/距离段参数化）——**预判与结算同形态的纪律改为「按 kind 工厂保证」**，新直线技能不再需要覆写。**已拍板（同上，决策九 D5；B-1 已落地——四技能迁移完成、技能类退役、预判 kind 工厂化生效）**。
- **D7 Buff 不并入**：EGamePlay 的 Buff=Ability 统一抽象对 GIC 是大手术低收益（回合制计时实体语义已清晰），BaseBuff 独立维持。**已拍板（同上，决策九 D7——Buff 维持独立）**。
- **D8 触发器范围=首批只做 TriggerSkill 技能链**（变奏触发数据化，替代 AmberSharpshooterSkill.TriggerHenka 硬编码）；条件计数器（命座"每回合至多 N 次"）留 B8 命座批，B 只留参数位。**已拍板（同上，决策九 D8；TriggerSkill 链已落地——被替代的 AmberSharpshooterSkill 亦随 B-1 迁移退役删除）**。

## 6. 风险

- **原子粒度切错**（太细=配置爆炸，太粗=每技能又回特殊 case）→ 护栏=首批原子只覆盖现有四技能+三角色文档（凯亚延奏/芭芭拉全技能）反推，不预设未来；新需求出现时先问"能否用现有原子组合表达"，不能才扩枚举。
- **预判与结算形态漂移**（§63 同形态纪律）→ kind 工厂化把纪律从"每个技能类自觉覆写"升级为"工厂按 kind 强制同形"，反而消除漂移面。
- 序列化兼容：effects 为纯新增字段（List 默认 null=空），旧资产零迁移（docs/20 §1.6 纯新增不升版）。
