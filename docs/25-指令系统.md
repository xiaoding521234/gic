# 指令系统

> 2026-09-13 创建。开发者向的操作/作弊控制台：**设置页指令输入**与 **AI 派蒙 run_command 工具**双前端共用同一套指令实现。
> 定位拍板（2026-09-13）：面向开发者而非玩家——文案基调见 §5；无权限门（个人 Demo）。
> 陷阱索引见 §7；派蒙侧视角（两形态执行差异）见 docs/19 §6.5.4。

## 1. 架构

```
设置页指令行（SettingsScreen.Account.cs）─┐
                                         ├→ CommandSystem.Execute(命令行) → CommandResult{ok, message}
派蒙 run_command 工具（PetChatIntent.cs）─┘       │
                                                ├─ 命令实现：GameCommandsCore.cs（GIC.Framework：help/give/card/time）
                                                ├─ 命令实现：GameCommandsPet.cs（GIC.Pet：open/wish）
                                                └─ 回执分流：设置页→PopupManager.ShowToast；派蒙→Ok/Error JSON
```

- **注册 = `[GameCommand]` 属性反射扫描**（SkillFactory `[SkillAttribute]` 同款先例）：`CommandSystem.EnsureScanned()` 懒扫描首用触发，各模块新指令即扫即用、无中央接线；重名忽略并告警
- 执行异常统一捕获（handler 抛错→`指令执行出错: {e.Message}`），GICLog.Info 审计每条执行
- **派蒙侧**：LLM 只见一个 `run_command` 工具（参数=命令行字符串，工具描述=`CommandSystem.HelpText()` 自动生成目录）——旧 set_game_time/get_game_time/open_screen/auto_wish 四工具已并入；桌面 IPC 协议零改动（PetIntentIpc 转发 tool=run_command 原通道）；回执 message 为开发者格式，由 LLM 翻译成派蒙口吻（工具描述写明该指令）
- **桌宠本地拦截**（2026-09-13 快捷消息）：`start_game`/`qm` 两指令在桌宠进程内由 `PetLocalCommands` 拦截本地执行（游戏没开时 IPC 无消费者——start_game 恰要在没开时用得上；qm 编辑的 pet.json 是桌宠域数据）；其余指令照旧 IPC 转发。切分语义复用 `CommandSystem.TokenizeLine`
- 会话层本地工具（memory_update/do_action/search_knowledge）**不走 CommandSystem**，保持原状（docs/19 §6.5.4）

## 2. 指令集（2026-09-13 现状）

| 指令 / 别名 | usage | 描述 | 实现要点 |
|---|---|---|---|
| `give` / 给 | `give <物品名> [数量]` | 给物品（默认 1） | 物品名三路解析（§3）；数量位置自适应（`give 100 原石` 同认）；maxStack 自动钳制；存档走 ModifyNow |
| `card` / 角色 | `card <角色名>` | 获得角色卡（不计星辉） | count=0=复活（祈愿同款语义）、新卡=AddOwnedUnit、重复=已拥有；不动祈愿经济记账 |
| `time` / 时间 | `time [set HH:mm \| reset]（无参=查询）` | 查询/设置游戏时间 | TimeUtility 偏移（不持久化，重启回系统时间）；广播 OnGameTimeChangedEvent → 大厅背景/音乐刷新 |
| `open` / 打开 | `open <hall/map/backpack/wish/settings>` | 打开界面（中文同认） | 与手动完全同路径导航（回大厅→ExitToSceneAsync，勿直接 Load 叠层）；联机/战斗互斥拒绝 |
| `wish` / 抽卡 | `wish <次数> [角色名]` | 自动抽卡（160 原石/次，可选卡池） | 数字=次数/非数字=角色名自适应（2026-09-13 快捷消息"抽温迪卡池10次"）；卡池=WishScreen.EnsurePoolSelected(UnitName?) 三态（指定角色无池=反应通道报错不偷换池）；PetWishAutoRunner 全流程+反应通道（docs/19 §6.5.5）；原石同步预检+运行时守卫 |
| `quit` / 关闭游戏 | `quit` | 退出游戏（自动存档） | QuitDelayer 延迟 0.3s（同帧退出会吞桌宠 IPC 响应回写）；存档兜底+closePetOnExit 在 GameScene.OnApplicationQuit 自动处理 |
| `start_game` / 启动游戏 | `start_game` | 启动主游戏（桌宠侧有效） | **桌宠进程=PetLocalCommands 本地拦截**：GameWindowState 心跳防双开 + 启动自身 exe（窗口位置恢复=主游戏读 game_window.json）；游戏内执行=回执"游戏已在运行" |
| `qm` / 快捷消息 | `qm [add <消息> \| set <序号> <消息> \| del <序号> \| clear]（无参=列表）` | 快捷消息编辑（拖拽派蒙弹的气泡） | PetQuickMessages（pet.json quickMessages v7/v8，≤5 条，首次种子四条——前三条指令行+纯文本"你好"；v8 老档一次性补齐）；两进程同实现（游戏内=CommandSystem 注册 / 桌宠=PetLocalCommands 拦截），与派蒙对话 run_command 也走同一路 |
| `help` / 帮助 | `help` | 指令列表 | 注册表自动生成；派蒙工具描述同源 |

## 3. 解析规则（CommandSystem.Tokenize + EnumNameResolver）

- 输入归一：`/` 前缀可选、全角空格（U+3000）归一、按空白切分、命令词大小写不敏感、中文别名原样键
- 物品/角色名三路解析：枚举英文名（不区分大小写）→ 数值 ID（MC 风格，如 `give 1005`）→ `InspectorName` 中文名（反射，无本地化表依赖）
- 解析失败回执 `未知物品: x` / `未知角色: x`——不罗列合法值（§5 基调）

## 4. IDE 式补全（InputPopupDialog 命令模式）

**Suggest 语义**（`CommandSystem.Suggest(input)`）：
- 命令词阶段：按 name/alias 前缀匹配（空输入列全部 6 条）；前缀命中别名则补别名
- **尾随空格 = 进入下一参数阶段**（`give ` 即出物品列表、`give 原石 ` 进数量阶段收起）；首词非完整命令时落回命令词过滤（`gi ` 仍列 give）
- 参数阶段交各命令 Suggester（give/card=EnumNameResolver 名单前缀双向提示；open=界面名；time=set/reset）；行数上限 maxSuggestRows=8（prefab 序列化）

**交互**（suggester 参数非空即命令模式，普通模式行为零变化）：
- 开窗即种子初始建议（`Show` 末尾 `_shown` 置位后显式调用 OnCommandInputChanged——空输入不再空白等首字符）
- Tab=补全**当前词**（↑↓ 选中优先；尾随空格=追加语义，勿剪尾空格否则上一词被误替换）；↑↓=切换选中（焦点保持）；点击行=补全；Enter=执行整行；ESC=关闭（IClosable 既有路径）

**布局预算（2026-09-13 目检实证的硬约束）**：行高 44px、hint 单行预算 **~322px@size26**——
- hint=description 单行：prefab 中 hint TMP **NoWrap+Ellipsis**（单行硬保证+超宽 … 截断兜底）
- "别名「X」·"前缀**不放 hint**（别名发现走 help 目录与中文前缀输入）
- 主词**中文优先**：空输入浏览态/中文前缀→中文名+英文对照 hint；英文前缀→英文名
- 行结构/样式全在 `InputPopupDialog.prefab`（SuggestPanel + SuggestRowTemplate；样式在 prefab 序列化，运行时只实例化+设文本——新建 MonoBehaviour 须独立同名文件，docs/14 §49）

## 5. 文案基调（2026-09-13 用户拍板"指令面向开发者"）

- **短、干、事实化**：`原石 +100（持有 16100）`、`未知物品: x`、`已拥有: 温迪`、`开始自动抽卡 ×3`、`原石不足: 需 480，持有 100`
- 错误提示不罗列全部合法值、不写"您可以…/支持…如…"教程腔、无拟人化语气词（补全与 help 本身就是发现手段）
- 派蒙的口吻由 LLM 转述层自加——回执层保持原始事实，两层解耦
- usage/description 双字段分工：usage 承载语法与枚举（可长），description 进补全 hint 与目录（受 §4 单行预算约束）

## 6. 新增指令 checklist

1. 静态方法挂 `[GameCommand(name, alias, usage, description)]`，签名 `static CommandResult Xxx(CommandArgs args)`；description ≤ 单行预算（§4）
2. 需要参数补全：同类静态 `XxxSuggest(int argIndex, string partial)`，属性 Suggester 字段填方法名
3. **存档变更一律 `SaveManager.ModifyNow`**（货币/进度=丢了会疼）；查询/流程类只读或走对应系统
4. 回执=CommandResult.Ok/Error，文案按 §5 基调；异常靠 CommandSystem 统一捕获，handler 内无需 try-catch
5. 派蒙无需额外接线（目录/工具描述自动更新，桌面 IPC 零改动）
6. 验证：Play Mode 断言（动存档必须快照+恢复，参照 docs/14 §50 所在会话测试法）+ 设置页目检（补全列表/Tab/回执/toast）
7. 归属：只依赖 Framework/Data → `GameCommandsCore.cs`；依赖 UI/Pet → `GameCommandsPet.cs`（GIC.Pet）

## 8. 派蒙聊天框 "/" 本地指令模式（2026-09-13 落地）

派蒙对话框（PetChatUIController，两形态共用）输入以 `/` 开头=本地指令行，与设置页指令行同款能力、与 LLM 对话互不干扰：

- **触发**：`Send()` 拦截 `text.StartsWith("/")` → `RunSlashCommand`（不经 LLM 直入）；Enter 走既有 onEndEdit→Send 路径无需另绑
- **补全**：`_inputField.onValueChanged → OnChatInputChanged`——/ 开头实时出建议列表（挂输入条顶边向上生长，随输入条 CanvasGroup 淡入淡出；程序化构建=本 UI 全程序化惯例；行高 40/主词 24+对照 20、NoWrap 单行同 §4 预算；上限 SlashMaxRows=6 窄窗从紧）；非 / 输入即时收起；closeInput/CloseChat 收起
- **键盘**：Tab=补当前词（↑↓ 选中优先）、↑↓=切换选中（焦点保持）；命令词阶段补全**保 "/"** 维持模式；尾随空格=追加语义（同 InputPopupDialog）
- **执行路由**：`session.RunCommandDirect → _toolExecutor`（游戏内=主进程直调 PetChatIntent；桌面=IPC 转发）——**与 LLM 工具循环同一执行器**，两形态零分叉；命令文本经 JsonConvert 编码进 run_command 参数
- **回执**：`PetChatIntent.ResultMessageOf` 解析 Ok/Error → `showBubble` **直出聊天气泡**（开发者格式原文，不经 LLM、不进对话历史、无口吻润色）；主动消息语义=停留 proactiveHoldSec 后自动淡出
- harness 断言（2026-09-13）：列表/Tab 两语义/斜杠保持/Send 全链（回执直出+清输入+面板收起+不进历史）/错误回执/收起路径 共 28 项全过
