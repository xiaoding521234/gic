# 统一消耗模型技术设计（C 批次）

> 2026-09-27 立项（用户设计输入「未来会有更多的技能，他们不一定消耗摩拉或体力，甚至可以是消耗酒，苹果等食物」→ 拍板「统一消耗模型」）。起因另有批3 复审发现：消耗管道按资源种类各写一条、非按「资源」统一抽象。
> 关联：docs/18 决策十五（立项拍板）、docs/29（效果原子库——消耗走「门槛+效应」非原子）、docs/05 §5.1（行动消耗规则本体）、docs/04 §4.1（低级单位不占配额不耗玩家资源）。
> 命名沿用先例：SkillTimeline（时轮）/ SkillEffectConfig（效果原子）——本系统英文载体名 `SkillCostEntry / ResourceGate`。

## 1. 现状与问题（2026-09-27 批3 复审盘点）

| 资源家族 | 真源 | 声明方式 | 门槛 | 消耗 | 客户端 |
|---|---|---|---|---|---|
| 元能（单位级） | UnitStats.Energy | ✅ 数据驱动（SkillParamKey.EnergyCost） | SkillExecutor 硬编码分支 | EnergyEffect(-, CategoryCost)→StatChange | 置灰 HasEnergyForSkill ✓ |
| 体力（玩家账户） | PlayerResourceState.stamina 池 | ❌ 规则写死（GetStaminaCost 按 SkillType 分档：Normal/Burst=10 其余 0） | StaminaGate（已泛化雏形） | StaminaEffect→StatChange | 置灰 HasStaminaForSkill ✓ |
| 摩拉（玩家账户） | PlayerResourceState.mora 池 | ❌ 仅部署扣费（直产命令，非技能链） | TrySpendMora | 部署直产 StatChange | chip ✓ |
| 物品（手牌条目） | HandCard.count（条目真源） | ❌ **完全空缺** | — | — | —（技能吃苹果无管道） |

既有地基：GainCard/LoseCard 对偶已备（2026-09-25 拍板，「使用/装备消费端后续批次接线」注记即本批）；SkillParamKey 已声明 MoraCost/StaminaCost（schema 跑在运行时前面）；ActionType.UseItem 已预留；BattleSimState.HasEnoughStamina/TrySpendMora 可复用。

根因：能量是数据驱动、体力是类型分档、摩拉无技能链、物品空缺——**四种资源四种写法**。行业定式：技能消耗=数据驱动的 (资源, 数量) 列表 + 统一资源门面路由（LoL/DOTA ability cost、炉石 cost 同模式）。

## 2. 设计

### 2.1 消耗声明（数据层，单源=技能资产）

`SkillConfig.SkillData` 新增字段（Data/Battle/Skill/ 新文件 SkillCostEntry.cs）：

```csharp
public enum CostKind { Energy = 1, Stamina = 2, Mora = 3, Item = 4 }

[Serializable]
public class SkillCostEntry
{
    public CostKind kind = CostKind.Energy;
    public ItemName item;   // kind=Item 时有效
    public int amount;
}
// SkillData.costs：List<SkillCostEntry>；空=无声明（双轨期回落旧逻辑）
```

- **加消耗=配条目零代码**（B-1 原子库同哲学）；costs 不上协议（客户端同包持有技能资产可直读，B7 LAN 不受影响——技能图标/名称已同链）。
- **双轨迁移（先例=B-1 D5 渐进双轨）**：costs 非空→新管道；空→回落旧逻辑（EnergyCost 参数 / GetStaminaCost 分档 / 移动常量直读）。C-2 全量迁移后回落代码退役。

### 2.2 ResourceGate 统一门（Host，StaminaGate 泛化收编）

`Battle/Flow/ResourceGate.cs`（StaminaGate 并入后退役删除）：

- `Has(sim, actor, playerId, cost)`：Energy=HasEnoughEnergy(actor, amount)（单位级）；Stamina=HasEnoughStamina；Mora=GetMora≥amount；Item=手牌条目 `FindHandEntry(cardId).count ≥ amount`。
- `Charge(sim, actor, playerId, cost, actionDesc, effects)`：登记对应消耗效应——Energy→`EnergyEffect(-amount, CategoryCost)`；Stamina→`StaminaEffect`；Mora→`MoraSpendEffect`（新）；Item→`ItemConsumeEffect`（新）。
- **门槛语义（既有拍板口径不变）**：不足=行动落空且不扣（先全查后全登记——多 cost 场景防「扣了体力才发现苹果不够」：SkillExecutor 先对 costs 全条目 `Has` 检查，全过后再逐条 `Charge`）；「先扣除，再加」（2026-09-25 拍板）结算序由既有元能两段应用扩展为「消耗类效应先于获取类」（ItemConsume/MoraSpend 归消耗桶）。
- **低级单位豁免推广**：体力豁免（星级<3 不扣玩家体力，docs/04 §4.1）推广到 Mora/Item——低级单位自主行动不消耗玩家任何资源；Energy 不豁免（单位自身资源）。
- **元能门槛=消耗值非上限**（B6a 拍板）口径随迁移保留。

### 2.3 新效应、命令与客户端链

- `MoraSpendEffect(playerId, amount)`（BattleEffect 新子类，TargetUnitId=玩家 ID——同 StaminaEffect 约定）：应用=ApplyEffects 分支 `TrySpendMora`；命令=StatChange(StatKindMora)（客户端 §78 玩家资源分流已备，chip 链零改动）。
- `ItemConsumeEffect(playerId, item, amount)`：应用=`LoseCard`（门槛先查+每玩家每回合单行动保证充足——同片同玩家双扣不可达；LoseCard 返回 false 仍 Warn 记账）；命令=**新 BattleCommandType.ItemConsume**（union 平铺：targetUnitId=玩家、metadata=itemName、value=amount；字段有效性矩阵注释同步更新）。
- 客户端：BattlePlayer 新增 ItemConsume 分流→本地快照 handCards 镜像条目 count 减/减尽移除→HUD 手牌对应卡角标刷新（货币角标链 RefreshHandCurrencyCards 同模式泛化）。
- **HUD 置灰链（预判/结算同形纪律，D5 先例）**：客户端 `HasSkillResources` 单源判定镜像 ResourceGate.Has 全条目（读 SkillData.costs+本地快照 energy/资源池/手牌条目），替换现有 HasEnergyForSkill∧HasStaminaForSkill 双查；技能键置灰随之数据驱动。
- 对账：MoraSpendEffect→StatChange(Mora)、ItemConsumeEffect→ItemConsume 登记 BattleEffectCommandAudit（未登记默认报警兜底已有）。

### 2.4 获得对偶（前瞻接口，C-3 实装）

`GainCardEffect`+ItemGain 命令（采集/产出类技能、资源点批用）：GainCard 装配期入口已备，效应化包装与 ItemConsume 严格对称（获得=有则加数量/无则加卡；命令=客户端手牌镜像增）。仅设计占位，不随 C-1 实装。

## 3. 批次切分与落地状态

- **C-1 管道落地（2026-09-28 完成，编译 0 错 0 警）**：SkillCostEntry schema+ResourceGate（收编 StaminaGate）+SkillExecutor 三门槛段→costs 循环+MoraSpend/ItemConsume 两效应+ItemConsume 命令+客户端分流+HUD 置灰单源化+审计登记。**存量技能走双轨回落，行为零变化**；AnyItem 语义随批实装（§6）。
- **C-2 存量迁移（2026-09-28 完成，编译 0 错 0 警，用户复检中）**：①撤临时验收条目②25 资产改动（Stamina +19：全 Normal/Burst/Move 技能；Energy +13：全 EnergyCost>0 技能）——**覆盖断言全绿**（配额技能 20 个 0 缺/EnergyCost>0 0 缺）③旧路径退役：GetStaminaCost 分档/GetEnergyCost 参数门槛/StaminaGate 类/移动常量直读/双轨回落全部删除，**ResourceGate 为消耗检查/登记唯一出口**（移动路径经 MoveExecutor.GetMoveCosts——**21/34 单位无 Move 条目=常量兜底是主路径**，规则真源=BattleMetrics.StaminaCostPerAction 保留一处）④AI 双脑门槛改 costs 感知（AIDebugBrain×4 处+LowUnitBrain×1——**AI 不感知 costs 的遗留就此销案**）⑤HUD 置灰简化（costs 空=免费）+ApplyMoveButton 单源化⑥UnitConfigEditor 校验行补 costs 守卫（Normal/Burst/Move 缺 Stamina/EnergyCost 漂移/AnyItem 配 Currency/Item 未指定/数量≤0）。
  - 迁移注意：**EnergyCost 参数保留**（描述渲染单源 SkillDescriptionBuilder 链不改）——运行时真源=costs，参数=描述，两者漂移由编辑器校验行拦截。
  - 行为保真推演：迁移按旧口径逐资产镜像（Normal/Burst=10/其余 0/参数元能值）——回归=零行为变化。
- **C-3 首个真实消耗技能**：随角色/技能批（酒/苹果消耗技能落地时端到端验收）；获得对偶（GainCardEffect）同批。

## 4. 验收与复检

- C-1 复检（交用户）：①存量全技能行为零变化（安柏/凯亚/芭芭拉各打一轮）②测试配置技能（如给某技能配 `Item 苹果×3`）——苹果不足=行动落空不扣且 toast/日志、充足=条目扣减+手牌角标即时刷新+对账零告警③技能键置灰按 costs 数据驱动。
- C-2 复检：旧路径引用全库清零扫描+资产断言（`git grep EnergyCost` 只剩本地化/描述渲染）。

## 5. 遗留与边界

- 掠夺摩拉（MoraPlunderEffect）/部署扣费维持直产命令先例（非技能消耗链，不入本模型——决策七「资源变更非单位效应」注记保留）。
- 物品「使用」行动（ActionType.UseItem）=本模型 Item cost 的单条特例（B8 物品卡使用批对接时收编，勿另起管道）。
- 货币身份三处硬编码（`Mora || Stamina`）判定为**永久两件套不单源化**（2026-09-27 讨论收敛：账户货币世界观即两种，原石局内=普通卡无池；`subType==Currency && maxPrepareCount>0` 派生式因原石备战上限 100 反例不成立）——本模型不动它。
- 时轮 aimMode 的目标声明轨道与 costs 无关（成本≠目标），勿混入。
- **AI 脑 costs 感知已随 C-2 实装（2026-09-28，原登记销案）**：AIDebugBrain×4 处（攻击/延奏/移动/走位估值）+LowUnitBrain×1 全部改 ResourceGate.HasAll costs 镜像（Host 同口径，含低级单位豁免）——AI 操控含物品消耗技能时会正确置灰不上交。

## 6. C-1 验收用例（临时，验收后撤销）

- 2026-09-28 用户指定：**凯亚霜袭（Kaeya_Frostgnaw）临时声明 costs=[Stamina×10, AnyItem 饮品×1]**（「额外消耗」=Stamina 与物品并列声明——costs 是完整消耗声明，双轨下只配物品会丢战技原有体力消耗）。
- **AnyItem 语义定版（2026-09-28 用户纠偏「不能因为现在饮品只有蒲公英酒而写死，要求的是任意饮品」——同类任意已实装，非触发点后置）**：
  - **跨同类条目凑足**：3 蒲公英酒+2 果汁可付「任意饮品×4」；
  - **原子性**：防御路径未足额=GainCard 回滚已扣部分（获得/失去对偶）→零命令——支付要么全额要么不支付；
  - **确定性**：按手牌列表序逐条扣减，零随机（回放/联机安全）；
  - **货币卡（摩拉/体力）不可被 AnyItem 匹配**：账户资源不经物品消耗链（LoseCard(货币)=动资源池属语义错误）；subType=Currency 恒不可匹配+Warn；
  - 实现分布：Schema（CostKind.AnyItem+subType 字段）/ResourceGate（CountAnyItems 聚合判定+CollectAnyItems **物化列表**——勿改回惰性枚举，扣减循环内 LoseCard 移除条目=集合修改异常）/ItemConsumeEffect（双模式+Consumed 明细）/TurnResolver（原子扣减+按明细逐条发射 ItemConsume）/审计（按明细查存在性）/HUD（HasHandAnyItem 聚合镜像置灰）。
- 验收点：①无饮品=战技键置灰+Host 提交落空不扣费；②有饮品=放技能扣 1 饮品（多品类时按手牌序扣首个）+手牌角标即时减+体力照扣 10；③共享此技能资产的丘丘人（低级单位）=豁免不扣饮品（星级判定）；④对账零告警。
- 复盘注意：霜袭同时被 AIDebugBrain 上交——AI 凯亚无饮品会落空（上条遗留的已知表现，验收期间忽略）。
- 撤销=清空 Kaeya_Frostgnaw.costs（一条编辑器脚本，验收通过后执行）。
