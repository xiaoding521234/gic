## 1. 即时制时间模型（决策九十五，取代旧「三层时间模型」）

模拟核心=**20Hz 固定 tick 状态机**（RTSFlowController：accumulator 累加器+每帧步数 clamp；1 tick=1/20 秒，定点整数纪律——位置 1 单位=1cm、时间全 tick 计数）。

| 时间语义 | 判定粒度 | 语义 | 读取状态 |
|---|---|---|---|
| 行动结算（瞬发效应） | 单行动 | **快照结算**：读行动前快照、独立结算、效应统一应用（旧「片内快照」的秒化等价物） | 行动前快照 |
| 命中判定 | tick | 投射物时间轴分段求交（三源轨迹：ActiveMovers A* 外推/静止）；移动中单位处于连续插值位置可被中途命中 | 逐 tick 连续位置 |
| 衍生链 | 行动内 | 因果序：延奏→变奏等衍生效果在行动块内部串行展开 | 块内继承 |

- **攻速片/片间硬先后随回合机退役**：行动上交即校验即结算；同拍内多行动按上交序逐个结算（后行动读到先行动结算后的状态）
- **秒拍/效果拍**（TurnResolver.ResolveSecondBeat）：秒拍族（发放/Buff 计时/泡湿/灵魂衰减/采集/建筑）每 1 秒、效果族（Buff tick 伤害/光环/建筑效果）每 2 秒（EffectBeatTicks=40——「时间翻倍」拍板）
- **死亡判定**：效应统一应用后判（同拍互杀=同归于尽）；跨行动击杀=后续行动落空（「未知单位/已死亡」防线）；枚举序（unitId 升序）仅决定命令排列与写-写冲突合并依据，不影响结算结果

## 2. 即时结算流（取代旧「执行阶段分步流式演算」）

结构对标王者荣耀的服务器权威（客户端实时表现+输入随时上交），tick 粒度=真 tick（旧文的「攻速片」为回合制前身——**2026-09-28 视图层定性勘正仍成立**：客户端形态=互动回放，连携/契约的介入协议=拍板 6 延后随实装势力从零设计）。

**TickAdvance 每拍窗口序（Host 侧，RTSFlowController）**：
1. **移动推进**：RTSMovementSystem.AdvanceTick（整数速度累积器+waypoint 消耗+圆碰撞检测）→到达/被挡收尾交 TurnResolver.ResolveMoveArrivals（途经采集+被挡位置校正命令）
2. **AI 节拍（%10=每 0.5 秒）**：探索账本同步（RevealFog）→眷属脑+伙伴脑批演算（ResolveAiActions，同批同段=批前快照）→配额脑（场景件）沿 Selecting 事件驱动同频决策
3. **秒拍（%20=每 1 秒）**：ResolveSecondBeat（秒拍族+效果拍族 %40）→快照广播（对账/自愈）→战斗时钟+1 分钟→desync hash 落盘
4. **submit 窗**：本拍内上交的行动（玩家/配额脑/购买）按序即时结算——校验链（灵魂/归属/建筑/眷属防线）在 RTSFlowController.OnSubmitAction 收口

**门控与约束（ack 门控随回合机退役）**：
- **Host 永不等客户端**（旧铁律退役）：命令流带 startTick 客户端按绝对时刻播，跟不上由渲染插值与快照自愈（>15cm 拉回）自然吸收——段直发无 ack
- 单人局浏览暂停（N0）=tick 暂停位（SelectTimerPaused——BattleSession 门控 IsSoloHumanGame）；多人局不冻全场
- 即时行动（购买 BuyCard）不落队列——即时通道即时结算，产出独立迷你段（sliceIndex=-1，客户端不派生相位）

**行动级快照结算**：
```
effects = []
foreach action in submitted.actions（上交序）:
    effects += action.Resolve(stateBeforeAction)   // 只读行动前快照
state = Apply(state, effects)                       // 效应统一应用
segment = Serialize(effects)                         // 产出段（带 startTick）
```
写-写冲突（伤害/治疗合并 HP 天然成立；同格碰撞圆重叠等）走确定性合并规则（§7.4 / docs/11）。

**瞬发×移动并存**：快照结算管瞬发效应，移动经 tick mover 动态展开；投射物在移动展开的时间轴上分段求交（§11 延续+P3 cm 化：ActiveMovers 轨迹外推/静止快照两源+毫米协议命中点）。

## 3. 数据模型

### 3.1 ActionData（行动上交）
- `ActionType { Move, Skill, Burst, DeployUnit, DeployBuilding, UpgradeConstellation, BuyCard, UseItem, EquipItem, FactionSkill, OpenChest, Pass }`
- 字段：playerID / unitId / ActionType / SkillContext 型参数（目标格/方向/目标单位）/ **即时制扩展（决策九十五）**：`targetX/targetZ`（cm 移动目标——Move 双轨主道，双零回落旧 direction+moveMagnitude 桥）、`deployX/deployZ`（部署自由落点 cm）、`aimX/aimZ`（千分瞄准向量=任意角真值，双零走 AimVectorOf 桥）、`submitTick`（行动产生 tick=回放排序锚）、`moveContinuous`（真摇杆标记：aim 双零=停止信号）/ cardId 等，按类型部分有效
- ForceData（推力语义，docs/05 §5.3）留作强制位移/月矩力批载体

### 3.2 BattleCommand（单命令，union 风格）
- `BattleCommandType { Move, Damage, Death, Heal, ApplyBuff, RemoveBuff, ElementAttach, Reaction, StatChange, Summon, Effect, UI, Pause, Resume, ... }`
- 字段：type / actorUnitId / 片号 / 片内序 / **visibilityScope（预留，切片恒全可见）** / 平铺 payload（目标格/方向/数值/位移路径…）
- 命令粒度 = 一次原子视觉事件（沿用 docs/18 决策一）

### 3.3 Segment（段命令块）
- `{ turnNumber, sliceIndex, startTick, insertedInstantAction 标记位, List<BattleCommand> }`——**startTick=段产生时刻（决策九十五）**，客户端按绝对时刻播；sliceIndex=段唯一序（ack 键语义退役）
- 对局输出 = Segment 流（逐段直发无 ack 等待；购买迷你段 sliceIndex=-1）

### 3.4 BattleSnapshot（每秒全量——即时制改「每选择阶段头」为秒拍）
- `{ turnNumber, List<UnitState>{ unitId/**连续位置 posX/posZ（cm）**/HP/元能/**战技/爆发 CD 剩余 tick**/元素附着/Buff 列表/尸体态/阵营/装备四字段 }, 双方资源（摩拉/体力/手牌/牌库）, resourceNodes, terrainKeys }`
- 快照=对账/自愈通道（客户端非移动中漂移 >15cm 拉回）；地形全量仅对局开始发一次，地形变化走 TerrainChange 增量命令

### 3.5 序列化
- **JSON**（JsonUtility；平铺字段适配其序列化能力，不用 Dictionary——列表+枚举索引代替）
- `IBattleSerializer` 接口隔离，将来可换二进制且不改调用方
- 调试友好优先：片级消息肉眼可读

## 4. 逻辑层载体与双端形状

- **逻辑 Unit = 现有 MonoBehaviour 组件容器**（Unit + 8 组件 + Skills/Buffs），仅 Host 场景实例化（可隐藏层），零重构复用 UnitStats/UnitElement/UnitMoveable/UnitStatus
- **UnitView = 双端同构表现层**（客户端与 Host 显示侧同一套代码）：Snapshot 建场、Segment 驱动动画，不持逻辑状态
- 本地/单机（B1-B6）：Host 与 Client 同进程，走 IBattleTransport-Local 直通；B7 LAN：同一接口换 Mirror 实现，上层零改动
- 铁律：**战斗逻辑不走 EventBusHub**；战斗内消息只走 IBattleTransport 专用通道

## 6. DamagePipeline

核心公式（docs/05 §5.6）：
```
最终伤害 = (攻击力 × 攻击百分比 + 额外伤害) × (增伤 − 免伤) × 易伤
易伤 = 防御 ≥ 0 ? 100/(100+防御) : 1 − 防御/100
```
Phase hooks（B1 预留点位，B2-B4 接线）：
1. PreDamage：命中判定 / 元素反应预判（B4）
2. 乘区修改：Buff/技能/激化"+10"类插入
3. PostDamage：命中触发（获元能/吸血）+ 死亡判定

死亡判定：HP≤0 → 尸体态（UnitStatus 切换），碰撞/体积/属性/势力保留（docs/05 §5.4）。

## 7. 移动系统（决策九十五 P2/P3/P4 即时制化——连续空间）

### 7.1 判定链（旧「体积绝对层」随格容量退役；蓝图 §3.2）
1. **碰撞圆层**：单位=受击圆柱同源圆（**统一直径 0.5 格**、per-unit 覆写〔协议核心 0.8〕）——敌方存活/尸体/建筑=硬挡（停于接触前）；友军=可穿不可停；**旧「单格体积上限 3」退役**（密度由碰撞圆自然限制）
2. **地形层**：TileType 标签（AllowWalk/AllowFly/WaterTerrain）按 ForceType 判定——A* 寻径层保证，推进期不再逐格判
3. **路径**：RTSPathfinder tile A*（静态地形+尸体格阻塞）→直线段 steering；目标不可达=ClampToNearestPassable 钳最近可走点

### 7.2 连续位置推进（RTSMovementSystem，tick 整数累积器）
- 每 tick 累积 speedCm/20 取步预算、按 waypoint 消耗（跨 waypoint 结转预算）；整数数学零浮点（确定性纪律）
- CheckBlocked：步进线段与硬挡圆接触判定（重叠回退接触前=Blocked 收尾+方向）
- **移动双形态**（蓝图 §3.3）：目标点（点击式点地走点不限距）/方向持续（真摇杆：按住行进/回中停/松手停——客户端周期重提交+moveContinuous 停止原语，2026-11-05 P6 落地）
- 被挡表现（P4-E）：位置校正命令（Move 空路径+hitX/hitY=cm 停点+MoveBlocked 元数据）→客户端停 tween+落位+撞墙弹回

### 7.3 同拍并存（旧「同片同步逐步结算」退役）
- 移动不再「轮」推进——每 mover 每 tick 独立步进；同 tick 多 mover 互不感知（快照独立结算语义延续）
- 相向对穿：双方在相邻 tick 内各自推进——接触判定（CheckBlocked）只对「敌方存活/尸体/建筑」生效，友军互穿保留旧语义

### 7.4 写-写冲突合并（沿用）
- 双元素同时附着同一目标 / 双推力同时施加：确定性合并规则待定（docs/11）
- 同段多伤害/治疗：数值合并，天然成立

### 7.5 位移类型
ForceType { Walk, Fly, Amphibious, Knockback, Pull, Jump, Teleport }：Pull 无视阻挡规则；建筑免疫强制位移。

## 11. 表现层：两态立牌与连续判定（2026-09-17 修订，B5 基线）

决策本体见 docs/18 决策二（2026-09-17 修订条目）；表现层时序与逻辑层解耦不变（逻辑即时结算，BattlePlayer 只管"何时播"）。~~2026-09-12 版"立牌队形 + 格子判定区"基线随队形方案一并作废。~~

- **立牌风格参考饥荒**：2D 立牌 + 底座投影；格子表现尺寸明显大于单位立牌（格感边界与重叠可读性服务）
- **同格单位重叠格心 + 两态模型（取代队形）**：
  - **执行阶段（演出态）= 收拢重叠**：全部立牌与格心重合；特效锚 `CellToWorld` 格心 = 锚所有单位，特效与立牌错位在根源上消除
  - **选择阶段（决策态）= 自动散开**：进入选择阶段即全部立牌散开展示（1 居中/2 并排/3 三角偏移布局复用为展开形态），底座正常显示；无需悬停/选中触发
  - 实现要点：`RefreshAllFormations` 改为阶段切换驱动（选择阶段开始→散开、执行阶段开始→收拢），不再每片重排；`GetFormationOffset` 从常驻队形改为展开布局
- **受击体 = 立牌圆柱（取代格子判定区）**：圆柱以底座圆盘为可视化（直径 0.42 起，容错 B5 目检定）；受击范围与格脱钩，视觉即判定
- **格 = 交互粒度，非判定粒度**：移动/占据/阻挡/技能范围声明按格；命中 = 投射物轨迹/特效形状 ∩ 圆柱；**移动中单位处于连续插值位置、可被中途命中**；移动速度/投射物速度为**逻辑常量**挂执行阶段时间轴（表现动画只是其可视化，Host 确定性不破）
- **命中分层**：接触判定（单位级，决定谁被打到）与效果作用域（技能声明：单目标/命中格 AoE/全体）解耦；格 AoE = 接触任一同格圆柱后按格声明生效（堆叠同心下与旧"格内全中"结果一致，向后兼容）
- **投射物真实飞行**：按弹道飞行（非逐格瞬移），命中 = **接触目标立牌圆柱之时**；效果作用域按技能声明（安柏战技 = 命中格 AoE）
- **弹射物路径与截停**：直线飞行型覆盖由 Host 逻辑即定（发射格 → 接触首个敌方圆柱截停，或 24 格上限消散——docs/05 §5.3）；命中时刻由 Host 判定后随 Segment 命令下发（发射格 + 命中点）。**连续坐标载体已定稿（2026-09-19 B5 落地）：千分定点字段 hitX/hitY（连续格心坐标×1000，格 c 的心=c+0.5，与 BattleBoard.CellToWorld 同系数）**——Damage 命令带命中点、无接触时发 Effect 命令（EffectKindProjectileVanish）带消散点，客户端零推算直读
- **B5 连续判定实现要点（2026-09-19 落地）**：①速度常量收口 BattleMetrics（投射物 8 格/秒、移动 0.18s/格、圆柱直径 0.42——判定与底座圆盘同源，视觉即判定）；②投射物技能产出 ProjectileEffect（只声明发射），ProjectileResolver 在同片移动展开后按时间轴分段求交（相对位移线性→二次方程小根=最早进入时刻），命中时刻平局按 unitId 升序（枚举序铁律）；③只有位置读命中时刻，HP/Buff 等状态仍读片前快照（同片并发基石不变）；附着读片内编译视图——同片多次命中的反应消耗/新附着随编译序对后续命中可见（2026-10-01 双蒸发修复，安柏双箭一层水双蒸发报障）；**投射物编译序=命中时刻序**（同日 WYSIWYG 拍板 docs/18 决策二十一——两遍法按 hitT+施法者 unitId 排序逐发编译，双单位多箭按到达顺序消耗 A1→G1→A2→G2；即时整线/箭雨 LineBurst 仍先于投射物编译，全量时序忠实待 R-1 子段化）；④格 AoE=命中时刻全体敌方连续位置四舍五入格==命中者所在格（接触判定与效果作用域解耦；堆叠同心下与旧"格内全中"结果一致，向后兼容）；⑤与 B4 格级近似的**行为差异**：同格堆叠敌方（贴脸）t=0 即接触命中（旧实现从相邻格起扫描、不打同格）；虚空格截断弹道（中心进入虚空格即消散）；⑥播放侧投射物/移动同 t=0 起跑（不吃命令 stagger），命中点/消散点定点驱动；箭矢正式素材/天降视觉/震屏闪白 → B5 表现美化后续波次
- **投放形态由技能数据驱动**：直线飞行（安柏战技）/ 整线天降斜落（安柏爆发）/ 单位指向无投射（延奏、契约——直接对目标单位生效，不经格子判定）；Segment 的 Damage 命令带 delivery 元数据或 BattlePlayer 按 skillId 查表（B4 定）
