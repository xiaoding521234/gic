# 祈愿系统

## 1. 概述

祈愿是玩家获取角色卡和物品卡的主要途径。采用**反应速度游戏**机制——卡道上的卡片随机滚动，玩家通过射击命中卡片来决定获得什么，而非预抽结果。玩家反应越快、越精准，越有可能命中高价值卡片。

## 2. 卡池配置

### 2.1 卡池结构

每个卡池由 `WishPoolConfig`（ScriptableObject）定义，包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| poolName | string | 卡池名称（如"风神卡池"） |
| description | string | 卡池描述（TextArea） |
| units | List\<UnitName\> | 卡池包含的角色列表 |
| items | List\<ItemName\> | 卡池包含的物品列表 |
| star5Weight | float | 五星出卡权重（默认1） |
| star4Weight | float | 四星出卡权重（默认4） |
| star3Weight | float | 三星出卡权重（默认10） |
| star2Weight | float | 二星出卡权重（默认30） |
| star1Weight | float | 一星出卡权重（默认55） |
| unitWeight | float | 角色权重（默认50） |
| itemWeight | float | 物品权重（默认50） |
| upgrade0Weight | float | 相遇之线升级0次权重（默认40） |
| upgrade1Weight | float | 相遇之线升级1次权重（默认30） |
| upgrade2Weight | float | 相遇之线升级2次权重（默认20） |
| upgrade3Weight | float | 相遇之线升级3次权重（默认7） |
| upgrade4Weight | float | 相遇之线升级4次权重（默认3） |

`WishPoolConfig` 关键方法：
- `RollStarLevel()` — 按权重累积抽星，返回 1~5
- `RollIsUnit()` — 按 unitWeight/itemWeight 抽类型
- `RollUpgradeCount()` — 按独立升级权重表抽取升级次数，返回 0~4（概率 = 权重 / 总权重，默认 40%/30%/20%/7%/3%）
- `GetUnitsByStar(unitConfig, starLevel)` — 返回指定星级的角色列表
- `GetItemsByStar(itemConfig, starLevel)` — 返回指定星级的物品列表

### 4.1 重复角色卡→星辉转换

抽中**已经拥有**的角色卡时，不增加该卡数量，而是转换为**星辉**（ItemName.Starglitter）：

| 星级 | 星辉数量 |
|------|---------|
| 5★ | 50 |
| 4★ | 25 |
| 3★ | 15 |
| 2★ | 8 |
| 1★ | 3 |

- 重复角色卡**不增加**背包中该角色的数量
- 星辉数量累加到存档中（初始为0）
- `starglitterEarned`（累计获取量，只增不减）同步累加，用于相遇之线计数
- 转换逻辑在 `WishManager.AddCardToInventory` 中实现，通过 `GetStarglitterByStar(int starLevel)` 查表

### 4.2 星辉雨动画

抽中重复角色时触发星辉雨动画：

- 从屏幕顶部随机 X 位置落下星辉图标（`masterless_starglitter.png`）
- 分批错落下落（每批 2~5 颗，批次间隔 0.15~0.35s），避免全部同时落下
- 每颗星辉：随机大小 40~60px、随机起始旋转、匀速下落、旋转下落
- 数量与真实获得星辉一致（每颗代表 1 个星辉）
- 下落持续 0.6~1.0s，落到屏幕底部以下才销毁（不淡出）
- 动画容器：`WishDrawRoot/StarglitterRainContainer`（全屏铺满，渲染层级在 Background 之上、CardTrack 之下）
- 性能优化：对象池 + 单协程批量管理（`List<StarglitterDropData>` struct 列表，无每帧 GC）

### 4.3 相遇之线

#### 4.3.1 触发条件

玩家每累计获取 **20 个星辉**（`WishManager.EncounterThreshold`），下一次射击从"命运之线"升级为"**相遇之线**"（金色线）。

**计数机制**（持久化到 `PlayerSaveData`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `starglitterEarned` | int | 累计获取的星辉总量（只增不减，与可消费的星辉余额解耦） |
| `encounterUsed` | int | 已使用的相遇之线次数 |

- 可用次数 = `starglitterEarned / 20 - encounterUsed`
- 进度条比例 = `(starglitterEarned % 20) / 20`
- `ConsumeEncounter()` — `encounterUsed++`，不扣星辉
- `RefundEncounter()` — `encounterUsed--`（5★卡无法提升时退回）
- **溢出处理**：星辉不消耗，基于累计总量计算。如一次获得 50 星辉 → 2 次相遇之线 + 余 10 进度

#### 4.3.2 相遇之线效果

1. 射击线变为金色（`encounterLineColor`，RGBA = 1, 0.85, 0.3, 1）
2. 射中卡后，**先 Roll 提升次数**（决定最终星级），不超过 5★ 上限：

使用 `WishPoolConfig.RollUpgradeCount()` 按独立升级权重表抽取（不复用 RollStarLevel）：

| 升级次数 | 权重 | 概率（默认） |
|:--------:|:----:|:------------:|
| 0 次 | 40 | 40% |
| 1 次 | 30 | 30% |
| 2 次 | 20 | 20% |
| 3 次 | 7 | 7% |
| 4 次 | 3 | 3% |

实际提升级数 = `Mathf.Min(RollUpgradeCount(), 5 - 当前星级)`，确保不超过 5★ 上限。

3. **5★ 无法提升**：返还相遇之线（`RefundEncounter`），按普通射击处理
4. **非 5★**：开始抖动+越来越亮动画（贯穿整个提升过程，即使 upgradeCount=0 也给玩家期待）
5. **原始卡**：立即播放特效（光带+光柱+边缘泛光）+ 判重复发星辉（`AwardDuplicateStarglitter`）
6. **逐级提升**（`upgradeCount` 次循环）：
   - 每升 1 级 → 从该星级候选列表随机选卡（`RollCardByStar`）→ 更新卡片显示（`Card.Init`）
   - 每级新卡：播放特效 + 判重复发星辉（`AwardDuplicateStarglitter`）
   - 如有重复：星辉雨 + 进度条更新
7. 抖动结束，清理发光叠加层
8. **最终卡入账**（`AddFinalResultToInventory`）— 只写入存档，不重复发星辉（每张展示卡的星辉已在展示阶段发放完毕）
9. 播放最终星级特效，卡片飞到左侧

> **星辉发放原则**：相遇之线流程中，每张展示卡（原始卡 + 每级新卡）都通过 `AwardDuplicateStarglitter` 统一判重发星辉。最终卡入账时调用 `AddFinalResultToInventory`（`awardStarglitter=false`），避免与展示阶段重复发放。

**代码位置**：`WishFlowController.PlanShot` → `PlanEncounterShot`（业务逻辑预计算）+ `WishDrawController.PlayStepsCoroutine`（动画播放）

#### 4.3.3 抖动+变亮动画

`CardShakeGlowCoroutine` — 多阶段抖动 + Additive 叠加层亮度变化：

- **多阶段**：每个星级阶段独立持续时间，`GetShakeDuration(star) = shakeBaseDuration * (1 + (star-1) * shakeDurationPerStar)`（asset 值：base=0.8, perStar=0.3，即 1★=0.8s, 5★=1.76s）
- **抖动**：`GetShakeIntensity(star) = shakeBaseIntensity + star * shakeIntensityPerStar`（asset 值：base=10, perStar=8，即 1★=18, 5★=50），阶段内随 `phaseT` 递增不减弱。抖动间隔 `shakeInterval = 0.025s`
- **变亮**：使用 `CardGlowOverlay`（Additive 叠加层），`GetMaxGlow(star) = glowBaseIntensity + star * glowIntensityPerStar`（asset 值：base=0.4, perStar=0.18，即 1★=0.58, 5★=1.3），smoothstep 缓动
- **不修改原始 Image 颜色**，叠加层 `Destroy` 即可清理，无恢复风险

#### 4.3.4 相遇之线冷却机制

- 相遇射击冷却固定 = `StarVisualConfig.BaseShotCooldown`（asset 值 0.3s），不随星级/提升次数变化（避免泄露提升次数）
- `_isEncounterAnimating` 标志阻断射击 + 冻结冷却条，直到动画完成
- 动画完成后重置冷却覆盖 hold+fly 时长

> **架构说明**：相遇之线的业务逻辑（Roll/Upgrade/AwardStarglitter）由 `WishFlowController.PlanShot` 一次性预计算，返回有序 `WishRevealStep` 列表。表现层 `PlayStepsCoroutine` 按序播放，不调用任何 WishManager 方法。冷却冻结由 `WishFlowController.CurrentState == Revealing` 统一管理。

### 4.4 星辉进度条

屏幕顶部居中显示星辉进度条（`WishDrawRoot/StarglitterProgressBar`）：

- 进度 = `(starglitterEarned % 20) / 20`
- 满时（有可用相遇之线）触发**抖动 + 流彩特效**（`ProgressBarGlowCoroutine`：Fill 位置抖动 + HSV 色相循环）
- 相遇之线射击中：进度条保持填满
- 进度条不消耗星辉，仅显示累积进度

## 5. 祈愿流程

### 5.1 整体流程

```
点击祈愿按钮 → 消耗原石 → 黑色背景遮屏 → 卡道开始滚动
→ 1.5秒倒计时（玩家射击或超时自动射击）
→ WishFlowController.PlanShot() 预计算全部业务逻辑（Roll/Upgrade/AwardStarglitter/AddToInventory）
→ PlayStepsCoroutine 按序播放动画（视频→特效→星辉雨→飞行）
→ 冷却（动画期间冻结，由 FlowController.State=Revealing 统一管理）→ 重复直到次数用完
→ 统一存盘 → OnWishComplete 回调刷新货币显示
→ 卡道隐藏 → 结果卡飞到屏幕中间横向展示 → 点击关闭
```

### 5.2 卡道机制

- 卡道位于屏幕中间竖向条带，卡片从底部移动至顶部
- 卡片**永远滚动**，射击和冷却期间不暂停
- 卡道上的卡片**随机生成**（`DrawRandomTrackCard`），与实际结果无关
- 每张卡按卡池概率随机选择星级和角色/物品
- 卡片紧密排列，无间隙（`cardSpawnInterval = 0.09s`，`cardMoveDuration = 0.75s`）
- 初始填满卡道（老虎机效果，一开始就有卡片在各位置移动）
- 空星级降星：某星级无候选时自动降星查找（`GetCachedUnitsByStar` / `GetCachedItemsByStar`）

### 5.3 射击机制

- 玩家点击鼠标左键射击（或1.5秒倒计时到期自动射击）
- 射击后发射"命运之线"：白色细线从屏幕右侧到左侧，0.2秒完成
- 相遇之线为金色（`encounterLineColor`）
- 命中卡道上**最接近屏幕中心的卡**（`FindCardNearestCenter`）
- **射中什么卡就获得什么卡**——读取该卡的 `Card.saveCardData` 作为实际结果
- 射击冷却：
  - 普通射击：`StarVisualConfig.GetShotCooldown(star)` = `baseShotCooldown + starLevel * cooldownPerStar`（asset 值：0.3 + star×0.15）
  - 相遇之线：固定 `StarVisualConfig.BaseShotCooldown`（0.3s），实际由 `_isEncounterAnimating` 控制
  - 5★过渡视频播放期间冻结冷却（`_isVideoPlaying` 标志）
  - 冷却期间卡道继续滚动，倒计时不计时

### 5.4 倒计时

- 每次射击有1.5秒时间限制
- 屏幕底部居中显示横条倒计时（类似血条）
- 倒计时从两侧向中心缩短（`localScale.x` 缩放）
- 超时自动射击

## 6. 特效

### 6.1 光带特效

- 射中卡片后在**卡片上**播放 `CardLightBandEffect`（`Card.PlayLightBand()`）
- 自定义 Shader `UI/CardLightBand`（Additive 混合），金色光带从左下到右上扫过卡面
- 持续0.3秒，使用 `LightBandGraphic`（自定义 `Graphic` 子类，不依赖 Sprite）

### 6.2 发光叠加层

- 相遇之线星级提升时，在卡片上创建 `CardGlowOverlay`（Additive 叠加层）
- 自定义 Shader `UI/CardGlowOverlay`（`Blend One One` 纯加色混合）
- `CardGlowOverlay` 继承 `Graphic`，创建时需包含 `CanvasRenderer` 组件
- `SetGlow(color, intensity)` 控制颜色和亮度，不修改原始 Image 颜色
- 抖动结束后 `Destroy` 叠加层 GameObject 即可清理，无颜色恢复风险

### 6.3 光柱特效

- 射中卡片后在**卡道中心**播放 `LightPillarEffect`
- 颜色 = `StarColor.GetStarColor(starLevel)`（1★绿/2★蓝/3★紫/4★橙/5★红）
- 光柱渲染在卡道**后面**（`SetSiblingIndex` 在 cardTrack 前），不遮挡卡片
- 包含：核心光束（过冲 1.08 倍后回弹）、6层光晕、地面闪光、30个上下双向飞溅粒子
- 光柱上升0.25秒后持续脉冲（速度3，幅度0.3），`GlowBurstCoroutine` 在0.5秒后调用 `Stop()` 淡出（0.5秒），总生命周期约1.1秒
- 粒子参数：数量30、速度1200、扩散1.5、时长0.8s，前60%保持高透明度，后40%平滑淡出

### 6.4 屏幕边缘泛光

- 射中卡片后在屏幕边缘播放 `ScreenEdgeGlow`
- 自定义 Shader 按到最近边缘距离计算 alpha
- `Play(color, starLevel)`：
  - `peakAlpha = min(EdgeGlowMaxAlpha * GetEdgeGlowAlpha(star), 1)` = `min(1.0 * (0.3 + star * 0.18), 1)`（1★=0.48, 5★=1.0）
  - `edgeWidth = GetEdgeGlowWidth(star)` = `0.08 + (star - 1) * 0.04`（1★=0.08, 5★=0.24）
  - `duration = EdgeGlowDuration`（0.8s），alpha 按 `1 - t²` 递减

### 6.5 星辉雨

- 参见 §4.2 星辉雨动画

### 6.6 五星过渡视频

抽到 5★ 卡片时（普通射击和相遇之线均触发），播放全屏黑屏过渡视频：

- **视频文件**：`StreamingAssets/mc.mp4`，1920×1080 RenderTexture
- **覆盖层**：全屏 `RawImage`，平时 alpha=0 不可见且 `raycastTarget=false`，播放时变白可见并拦截输入
- **预加载**：`StartWish` 时调用 `PreloadStar5Video()`（非阻塞 `VideoPlayer.Prepare()`），避免首次播放卡顿
- **播放**：`PlayStar5TransitionCoroutine` — 等待 prepared（超时 3s 静默跳过）→ 播放至结束 → 隐藏覆盖层
- **冻结机制**：`WishFlowController.CurrentState == Revealing` 统一冻结冷却倒计时，视频和动画步骤均在 Revealing 状态下播放
- **触发时机**：
  - 普通射击 5★：先播视频，再播特效+飞行（`Star5NormalRevealCoroutine`）
  - 相遇之线最终 5★：先播视频，再播最终特效（`EncounterRevealCoroutine` 第 8.5 步）
  - 相遇之线原始卡已是 5★（退款路径）：同样播视频
- **清理**：`OnDestroy` 释放 RenderTexture，`CleanupStar5Video`（OnDisable）停止播放+隐藏覆盖层

**代码位置**：`WishDrawController.Video.cs`

## 7. 结果展示

### 7.1 射击后

1. 被射中的卡从卡道移除，`SetParent(resultContainer, true)` 保持世界位置
2. 放大到 `holdCardSize`（280px，scale = 280/160 = 1.75x）在屏幕中心停留 `StarVisualConfig.GetHoldTime(star)` = `0.3 + (star-1) * 0.175` 秒
3. 飞到屏幕左侧竖向排列（`FlyToPosition`，缓出三次曲线0.4s），缩小到 `resultCardSize`（80px）
4. `HoldThenFlyAndCount` 协程追踪剩余飞行数，`ShowFinalDisplay` 等待所有飞行完成

### 7.2 全部抽完后

1. 等待 `PlayStepsCoroutine` 完成（`_flow.CurrentState == Finished`）
2. 统一存盘一次（`SaveGame`）
3. 触发 `OnWishComplete` 回调，通知 `WishScreenDraw.UpdateFateCount()` 刷新原石/星辉货币显示
4. 停止所有仍在飞行的 `HoldThenFly` 协程（避免位置冲突）
4. 卡道和倒计时隐藏
5. 左侧竖列的结果卡飞到屏幕中间，横向排列展示（`FlyToPosition`，缓出曲线）
6. `CanvasGroup` 淡入 0.3s
7. 玩家点击任意位置后淡出 0.3s，关闭祈愿，回到卡池界面

## 8. 氛围特效

### 8.1 概述

祈愿界面背景层包含两层 ParticleSystem 驱动的氛围特效，由 `WishAmbienceController` 统一控制。

Canvas 采用 **Screen Space Camera** 模式（非 Overlay），配 UICamera（Orthographic）使 ParticleSystem 可在 UI 层渲染。

排序层级：Background 子 Canvas (sortingOrder=50) < SmokeParticles (74) < ElementParticles (75) < 主 UI (100)。

### 8.2 元素粒子 (ElementParticles)

- **材质**：`Wish/ParticleAdditive` 自定义 shader（硬编码 `Blend SrcAlpha One`，绕过 URP shader GUI 重置问题）
- **纹理**：`SoftCircle.png`（64×64 径向渐变，Uncompressed RGBA32）
- **混合模式**：Additive（发光效果）
- **运动**：从右往左飘动，Velocity X=[-80,-40]，Y=[-15,15]
- **颜色**：跟随卡池角色元素颜色，切换卡池时通过 `GetParticles`/`SetParticles` 修改已存活粒子的颜色
- **加速效果**：切换卡池瞬间触发 `OnPoolSwitching()`，粒子速度 ×8 持续 0.6 秒，然后 0.5 秒 lerp 平滑减速回原速。发射率同步缩放维持密度恒定
- **预填充**：`StartWithPrewarm()` 用 `Simulate(duration)` 手动预热，粒子初始分布在屏幕各处
- 参数：rate=2/s, lifetime=25-35s, maxParticles=200, size=15-30

### 8.3 雾气粒子 (SmokeParticles)

- **材质**：`Wish/ParticleAlpha` 自定义 shader（Alpha Blend）
- **纹理**：`SoftCloud.png`（256×256，Perlin 噪声调制的云雾形，Uncompressed RGBA32）
- **运动**：从右往左缓慢漂移，Velocity X=[-60,-30]，Y=[-2,2]
- **范围**：屏幕底部 30% 区域（Shape position Y=-504, scale Y=432）
- **噪声**：Noise 模块（strength=15, frequency=0.1）使漂移有机化
- **淡入淡出**：Color over Lifetime gradient 中段 alpha=1.0，透明度由 startColor（alpha=0.02）单独控制
- **尺寸呼吸**：Size over Lifetime 曲线 0.2→1→1→0.5，缓入缓出
- 参数：rate=4/s, lifetime=15-25s, maxParticles=100, size=800-1600

### 8.4 WishAmbienceController API

| 方法 | 说明 |
|------|------|
| `StartAmbience()` | OnEnable 时调用，Simulate 预填充 + Play |
| `StopAmbience()` | OnDisable 时调用，StopEmitting（非 StopEmittingAndClear） |
| `OnPoolSwitching()` | 切换卡池瞬间调用，触发粒子加速 |
| `SetElementColor(Color)` | 设置元素粒子颜色，同时更新已存活粒子 |

### 8.5 注意事项

- `prewarm=true` 只对 `playOnAwake` 生效，手动 Play 不触发。需用 `Simulate(duration, true, true)` 手动预热
- `main.startColor` 只影响新粒子，已存活粒子需 `GetParticles`/`SetParticles` 修改
- Velocity X/Y/Z 三轴 curve mode 必须一致（同为 TwoConstants 或 Constant）
- 最终 alpha = `startColor.a × colorOverLifetime.gradient.a`，透明度只在一处控制
- Tuanjie 引擎 API 差异：`ParticleSystemGradientMode.Color`（非 `ParticleSystemCurveMode.Color`），`NoiseModule` 无 `dampen` 属性

### 10.4 关键设计决策

1. **反应速度游戏**：不预抽结果，玩家射中什么卡就获得什么卡。卡道卡随机生成，实际结果由 `Card.saveCardData` 读取并写入存档。

2. **卡道永远滚动**：射击和冷却期间卡道不暂停，保持视觉连贯性和紧张感。

3. **同一卡片飞行**：被射中的卡直接从卡道 `SetParent(resultContainer, true)` 转移到结果容器，保持世界位置不突变，先停留再飞到左侧。

4. **先算后播架构**（核心决策）：`WishFlowController.PlanShot()` 一次性预计算全部业务逻辑（Roll/Upgrade/AwardStarglitter/AddToInventory），返回有序 `WishRevealStep` 列表。`PlayStepsCoroutine` 按序播放，零业务调用。消除了旧架构中 6 个 bool 标志位（`_isActive`/`_isEncounterShot`/`_isEncounterAnimating`/`_isVideoPlaying`/`_totalShots`/`_shotsCompleted`）和业务逻辑与动画协程交错导致的时序 bug。

5. **状态机驱动冷却**：`WishFlowController` 状态机（Idle/Drawing/Revealing/Finished）统一管理流程。`Revealing` 状态冻结冷却倒计时，`OnRevealComplete()` 在 `PlayStepsCoroutine` 结束后调用，将状态转回 `Drawing` 或 `Finished`。

6. **相遇之线星辉发放分离**：每张展示卡（原始卡 + 每级新卡）通过 `AwardDuplicateStarglitter` 统一判重发星辉（只加星辉，不写入卡片列表）。最终卡通过 `AddFinalResultToInventory`（`awardStarglitter=false`）只入账不重复发星辉。普通射击路径 `AddResultToInventory`（`awardStarglitter=true`）入账时判重发星辉。

7. **相遇之线冷却固定**：相遇射击冷却固定为 `StarVisualConfig.BaseShotCooldown`，不随星级/提升次数变化，避免泄露提升次数信息。

8. **5★过渡视频时序**：视频步骤（`Star5Video`）在 `WishRevealStep` 列表中始终位于 `CardEffects` 之前，确保视频在一切特效之前播放。

9. **Additive 叠加层替代 Image.color Lerp**：抖动变亮效果使用 `CardGlowOverlay`（Additive 混合）而非直接修改 `Image.color`。不碰原始颜色，`Destroy` 即可清理，无恢复风险。亮度按星级递增，smoothstep 缓动。

10. **协程隔离**：`LightPillarEffect` 用 `_activeCoroutines` 列表管理自己的协程，`Stop()` 只停自己的协程不影响外部 `GlowBurstCoroutine`。粒子协程不追踪，由 `ClearSpawned` 销毁。

11. **Card.skipFadeIn**：卡道卡设置 `skipFadeIn = true` 跳过 `PlayFadeIn` 协程，避免对象池复用时 `OnEnable` 触发淡入导致半透明。

12. **性能优化**：
   - `LightPillarEffect` 的纹理和 Sprite 为 `static` 懒加载，所有实例共享。
   - `FateLine` 的 Shader 缓存为 `static` 字段，避免每次射击 `Shader.Find`。
   - `CardGlowOverlay` 的 Shader 同样 `static` 懒加载。
   - `StartWish` 时预构建星级→候选列表缓存（`Dictionary<int, List<UnitName/ItemName>>`）。
   - 存盘改为抽卡流程结束后统一调用一次 `SaveGame()`，而非每张卡都存盘。
   - 星辉雨单协程模式（`RequestStarglitterRain`），避免多协程共享 `_activeDrops` 导致重复更新。

13. **Partial class 文件拆分**：`WishDrawController` 按职责拆分为 7 个 partial 文件。业务逻辑提取到独立的 `WishFlowController`（纯C#）和 `WishShotResult`（数据类），表现层 `PlayStepsCoroutine` 统一播放器替代旧的 `EncounterRevealCoroutine`/`Star5NormalRevealCoroutine` 交错协程。

14. **OnWishComplete 货币刷新**：抽卡存盘后触发 `OnWishComplete` 事件，`WishScreenDraw` 订阅并调用 `UpdateFateCount()` 刷新原石/星辉显示。

15. **StarVisualConfig 统一参数配置**：所有星级视觉参数统一在 `StarVisualConfig.asset` 中配置，通过静态方法和属性访问。`ConfigManager` 启动时注入单例。
