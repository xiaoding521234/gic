# 输入系统

> 2026-08-14 定稿。三层重构演进：分散标志位 → 米哈游 InputLock 栈 → (owner, reason) 精确配对锁。
> 代码位置：`Assets/_Scripts/Framework/`（InputManager / InputLocks / KeyAction / KeyBindingEntry / IClosable）。

## 1. 总览

输入系统由三部分组成，职责分离：

| 部分 | 文件 | 职责 |
|------|------|------|
| 输入锁 | InputManager + InputLocks 门面 | 控制输入权限 — 锁生效期间暂停所有动作派发 |
| 可关闭 UI 栈 | InputManager + IClosable | 按下 CloseUI 时关闭最顶层注册的界面 |
| 按键绑定 | InputManager + KeyAction + KeyBindingEntry | 动作↔按键映射，支持玩家重绑定并持久化 |

InputManager 是 `[Component]` 纯 C# Manager（构造器注入 SaveManager，`Wargame.Context.Get<InputManager>()` 获取），由 GameScene.Update 驱动轮询。

```
GameScene.Update
  └─ Wargame.Update
       └─ InputManager.Update
            ├─ IsRebinding?         → return（重绑定监听中）
            ├─ IsInputLocked?       → return（任意锁生效）
            ├─ _skipNextFrame?      → return（重绑定完成防误触）
            └─ 遍历绑定表 GetKeyDown → OnActionTriggered 事件
                                        + 内置动作注册表（CloseUI → CloseTopUI）
```

## 2. 输入锁（InputLock）

### 2.1 数据模型

锁是 `List<(object owner, string reason)>` 条目，**不是栈**。三条 API 构成精确配对：

```csharp
InputLocks.Push(this, InputLockReason.Entering);  // 同 (owner,reason) 去重
InputLocks.Pop(this, InputLockReason.Entering);   // 按 (owner,reason) 移除，幂等
InputLocks.PopAll(this);                          // OnDestroy 兜底，清到泄漏锁时 LogWarning
```

| API | 语义 | 设计动机 |
|-----|------|---------|
| Push | 同 (owner,reason) 只入列一次 | 协程重入（上一次动画未完成又启动）无需先"补 pop" |
| Pop | 从最新向旧找匹配项移除，找不到静默 | 与栈顶无关 — push A → push B 后 pop A 不会误删 B；重复调用安全 |
| PopAll(owner) | 释放该持有者全部锁 | 锁泄漏 = 输入永久冻结，这是保险丝 |

### 2.2 锁的原因常量

全部定义在 `InputLockReason`（Framework/Input/InputLocks.cs），调用点禁止裸字符串：

| 常量 | 使用场景 | 持有者 |
|------|---------|--------|
| SceneTransition | 场景切换四个协程期间 | GameScene |
| SplashProtection | 启动前 0.3 秒防误触 | SplashScreen |
| Entering | Screen 入场动画期间 | 各 Screen |
| Closing | Screen 退场动画期间 | 各 Screen |
| MapEntering | 地图入场缩放动画期间 | MapZoomAndDrag |
| PopupEntering / InputPopupEntering | 弹窗淡入期间 | PopupDialog / InputPopupDialog |
| WishInProgress | 祈愿抽卡全程 | WishDrawController |

`HasInputLock(reason)` 按原因精确查询 — `GameScene.IsTransitioning` 与 `LoadSceneWithConfig` 守卫用它，不会被入场动画等无关锁误触发。`GetActiveLocksDescription()` 返回全部活跃锁（诊断输入冻结用）。

### 2.3 使用规则（新 Screen 必读）

1. **push 在协程/方法开头，pop 在协程末尾** — 中间不能有早退 return 路径（早退路径要么先 pop 要么把 push 放到守卫之后；参考 WishDrawController.StartWish 把 push 放在扣费成功之后）。
2. **协程被 StopCoroutine 中断时锁不会自动释放** — 两种保险任选：
   - 中断处显式 `InputLocks.Pop(this, ...)`（幂等，多调无副作用）
   - `OnDestroy` 中 `InputLocks.PopAll(this)` 兜底（推荐每个持锁类都加）
3. **场景卸载会杀掉协程** — Screen 被销毁时 OnDisable/OnDestroy 不会执行协程后半段，PopAll 是唯一保险。
4. PopAll 清理到锁时 LogWarning（"释放泄漏锁: Reason(OwnerType)"）— 出现该日志说明配对逻辑有 bug，按 owner 定位修复，不要习惯性忽略。

## 3. 可关闭 UI 栈（IClosable）

```csharp
public interface IClosable
{
    void Close();
}
```

- Screen 在 Start 注册 `RegisterClosable(this)`，OnDestroy `UnregisterClosable(this)`（后注册 = 更顶层）。
- 按下 CloseUI → `CloseTopUI()` 从顶向下关闭第一个非 null 的 IClosable。
- **无 GoBack fallback** — 没有任何注册界面时按 ESC 不做任何事（弹出场景返回必须走显式按钮/逻辑）。
- **无 CanClose** — 各实现在 `Close()` 入口自行检查（如 `if (isClosing) return;` 防重入）。
- 退场动画期间自己 push `InputLockReason.Closing`，动画末尾 pop 后调 `GameScene.GoBack()`。

## 4. 按键绑定

### 4.1 动作与数据

- `KeyAction` 枚举 = 玩家可绑定的抽象动作。当前：`CloseUI`（默认 ESC / 鼠标右键）、`Confirm`（默认 Space / Enter）。
- 每动作 2 槽位（主键 slot=0 / 副键 slot=1），存 `PlayerSaveData.keyBindings`。
- 查询单键用 `GetKey(action, slot)`（无分配）；`GetKeys(action)` 返回副本仅用于遍历。

### 4.2 派发与内置动作

动作触发走两条通道：
1. `OnActionTriggered` 事件 — 外部订阅（如 SplashScreen 订阅 Confirm）
2. 内置动作注册表 `Dictionary<KeyAction, Action>` — 构造器中注册 CloseUI→CloseTopUI；新增内置动作用 `RegisterBuiltinHandler()`，派发循环无需修改

### 4.3 重绑定（SettingsScreen）

`KeyBindingSettingItem` 单 slot 模式：每个实例管一个按键槽位，SettingsScreen 场景中静态预设 4 行（CloseUI/Confirm × 主/副键）。标签用 TextCombiner 组合「动作名 - 主键/副键」。

流程：点击按钮 → `BeginRebind()`（抢占时通过 `OnRebindCancelled` 通知前一个监听者取消）→ 监听下一次任意按键 → `FindKeyConflict()` 查跨动作冲突（冲突 Toast 提示并放弃）→ `RebindKey()` 写存档。再次点击同一按钮 = 取消监听。

**已踩过的坑（勿再踩）**：
1. 点击按钮启动监听后必须 `EventSystem.current.SetSelectedGameObject(null)` — 否则 Space/Enter 被 EventSystem 当 Submit 再次触发 onClick。
2. 必须 `_skipFrame` 跳过启动点击所在帧 — 否则捕获到启动点击本身。
3. `EndRebind()` 后 InputManager `_skipNextFrame` 跳一帧 — 否则刚绑定的按键立即触发动作。
4. 监听循环须 `Input.anyKeyDown` 前置门 + static `KeyCode[]` 缓存 — 每帧 `Enum.GetValues` 会分配 350 元素数组。

### 4.4 按键名本地化

特殊命名的键通过 `GetKeyNameTableKey()` 映射到 UIText 表 `KeyName_*` key（19 个 × 5 语言：鼠标三键/Space/ESC/Enter/Tab/Backspace/Delete/方向键×4/修饰键×8），语言切换时由 TextCombiner 自动刷新。字母键、F1-F12 等直接回退枚举名显示。新增可绑定按键类型时同步补 `GetKeyNameTableKey` 映射 + UIText 表条目（CSV 工具见 gic-localization skill；CSV 导入 Id 分配陷阱见 docs/14 §5.1）。

## 6. 已修复的历史 bug（存档）

| Bug | 根因 | 修复 |
|-----|------|------|
| 祈愿原石不足后输入永久锁死 | StartWish 先 push 锁再检查扣费，早退路径不 pop | push 移到扣费成功之后 |
| 联机返回后输入锁死 | OnLeaveRoomClick push Closing 后无退场动画、无 pop | 删除无动画路径的多余 push（转场由 SceneTransition 锁覆盖） |
| 抽卡中按右键关闭祈愿场景 | 旧 bool 标志漏检 | WishInProgress 锁统一拦截 |
| pop 错配（push A→push B→pop 弹掉 B） | 旧 Stack 盲弹栈顶 | (owner,reason) 精确配对 + 幂等 Pop |
| 场景切换守卫误拦截 | IsTransitioning 复用 IsInputLocked | HasInputLock(SceneTransition) 精确查询 |
